# 8개 레퍼런스 상세 명세

**현재 HTML 원본의 재구현 명세**입니다. 어떤 페이지를 선택할지는 [카탈로그](../TEMPLATE_CATALOG.md), 시각 토큰은 [디자인 시스템](../DESIGN_SYSTEM.md), 그림 제작 절차는 [Figure 표준](FIGURE_PRODUCTION_STANDARD.md)을 봅니다. 공통 규칙을 여기에 반복 정의하지 않습니다.

## 공통 구현 계약

- 모든 원본은 `templates/html/` 아래에 있고, `styles.css`의 로컬 Pretendard·색상·전역 −1pt를 상속합니다.
- 1440×810 기본 캔버스, 900px 이하 읽기 배치, 520px 이하 유형별 재구성을 사용합니다. 6개 화면 크기는 [검증 가이드](REFERENCE_REVIEW_GUIDE.md)를 따릅니다.
- 사진은 저장소 제공 자산 `templates/html/assets/concept-apple-photo.jpg`입니다. 외부 이미지로 교체하면 출처와 모든 파생 계산을 갱신합니다.
- SVG/Canvas 그림은 직접 편집할 수 있고, 프리뷰는 소스 대신 사용하지 않습니다.
- 구현 파일에서 명시된 데이터가 수식·레이블·도형·접근성 설명과 일치해야 합니다.

## 01 Concept

**목적:** 사람이 보는 하나의 사진이 높이(H)×너비(W) 크기의 숫자 행렬 세 장(R, G, B)이라는 사실을 먼저 보여준 다음, 해당 행렬의 4×4 영역을 확대하여 하나의 픽셀이 RGB 세 정수 값으로 이루어짐을 연결합니다. 세 장을 겹친 Figure는 H/W 공간축과 채널축 C=3을 시각화하며, 3D 공간에 이미지가 물리적으로 쌓인다는 뜻은 아닙니다. CNN/Kernel/Feature Map/Classification을 다루지 않습니다.

### 최종 시각 흐름

| 순서 | 화면의 Figure | 전달할 사실 |
| --- | --- | --- |
| 1 | 입력 이미지: ROI 표시 없는 실제 사과 사진 1장 | 사람에게 한 장의 사진으로 보이는 RGB 데이터. ROI 테두리는 행렬 단계에만 존재 |
| 2 | 동일 크기 R/G/B 채널 판 3장과 **앞쪽 R 판의 ROI** | 각 판은 실제 H×W 채널 데이터. R 판의 ROI는 R/G/B 공통 좌표 (52,38,4,4)를 대표하며 C=3은 행렬 위쪽 외곽에 배치 |
| 3 | 부분 확대: **RGB 행렬에서 표시된 ROI**의 RGB/G/B 4×4 Stack | 같은 ROI의 RGB 16개 값에서 전면 RGB 합성 (R,G,B)을 원본값으로 표시하고, 중간 G와 후면 B는 왼쪽 채널 행렬의 밝은 프레임 색상(#8acfb3/#8eb8e7)을 기준으로 값을 표시하고 원본 채널값은 별도로 유지. 전면 RGB 왼쪽에 H=4, 후면 B 채널 가로 중심의 확대 격자 아래에 W=4를 텍스트로만 표시. 확대 영역 C=3과 가로/세로선은 제거하고 우상단 R/G/B 배지 및 `4×4×3 = 48개 값` 설명으로 채널 개수를 전달 |
| 4 | 같은 White 패널 안에서 4×4 선택 index 6 → 화살표 → 선택 Swatch·RGB/HEX·R/G/B 막대 | 별도 오른쪽 카드 없이 Figure 한 줄에서 한 픽셀의 RGB 세 정수와 실제 색상을 연결 |
| 5 | 확대 Figure 아래 `4×4×3 = 48개 값`과 카드 하단 R/G/B 조합 관계 | 확대 영역의 48개 채널 값은 해당 Figure에 붙이고, 구분선 아래에서 실제 한 픽셀의 R·G·B 성분을 조합해 같은 색상 Swatch로 표시. 전체 H×W×3 정의는 최하단 핵심 개념에 남김 |

각 채널 판 위의 8×8 가는 격자선은 **행렬이라는 개념을 설명하는 시각적 가이드**입니다. 실제 픽셀 샘플은 각 채널마다 80×80이며 격자를 8×8로 다운샘플링한 것이 아닙니다.

### Canvas 계산 및 재현 계약

1. 원본 이미지는 templates/html/assets/concept-apple-photo.jpg 하나입니다. image.decode() 완료 후 80×80 Canvas, imageSmoothingEnabled=true 및 imageSmoothingQuality=high로 drawImage(image,0,0,80,80)를 수행합니다. 원본 전체 사진의 실제 파일 크기와 리샘플 분석 공간 80×80은 구별합니다.
2. 해당 80×80 전체 RGBA 버퍼의 각 (y,x)에서 R/G/B 값을 추출해 동일한 80×80 R/G/B Canvas에 각각 그립니다. 채널 C가 0/1/2일 때 채널 평면의 해당 RGB 성분만 실제 원본의 8-bit 값을 넣고 다른 두 성분은 0, alpha=255입니다. 실제 채널 intensity가 틴트된 형태로 표현되며 다른 랜덤 픽셀·학습된 Feature Map·3개의 사진 복제품이 아닙니다.
3. 겹친 세 Canvas 판은 크기가 같고 R/G/B 문자 식별과 H, W, C=3 축을 갖습니다. 이중 H/W는 위치를 가리키고 C는 채널 개수를 가리킵니다. 화면의 앞뒤 순서는 데이터 계산 순서가 아니므로 0-based RGB 인덱스를 바꾸지 않습니다.
4. ROI는 getImageData(52,38,4,4)로 0-based 시작 (52,38), 4×4=16픽셀입니다. 원본 사진에는 ROI를 표시하지 않고 R 채널 Canvas 앞의 `.matrix-roi`만 사용합니다. R 판이 세 채널의 **동일한 공간 좌표**를 대표하며 ROI의 CSS left=65%, top=47.5%, width=height=5%는 실제 리샘플 좌표로부터 구합니다. 4×4 각각의 RGB는 RGBA 배열의 i번째 위치 (4i,4i+1,4i+2)에서 읽습니다.
5. 선택 index 6은 ROI 로컬 (x=2,y=1), 전체 리샘플 (x=54,y=39)입니다. 기준 Chromium 검산 RGB (223,54,56), HEX #DF3638이며 환경 변화 시 Canvas 계산 결과를 우선합니다. 채널 세 값은 각각 0~255; 막대 width(%)=100×value/255, 클래스 확률이 아닙니다.
6. 실제 선택 픽셀의 세 숫자에서 RGB 문자열, 대문자 16진수 HEX, Swatch, 세 막대를 한 번에 갱신합니다. 이미지 디코딩/계산 전에는 중립 placeholder이며 실패 시 오류 메시지·중립 Swatch·0% 막대·data-sampled=error 상태로 표시합니다.
7. 확대 4×4 RGB 픽셀의 원소 개수는 4×4×3=48이며 **RGB 합성색으로 그린 4×4 격자도 C=3을 유지**합니다. H=4는 전면 RGB 왼쪽, W=4는 후면 B 가로 중심의 격자 아래에 가이드선 없이 표시하며 확대 영역의 C=3은 삭제하고 `4×4×3 = 48개 값`은 확대 Figure 설명 바로 아래에 둡니다. 전체 일반 이미지의 배열 Shape는 H×W×3(HWC)입니다. HWC는 하나의 표현이며 CHW 레이아웃도 존재합니다. 48은 픽셀 개수 16과 구별하며 바이트 단위 저장 크기와도 구분합니다.

8. **일부 영역 확대 Stack 개선:** 같은 `getImageData(52,38,4,4)`에서 계산한 16개 RGB 배열을 세 격자가 공유합니다. 전면 RGB 합성격자는 원본 `(R,G,B)` 색상으로 표현하며 순수 R 채널이 아닙니다. 중간 G와 후면 B는 기존 윤곽 색상 `#279467`/`#427ec5`를 **동일한 CSS 변수로 공유**하고 JS에서 해당 격자의 실제 `outlineColor`를 읽어 밝기를 표시합니다. 표시 전용 정규화 `t=0.22+(v/255)×0.78`, `displayRGB=JS.Math.round(255+(baseRGB−255)×t)`를 사용하며 선택 RGB/HEX/막대에는 적용하지 않습니다. 원본 채널은 각 셀의 `data-raw-value`에도 기록하고, 선택 RGB/HEX·막대·하단 결합 Figure는 반드시 미보정 원본을 사용합니다. DOM/z-index는 B→G→RGB이고 전면 기준 데스크톱 G(+17px,−17px)/B(+34px,−34px), 520px 이하에서는 G(+14px,−14px)/B(+28px,−28px)입니다. 레이어 노출 폭은 데스크톱 17px·모바일 14px이며 15px/12px 우상단 R/G/B 배지가 뒤 레이어에 가려지지 않도록 확보합니다. 전면 R 배지가 있는 격자는 원본 RGB 합성색을 그대로 유지합니다. 격자는 데스크톱 130px(31×4+2×3), 모바일 122px(29×4+2×3)로 축소합니다. 가로·세로 가이드선은 추가하지 않습니다. H=4 텍스트를 전면 RGB 왼쪽 세로 중앙, W=4 텍스트를 후면 B 격자의 가로 중심에 맞춰 전체 확대 격자 아래에 배치합니다. 두 글자는 선 없이 표시하며 채널 레이어와 서로 겹치지 않습니다. 확대 Stack은 H 라벨과 후면 G/B까지 포함한 시각 중심을 기준으로 가운데 정렬합니다. 다음 단계의 1픽셀 Swatch·RGB 숫자·채널 막대 크기도 비례 축소하고, 4개 Figure의 하단 라벨/캡션 위치는 유지합니다. 전면 격자 좌하단의 `RGB` 중복 표기와 확대 Figure의 `C=3`은 제거합니다. 왼쪽 전체 R/G/B 행렬의 `C=3`는 유지하고 확대 Figure 아래 `4×4×3=48개 값`으로 채널 개수를 설명합니다. 선택 index 6은 RGB 전면에만 2px 흰색 Halo+5px Navy 외곽선으로 표시하며 16개 셀은 숫자 없이 RGB 합성색 블록으로 유지합니다. 48은 16픽셀×3성분을 뜻합니다. `python scripts/validate_references.py --templates concept`에서 실제 CSS 윤곽색에서 계산된 G/B 표시색·원본 채널값 분리·배지 R/G/B의 실제 노출·16셀·B 기준 W/전면 RGB 기준 H 텍스트 중심·간격 및 가이드선과 확대 C=3의 부재·4개 Figure 시각 중심·오프셋·선택 테두리/값과 전체 6개 뷰포트를 확인합니다.

### 구성과 반응형

- 제목은 이미지의 숫자 구조, 부제는 입력 사진 → RGB 숫자 행렬 → 일부 확대 → 픽셀 하나의 RGB 값입니다. **White 패널 하나** 안에 입력 사진(ROI 없음) → 실제 R/G/B 행렬(R 판에 ROI) → 4×4 실제 확대 → 선택 픽셀 Swatch/RGB/HEX/3채널 수치를 **세 Blue 화살표로 연속 연결**합니다. 왼쪽 전체 행렬의 C=3은 행렬 평면 밖에 그대로 유지합니다. 확대 Figure에는 C=3과 가이드선 없이 H=4(왼쪽)·W=4(아래)만 표시합니다. 별도의 오른쪽 카드, 요약 카드 또는 장식 상자는 추가하지 않습니다. 패널의 가로 구분선 아래에서는 전체 배열 Shape를 다시 설명하지 않고 **한 위치의 R/G/B 값을 조합해 RGB 색상을 만든다**는 관계를 단일 행으로 시각화합니다. 실제 index 6의 세 숫자와 합성색은 같은 Canvas 선택값에서 갱신하며, `+` 표시는 산술 덧셈이 아니라 채널 성분의 결합입니다. 전체 H×W×3 설명은 마지막 핵심 개념에만 남깁니다.
- 로컬 Pretendard Variable WOFF2, 전체 자간 −1pt, Navy/Blue/Teal 팔레트·공통 1440×810 16:9 Slide를 유지합니다. 별도 장식 프레임·복잡한 3D 큐브 및 의미 없는 설명 카드를 추가하지 않습니다.
- 데스크톱에서는 한 패널에서 4단계를 가로로 정렬하며, 520px 이하에서는 사진·R/G/B Stack·4×4 확대·한 픽셀 RGB를 세로 한 축에 배치하고 화살표를 아래로 회전합니다. 900px에서는 기존 Slide 축소·반응형 동작을 확인합니다. Footer·패딩·가로 오버플로·가독성을 실측합니다.

### 검증·재사용

python scripts/validate_references.py --templates concept 명령으로 1600×950, 1440×810, 1366×768, 1280×720, 900×900, 390×844 화면을 Chromium에서 검사합니다. 검증은 실제 원본 독립 리샘플, R/G/B 세 평면 × 6400개 픽셀의 채널 성분, ROI/16셀/선택 index/Swatch/RGB/HEX/강도 막대, 확대 격자 C=3 및 48개 값의 배치, 하단 R/G/B 조합 숫자와 Swatch의 실제 선택값 동일성, 3개 판의 동일 크기와 깊이 배치, R 판 ROI의 위치·크기, 원본 사진 ROI 없음, C=3의 판 바깥 배치, H=4 가이드와 선 간격, 단일 패널 4단계 정렬, 폰트 실제 글리프와 −1pt·Footer 및 JS 오류를 포함합니다.

사진/ROI/Canvas 크기를 바꾸면 세 채널 Canvas·ROI 테두리·4×4 색 격자·선택값·HEX·막대·프리뷰·본 문서의 수치를 동시에 갱신해야 합니다. 원본과 다른 데이터를 혼합해 같은 RGB Figure라고 표현하지 않습니다.

## 02 Process

**목적·독자:** CNN 예측 과정을 처음 배우는 독자. **핵심 메시지:** 입력 이미지는 CNN에서 특징으로 표현되고, Task Head는 그 특징을 목적에 맞는 예측 결과로 변환합니다.

**#6과 역할 구분:** #2는 입력→특징 추출→목적별 처리→출력의 역할을 설명합니다. #6은 Conv/ReLU/Pool/Flatten/FC/Softmax와 Tensor Shape를 설명합니다. 사진·평면 Stack·Blue 외부 화살표·Teal 내부 변환·Navy 제목의 표현은 공유하되, #6의 내부 구조 전체를 #2 안에 축소 복제하지 않습니다. #2에는 커널/stride/padding·Flatten 차원·FC 연결·Softmax 수식을 나열하지 않습니다.

**제목·부제:** `CNN의 예측 흐름` / `이미지 → 특징 추출 → 목적별 처리 → 예측 결과`.

**전체 구조:** INPUT → FEATURE → TASK → OUTPUT의 동일 크기 카드 4개와 Blue 외부 화살표 3개. 각 카드는 Stage Label, 독립 Figure 슬롯, Title, Description 순서입니다. 마지막 흰색 캡션/Teal 왼쪽 선에 `역할 분리`와 `CNN은 이미지에서 특징을 추출하고, Task Head는 이를 목적에 맞는 예측으로 변환`을 둡니다.

| 단계 | Figure·의미 | 제목 | 설명 | 카드 배경·경계 |
| --- | --- | --- | --- | --- |
| INPUT | 기존 사과 사진 한 장, RGB 입력 | 입력 이미지 | RGB 픽셀 데이터 | White / Border |
| FEATURE | 실제 계산한 대표 맵 4장의 Stack | CNN | 이미지에서 특징 추출 | Pale Blue / Blue |
| TASK | 짧은 특징 벡터 → 분류 Head → 예시 점수 3개 | Task Head | 특징을 목적에 맞게 처리 | White / Border |
| OUTPUT | 사과/토마토/기타 확률과 수평 막대 | 예측 결과 | 클래스별 예측 확률 | White / Border |

**강조 정책:** CNN 특징 추출을 학습 초점으로 드러내기 위해 FEATURE만 컬러 배경을 씁니다. OUTPUT의 Pale Teal 배경과 Teal 카드 테두리는 `.process-slide .node:not(.feature)`에서 White/Border로 덮어씁니다. 공통 `.node.output` 규칙은 변경하지 않습니다. 카드별 의미는 문자·위치로도 전달합니다.

### 사진과 특징 맵 계산

입력 파일은 `assets/concept-apple-photo.jpg` 그대로입니다. 사진 한 장을 desktop 124×124px / mobile 120×120px, object-fit cover로 표시합니다. #6의 단일 사진처럼 추가 장식 배경·외곽 프레임·그림자 없이 사용합니다. RGB Tensor의 내부 구조는 #1에서 설명합니다.

화면 사진 크기·원본 해상도와 아래 계산용 64×64 크기는 서로 다릅니다. 공통 엔진은 #3과 공유하며 수정하지 않습니다.

1. Canvas를 64×64로 만들고 `imageSmoothingEnabled=true`, `imageSmoothingQuality='high'`로 RGB 사진을 리샘플합니다.
2. `Y=(0.2126R+0.7152G+0.0722B)/255`를 Float32 배열에 저장합니다.
3. `gx`는 `[[−1,0,1],[−2,0,2],[−1,0,1]]/8`, `gy`는 `[[−1,−2,−1],[0,0,0],[1,2,1]]/8`로 계산합니다. 경계는 가장자리 픽셀 반복입니다.
4. 채널 c=0…15의 방향 `θ=cπ/8`에서 `A_c=max(0,(gx cosθ + gy sinθ + (c mod 4)×0.007)×3.2)`를 계산합니다.
5. 대표 채널 0/3/6/9를 표시합니다. 색상은 `t=clamp(4.5A)^0.74`, 밝은 `[242,247,253]`에서 진한 `[30,74,142]`까지 보간합니다.

공통 엔진의 **각 64×64 PNG 데이터 URL을 변경 없이** 사용합니다. #2 전용 JS는 표시 위치·크기·평면 경계만 조정합니다. #6의 손으로 만든 8×8 활성화 패턴을 가져오거나 맵 네 장을 동일 이미지로 대체하지 않습니다.

- 각 면의 2px 바깥 테두리는 `120×120`, radius 1.5입니다. 바탕 `#b7cdea`, 뒤쪽 경계 `#6e94c6`/1.05px, 전면 `#4679b8`/1.5px로 #6의 Blue 평면 스타일과 통일합니다.

### Task Head · 기존 그림 유지

기존의 **짧은 특징 벡터 → 분류 Head → 점수 3개** 그림을 사용합니다. 7개 대표 직사각형 셀은 특징을 요약하는 기호이며 실제 차원·Flatten 크기·레이어 수를 뜻하지 않습니다. 실제 학습된 분류기를 호출하지 않는 역할 **모식도**입니다. 복잡한 FC 교차 연결이나 Flatten/FC/Softmax의 독립 블록은 추가하지 않습니다.

SVG viewBox는 `248×144`이며 원본 `af51f6b`의 TASK SVG를 그대로 사용합니다. 벡터는 X 20, 너비 14의 셀 7개이며 Y 30/42/54/66/78/90/102입니다. 중앙 분류 Head rect는 `(75,42)`, 크기 `68×60`, radius 7, White 바탕, `#7193be`/1.5px 경계입니다. `분류`/`Head`는 X 109, baseline Y 67/87, 17px로 표시합니다.

점수 노드는 `(198,37)`, `(198,72)`, `(198,107)`의 원 3개, radius 12, Pale Blue 바탕입니다. 기본 점수 2/1/0을 위에서 아래로 표시합니다. 내부 Teal 화살표는 Y 72, X 42→67 / 151→170이며 점수 노드를 묶는 가는 분기선은 X 178입니다. 실제 그룹 경계를 재측정해 Figure 중앙으로 옮깁니다. 그림의 문장형 각주를 다시 추가하지 않습니다.

TASK 제목 `Task Head`, 설명 `특징을 목적에 맞게 처리`, White 배경, FEATURE 단독 강조, 최신 Stack·Output·전체 정렬은 유지합니다. TASK의 예시 점수와 Output의 확률·막대·강조·접근성 설명은 같은 JS 점수 배열에서 함께 갱신합니다.

이 예시의 Task는 **Classification**입니다. 일반적인 Vision AI의 Task Head는 목적에 따라 검출의 위치·클래스, 분할의 픽셀 마스크 등을 출력할 수 있습니다. Task Head를 항상 분류만 수행하는 모듈로 정의하지 않습니다. 다른 목적을 설명하는 새 자료에서는 블록 라벨과 출력 유형을 함께 바꿉니다.

설명용 점수 `z=[2,1,0]`을 사과/토마토/기타 순서에 대응합니다. #6의 예시 logits와 같은 값이며 별도 예제입니다. 실제 수식 `p_i=exp(z_i−max(z))/Σexp(z_j−max(z))`에서:

| 클래스 | 예시 점수 | 반올림 전 확률 | 화면 값 | 트랙 220 단위에서 막대 길이 |
| --- | ---: | ---: | ---: | ---: |
| 사과 | 2 | 0.6652409557748218 | 66.5% | 146.3530102704608 |
| 토마토 | 1 | 0.24472847105479764 | 24.5% | 53.84026363205548 |
| 기타 | 0 | 0.09003057317038046 | 9.0% | 19.8067260974837 |

세 확률 합은 1, 표시 백분율 합은 100.0%입니다. 막대 길이는 반올림 전 확률을 사용합니다. 사과를 Teal `#26a6a1`로 강조하고 나머지 막대는 낮은 채도의 `#85bcb6`입니다. White 카드 배경을 유지하며 Figure 아래 작은 `예시 확률`만 표시합니다. 수식과 점수는 슬라이드에 쓰지 않습니다.

`process-reference.js`의 점수 배열 하나가 확률·막대·최대 클래스 강조·접근성 설명을 함께 갱신합니다. 정적 HTML도 같은 초기값이 있어 JS가 실패해도 Task/확률 Figure가 빈 상태가 되지 않습니다. 변경 데이터 `[1,2,0]`에서는 토마토가 최대가 되고 모든 막대·수치·강조·aria-label이 함께 바뀌는지 검사합니다.

**혼동 금지:** 사진→고정 필터 맵은 실제 계산입니다. 특징 벡터·분류 Head·점수 노드는 역할 모식도입니다. 예시 logits→확률은 독립 계산입니다. **해당 맵에서 직접 얻은 확률도, 실제 학습된 사과 분류 모델의 추론 결과도 아닙니다.** 흐름 화살표는 역할 간 논리적 순서를 설명하며 학습된 단일 모델 실행을 입증하지 않습니다. 출력의 `예시 확률`을 삭제하지 않습니다.

## 04 Step-by-Step

**목적·독자:** convolution의 국소 계산을 처음 배우는 독자. **핵심 메시지:** 선택한 입력 영역의 원소별 곱 9개를 더하면 출력 한 칸이 됩니다.

**전체 구조:** 왼쪽 카드에서 입력 영역과 출력 위치를 연결하고, 오른쪽 카드에서 같은 선택 영역·커널·원소별 곱·합산을 풉니다. 두 카드 하단 설명 구분선은 데스크톱에서 같은 높이입니다.

**데이터:**

```text
입력 X (5×5)             커널 K (3×3)
1 2 3 1 0                1 0 -1
4 5 6 2 1                1 0 -1
7 8 9 3 1                1 0 -1
2 1 0 4 2
1 3 2 1 0

원소별 곱 (좌상단)        전체 출력 Y (3×3)
1 0 -3                   -6  9 16
4 0 -6                   -2  5 11
7 0 -9                   -1  4  8
```

**정확한 수식·조건:**

`Y[y,x] = Σ(ky=0…2) Σ(kx=0…2) X[y+ky,x+kx] K[ky,kx]`.

Stride 1, padding 0, 단일 채널, bias 0, 커널 반전 없음. 출력 한 변은 `floor((5+2×0−3)/1)+1=3`입니다. 화면의 (1,1)은 **1-based 좌상단 위치**, 코드의 y/x 인덱스는 0-based입니다.

`Y[0,0] = 1+0−3+4+0−6+7+0−9 = −6`.

**요소와 의미:** 왼쪽 5×5의 행·열 0…2에 해당하는 9칸을 강조하고 출력 좌상단 하나를 Navy로 강조합니다. 오른쪽은 같은 9칸·같은 커널·각 곱셈 식과 값·합·출력 위치를 보여줍니다. 나머지 출력 8개도 실제로 계산된 값입니다.

**색·화살표·배치:** 선택 영역은 Blue 계열, 커널은 작은 Teal 면, 최종 출력은 Navy입니다. 연결은 Blue SVG 경로입니다. 원소별 곱 기호는 원·점 SVG이며 다른 텍스트 글꼴을 쓰지 않습니다.

**초급자 최소 설명·삭제 금지:** 기호의 뜻, 9개 곱을 전부 더한다는 문구, 한 칸씩 커널을 움직여 전체 출력이 만들어진다는 설명, 실제 CNN의 가중치는 학습된다는 조건.

**구현:** [step-by-step.html](../templates/html/step-by-step.html)의 편집 가능한 정적 행렬·inline CSS, 공통 CSS. 별도 JS는 없으며 검증이 모든 출력 값을 독립 계산합니다. **프리뷰:** [JPG](../previews/html-step-by-step.jpg).

## 06 Architecture

**목적·독자:** CNN의 연산·모듈 경계와 차원 변화를 읽는 독자. **핵심 메시지:** 이 모델의 Conv는 특징 채널을 만들고 Pool은 공간을 줄이며 Flatten 후 분류합니다.

**최종 구조:** Input → Conv Block 1 → Conv Block 2 → Flatten → FC Layer → Softmax.

| 단계 | 연산 | 전후 Shape |
| --- | --- | --- |
| Input | RGB 사진 한 장, batch 생략 | 64×64×3 |
| Block 1 Conv | 3×3, S1, P1, out=16 | 64×64×3 → 64×64×16 |
| Block 1 ReLU | max(0,x) | Shape 유지 |
| Block 1 Pool | MaxPool 2×2 S2 | 64×64×16 → 32×32×16 |
| Block 2 Conv | 3×3, S1, P1, out=32 | 32×32×16 → 32×32×32 |
| Block 2 ReLU | max(0,x) | Shape 유지 |
| Block 2 Pool | MaxPool 2×2 S2 | 32×32×32 → 16×16×32 |
| Flatten | 원소 순서 재배열 | 16×16×32 = 8,192 |
| FC | z=Wx+b, W는 3×8192 | 8,192 → 3 logits |
| Softmax | p_i=exp(z_i)/Σ exp(z_j) | 3 probabilities |

**차원 수식:** `out=floor((n+2p−d(k−1)−1)/s)+1`, dilation d=1. Conv는 H/W를 유지하고 Pool은 두 번 절반으로 줄입니다. 다른 CNN에 이 역할을 보편 규칙으로 강제하지 않습니다.

**확률 예시:** logits `[2,1,0]`의 softmax는 `[0.665240956,0.244728471,0.090030573]`, 표시는 `P(class0)=66.5%`, `P(class1)=24.5%`, `P(class2)=9.0%`, 합 100.0%입니다. 사진에 대한 실제 추론 결과가 아닙니다.

**Figure 요소·배치:** 입력 사진 한 개. 두 Block 내부의 큰 Conv Stack → 작은 Pool Stack. Stack 평면 7개는 채널 수의 축약 표현입니다. Flatten은 Stack → 세로 1D 벡터이며 34개 대표 셀과 생략점으로 8,192차원을 축약합니다. FC는 벡터와 세 노드, Softmax는 클래스별 막대입니다. Feature Extractor/Classifier 범위 선으로 역할을 구분합니다.

**색·화살표·중앙축:** 외부 Blue 5개, 내부 Teal 3개. 각 화살표의 직선·화살촉은 한 path이며 같은 tip 좌표를 씁니다. 실제 Stack bounding box 사이의 간격으로 내부 화살표를 계산합니다. 제목·그림·Shape 중심축은 desktop/tablet에서 2px 이내입니다. 폰트 로딩 후 `getBBox()`로 그림 중심을 다시 맞춥니다. 520px 이하의 왼쪽 그림/오른쪽 텍스트 배치는 의도된 예외입니다.

**최소 설명·삭제 금지:** 모든 출력 Shape, Conv/ReLU/MaxPool 순서, 첫 Block의 역할 설명, Flatten 차원, FC의 logits와 Softmax 확률 구분, 설명용 확률 표기, 단일 사진.

**데이터 단순화:** 맵 패턴은 SVG 구조 설명을 위한 모식도이며 #2·#3 고정 필터 엔진을 사용하지 않습니다. 그려진 작은 격자 수·평면 수를 실제 Tensor 크기로 해석하지 않습니다.

**구현:** [architecture.html](../templates/html/architecture.html)의 SVG 생성 JS·페이지 CSS, 공통 CSS. **프리뷰:** [JPG](../previews/html-architecture.jpg).

## 07 Experiment

**목적·독자:** 혼동행렬에서 정확도·정밀도·재현율·F1이 어떻게 나오는지 배우는 독자. **핵심 메시지:** 같은 판정 개수를 다른 질문의 분모로 해석합니다.

**구조:** 왼쪽 흰색 Confusion Matrix 카드, 오른쪽 4개 Metrics 카드. 지표별 이름·값·짧은 뜻·일반식·대입식을 묶습니다. FP/FN 설명은 행렬 카드 안에 있습니다.

| 모델 예측 / GT | 실제 이상 | 실제 정상 |
| --- | ---: | ---: |
| 예측 이상 | TP=4 | FP=1 |
| 예측 정상 | FN=2 | TN=5 |

평가 샘플 총 12, 실제 이상 6·정상 6, 양성은 이상입니다. GT는 상단 가로축, 모델 예측은 좌측 세로축이며 **예측 이상이 위 행**입니다.

| 지표 | 식 | 대입 결과 |
| --- | --- | --- |
| Accuracy | (TP+TN)/(TP+TN+FP+FN) | 9/12 = 75.0% |
| Precision | TP/(TP+FP) | 4/5 = 80.0% |
| Recall | TP/(TP+FN) | 4/6 = 66.7% |
| F1 | 2TP/(2TP+FP+FN) | 8/11 = 72.7% |

동치식 `F1=2PR/(P+R)`을 함께 표기합니다. 표시용으로 반올림한 80.0/66.7을 다시 넣어 계산하지 않고 원래 비율에서 반올림합니다.

**색·기하:** TP/TN Teal, FP/FN Amber. 축·행열 라벨·각 셀의 코드와 숫자는 중앙 정렬. GT 아래 가로선, 모델 예측과 행 라벨 사이 중앙의 세로선. 세로선은 실제 텍스트 경계를 Range로 측정하고 zoom·선 두께를 보정합니다.

**최소 설명·삭제 금지:** `FP: 정상인데 이상으로 예측`, `FN: 이상인데 정상으로 예측`, 예시 12개·양성 정의, 모든 수식과 실제 계산 결과. 최초 구상보다 우선하는 최종 축 순서를 유지합니다.

**구현:** [experiment.html](../templates/html/experiment.html)의 HTML 표·inline CSS·세로선 정렬 JS, 공통 CSS. **프리뷰:** [JPG](../previews/html-experiment.jpg).

**검증:** 행렬 합·정답 개수·행열 위치·네 지표와 두 F1 식, 코드/숫자/축 정렬 오차<2px, 세로선 양쪽 간격 차이<0.25px, 카드/푸터·폰트·모바일. [상세 패턴](EXPERIMENT_PATTERN.md).

**목적·독자:** 운영 효율의 숫자와 실행 항목을 빠르게 검토하는 독자. **핵심 메시지:** 효율 지표의 변화와 파일럿 확대 시 확인할 위험을 함께 봅니다.

**전체 구조:** 왼쪽 넓은 흰색 카드 안에 3개의 KPI 그룹, 각 그룹은 기존 Blue / 개선안 Teal 세로 막대·실제 수치/단위·지표 이름·변화율입니다. 오른쪽 흰색 카드에는 우선순위 설정 / 파일럿 기준 통일 / 확대 판단의 세 항목입니다.

| --- | ---: | ---: | ---: | ---: |
