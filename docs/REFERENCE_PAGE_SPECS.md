# 8개 레퍼런스 상세 명세

**현재 HTML 원본의 재구현 명세**입니다. 어떤 페이지를 선택할지는 [카탈로그](../TEMPLATE_CATALOG.md), 시각 토큰은 [디자인 시스템](../DESIGN_SYSTEM.md), 그림 제작 절차는 [Figure 표준](FIGURE_PRODUCTION_STANDARD.md)을 봅니다. 공통 규칙을 여기에 반복 정의하지 않습니다.

## 공통 구현 계약

- 모든 원본은 `templates/html/` 아래에 있고, `styles.css`의 로컬 Pretendard·색상·전역 −1pt를 상속합니다.
- 1440×810 기본 캔버스, 900px 이하 읽기 배치, 520px 이하 유형별 재구성을 사용합니다. 6개 화면 크기는 [검증 가이드](REFERENCE_REVIEW_GUIDE.md)를 따릅니다.
- 사진은 저장소 제공 자산 `templates/html/assets/concept-apple-photo.jpg`입니다. 외부 이미지로 교체하면 출처와 모든 파생 계산을 갱신합니다.
- SVG/Canvas 그림은 직접 편집할 수 있고, 프리뷰는 소스 대신 사용하지 않습니다.
- 구현 파일에서 명시된 데이터가 수식·레이블·도형·접근성 설명과 일치해야 합니다.

## 01 Concept

**목적·독자:** 이미지의 숫자 표현을 처음 배우는 독자. **핵심 메시지:** 한 픽셀은 RGB 세 값, 전체 이미지는 H×W×3 구조입니다.

**전체 구조:** 왼쪽 흰색 카드에 사진·선택 영역·오른쪽 화살표·4×4 픽셀 확대. 오른쪽 흰색 카드에 선택 색상·RGB/HEX·R/G/B 막대·HWC Shape. 마지막 캡션에서 픽셀과 전체 구조를 연결합니다.

**데이터·계산:**

1. 사진을 80×80 Canvas에 high-quality smoothing으로 리샘플합니다.
2. 좌상단 `(52,38)`부터 너비 4·높이 4의 RGBA를 읽습니다.
3. 행 우선 16개 셀을 그 RGB 색으로 칠하고 index 6(로컬 x=2,y=1)을 선택합니다. 전역 선택 위치는 `(54,39)`입니다.
4. `HEX = '#' + R/G/B 각각의 2자리 16진수`, `채널 막대 너비 = 값/255 × 100%`.
5. 기준 렌더링에서 RGB `(223,54,56)`, HEX `#DF3638`. 사진 또는 리샘플 조건이 바뀌면 고정값으로 유지하지 않습니다.

**요소와 의미:** 사진은 입력, ROI는 확대하는 위치, 16개 색 셀은 실제 래스터 값, 테두리가 있는 한 셀은 수치 카드와 대응합니다. 색 채널 막대는 채널 값의 크기이며 클래스 확률이 아닙니다.

**배치·색·화살표:** 사진/확대의 그림 높이와 화살표 중심을 맞춥니다. 사진 자체에 추가 배경·중첩 프레임을 붙이지 않습니다. RGB 막대는 채널에 의미가 있는 작은 색상 영역입니다.

**초급자 최소 설명·삭제 금지:** 8-bit 범위 0–255, 확대 배열 4×4, 실제 선택 픽셀, HWC의 높이/너비/채널 의미. 선택 수치만 남기고 픽셀과의 대응을 없애지 않습니다.

**구현:** [concept.html](../templates/html/concept.html)의 inline JS, 공통 styles/reference-layout CSS. **프리뷰:** [PNG](../previews/html-concept.png).

**검증:** 16개 셀과 같은 Canvas 래스터, 선택 RGB/HEX/스와치/막대의 일치, 사진 로드, 확대 화살표 중심, 모바일 가로 폭, 실제 글꼴.

## 02 Process

**목적·독자:** CNN 예측 과정을 처음 배우는 독자. **핵심 메시지:** 입력 이미지 → CNN이 특징 표현 생성 → Task Head가 분류 점수 계산 → 클래스별 예측 확률. 세부 연산 구조를 설명하는 #6과 구분합니다.

**제목·부제:** `CNN의 예측 흐름` / `입력 이미지 → 특징 추출 → 목적별 처리 → 예측 결과`.

**전체 구조:** INPUT → FEATURE → TASK → OUTPUT의 동일 크기 카드 4개와 외부 Blue 화살표 3개. 각 카드는 Stage Label, 독립 Figure 슬롯, Title, Description 순서입니다. 마지막 흰색 캡션/Teal 왼쪽 선에 `역할 분리`와 `CNN은 이미지의 특징을 추출하고, Task Head는 이를 목적에 맞는 예측으로 변환`을 둡니다.

| 단계 | Figure·의미 | 제목 | 설명 | 가까운 조건 표기 |
| --- | --- | --- | --- | --- |
| INPUT | 기존 사과 사진 한 장, RGB 입력 | 입력 이미지 | RGB 픽셀 데이터 | 64×64×3 · 리샘플 |
| FEATURE | 실제 계산한 서로 다른 대표 맵 4장 | CNN | 이미지에서 특징 추출 | 대표 특징 맵 · 고정 필터 설명용 |
| TASK | 짧은 특징 벡터→분류 Head→점수 3개 | Task Head | 특징을 클래스별 점수로 변환 | 특징 → 분류 점수 · 모식도 |
| OUTPUT | 사과/토마토/기타 확률과 수평 막대 | 예측 결과 | 클래스별 예측 확률 | 예시 확률 · 합계 100% |

### 사진과 특징 맵 계산

입력 파일은 `assets/concept-apple-photo.jpg` 그대로입니다. 화면의 사진 크기·원본 파일 해상도와 계산용 64×64 리샘플 크기를 구분합니다. 새 사진이나 사과 이미지를 생성하지 않습니다.

공통 엔진은 #3과 공유하며 이번 개선에서 변경하지 않습니다.

1. Canvas를 64×64로 만들고 `imageSmoothingEnabled=true`, `imageSmoothingQuality='high'`로 RGB 사진을 리샘플합니다.
2. `Y=(0.2126R+0.7152G+0.0722B)/255`를 Float32 배열에 저장합니다.
3. `gx`는 `[[−1,0,1],[−2,0,2],[−1,0,1]]/8`, `gy`는 `[[−1,−2,−1],[0,0,0],[1,2,1]]/8`로 계산합니다. 경계는 가장자리 픽셀 반복입니다.
4. 채널 c=0…15의 방향 `θ=cπ/8`에서 `A_c=max(0,(gx cosθ + gy sinθ + (c mod 4)×0.007)×3.2)`를 계산합니다.
5. 대표 채널 0/3/6/9를 표시합니다. 색상은 `t=clamp(4.5A)^0.74`, 밝은 `[242,247,253]`에서 진한 `[30,74,142]`까지 보간합니다.

공통 엔진의 64×64 PNG 데이터 URL을 그대로 사용합니다. #2 전용 JS는 그 결과의 표시 좌표만 조정합니다. 뒤쪽부터 채널 9/6/3/0 순서이며 전면은 0입니다. SVG viewBox는 `184×162`, 각 맵 면은 `108×108`, depth k의 위치는 `(8+20k,45−12k)`입니다. 테두리는 2px 바깥의 `112×112`입니다. 공통 엔진의 작은 격자·임의 패턴으로 대체하지 않습니다.

### Task와 예시 확률

7개 직사각형 셀은 **특징 벡터를 요약하는 기호**입니다. 실제 특징 차원·Flatten 연산·레이어 수를 나타내지 않습니다. 중앙 분류 Head와 점수 노드 3개를 두고 내부 Teal 화살표 2개로 왼쪽→오른쪽 변환을 보여줍니다. 복잡한 뉴런 연결망이나 교차선을 추가하지 않습니다.

설명용 점수 `z=[2,1,0]`을 사과/토마토/기타 순서에 대응합니다. `p_i=exp(z_i−max(z))/Σexp(z_j−max(z))`에서:

| 클래스 | 점수 | 반올림 전 확률 | 화면 값 | 트랙 220 단위에서 막대 길이 |
| --- | ---: | ---: | ---: | ---: |
| 사과 | 2 | 0.6652409557748218 | 66.5% | 146.3530102704608 |
| 토마토 | 1 | 0.24472847105479764 | 24.5% | 53.84026363205548 |
| 기타 | 0 | 0.09003057317038046 | 9.0% | 19.8067260974837 |

세 확률은 합 1이며 표시 백분율도 합 100.0%입니다. 막대 길이는 반올림 전 확률을 사용합니다. 사과를 Teal로 강조하고 나머지 막대는 낮은 채도의 Teal입니다. 같은 JS의 점수 배열이 Task 숫자·확률·막대·최대 클래스 강조·접근성 설명을 함께 갱신합니다. SVG의 초기값도 동일해 JS가 실패해도 Task/Output이 빈 도형으로 남지 않습니다.

**기술적 구분:** 사진→고정 필터 맵은 실제 계산입니다. Task 벡터와 Head는 모식도이며, 점수 `[2,1,0]`는 #6의 설명용 예와 일치시킨 별도 예제입니다. 이 맵을 학습된 분류기에 넣어 해당 점수를 얻은 단일 추론 실행을 구현했다고 주장하지 않습니다. 화면의 `고정 필터 설명용`·`모식도`·`예시 확률`을 유지합니다. Softmax 수식·Logit 정의는 문서에 두고 이 Process 슬라이드에 펼치지 않습니다.

### 배치·색·정렬

- 기본 1440×810 프레임과 공통 폰트·−1pt를 사용합니다. 외부 카드나 장식 프레임을 더하지 않습니다.
- 데스크톱 Flow 열은 `1fr 44px 1fr 44px 1fr 44px 1fr`. 네 카드 모두 높이 376px, padding 24px 18px, border 2px, radius 20px입니다. 일반 카드는 White, Feature는 Pale Blue/Blue 경계, Output은 Pale Teal/Teal 경계입니다.
- 카드 행은 `20px 176px 36px 56px`, 행 간격 12px입니다. Label·Title·Description의 y좌표를 일치시킵니다. Task의 긴 설명만 두 줄이며 첫 줄의 기준 높이는 같습니다.
- 사진·Stack·Task·확률 그래프를 각각의 Figure 중심에 둡니다. SVG는 실제 artwork `getBBox()`의 중심을 viewBox 중앙으로 옮기며 `document.fonts.ready` 뒤 다시 맞춥니다. SVG viewport만 중앙에 두고 그림이 치우치게 하지 않습니다.
- Figure 중심은 카드 위에서 146px입니다. 외부 화살표는 이 축을 통과합니다. 3개 모두 `M1 8 H27 M21 2 L27 8 L21 14` 한 경로로 직선과 화살촉을 연결하며 카드 경계 사이의 여백 안에 둡니다.
- 실제 그림 중심·카드 높이·라벨/제목/설명의 정렬 오차는 1 CSS px 미만으로 검사합니다. 그림의 작은 조건 표기는 Figure 슬롯 하단에 따로 두어 실제 그림 중심을 밀지 않습니다.
- 900px 이하에서는 1열과 아래 방향 화살표로 바꿉니다. 카드 높이 346px, 행 `20/160/36/56px`, 간격 10px, padding 20px 18px입니다. 실제 그림은 Figure의 중앙을 유지하며 가로 오버플로를 만들지 않습니다.

### 실패 처리와 새 자료에 재사용

사진 또는 공통 엔진·Canvas 계산이 실패하면 특징 맵 자리에 원인 확인 문구를 표시합니다. #2 표시 스크립트 자체가 없거나 JS를 꺼도 정적 안내가 남습니다. 사진 실패 시 사진 자리에도 안내를 둡니다. 빈 사각형을 실제 특징 맵처럼 제출하지 않습니다.

새 Process 자료는 먼저 입력·표현·목적별 처리·출력의 역할을 정의하고 네 Figure를 대응시킵니다. 다른 Task의 실제 의미가 필요하지 않으면 Detection/Segmentation까지 한 장에 늘리지 않습니다. 입력·필터·클래스·점수를 바꾸면 계산·조건 표기·막대·강조·접근성 문구도 함께 바꿉니다. 단계별 Label/Figure/Title/Description 정렬과 마지막 역할 분리 캡션을 유지합니다. 새 확률에서는 반올림 전 합과 표시 합도 확인합니다.

**구현:** [process.html](../templates/html/process.html)의 #2 범위 CSS·정적 SVG, [process-reference.js](../templates/html/process-reference.js)의 #2 표시·예시 계산·오류 처리, 변경하지 않은 [cnn-feature-maps.js](../templates/html/assets/cnn-feature-maps.js), 공통 styles/reference-layout CSS.

**프리뷰:** [최신 PNG](../previews/html-process.png), [수정 전 PNG](../previews/review/process-before.png).

**검증:** `python scripts/check_process.py`는 실제 Pretendard와 6개 요청 화면 크기, 16채널×7위치의 독립 필터 계산·4맵×7픽셀 색상, 점수/확률/막대 일치, 중앙축·외부/내부 화살표·카드/푸터/글자 잘림을 확인합니다. JS 없음·엔진 없음·표시 JS 없음·사진 없음·Canvas 없음·다른 점수 `[1,2,0]`를 데스크톱/모바일에서 검증하는 12개 추가 사례가 있습니다. [process-validation.json](../previews/review/process-validation.json)이 전용 결과입니다. 공통 8종 검사에도 동일한 #2 검증을 연결해 #3을 포함한 회귀를 확인합니다.

## 03 Comparison

**목적·독자:** 같은 이미지 분류 과제에서 규칙 기반과 머신러닝의 선택 조건을 이해할 독자. **핵심 메시지:** 판단 기준을 직접 작성하는 방식과 데이터로 추정하는 방식은 변경·검증 조건이 다릅니다.

**전체 구조:** 동일 크기의 좌우 카드. 두 카드 모두 라벨 → 제목 → 짧은 설명 → 같은 사진을 사용하는 Figure → 세 비교 행 → 장점·한계 순서입니다.

| 비교 행 | 규칙 기반 | 머신러닝 |
| --- | --- | --- |
| 판단 기준 | 색상 비율 + 둥근 윤곽 조건 | 학습 데이터의 시각 패턴 |
| 기준 변경 | 조건·임계값 직접 수정 | 데이터 보완 + 재학습 |
| 적용 조건 | 조명·배경이 일정한 환경 | 대표성 있는 학습·평가 데이터 |

**데이터·수식:** 양쪽 사진은 동일 파일입니다. 머신러닝 쪽 특징 모티프의 수식·표시 채널은 #2와 동일합니다. 비교 Figure는 실측 성능 비교나 학습 결과가 아닙니다.

**요소·배치·색:** 왼쪽 색상/형태 조건 배지는 Amber 계열의 작은 영역, 오른쪽 특징 맵은 Blue입니다. 각 카드의 행 경계와 제목 수준을 맞춥니다. 사진 → 조건/특징의 화살표는 동일한 역할입니다.

**초급자 최소 설명·삭제 금지:** 같은 입력·같은 비교 기준, 각 방법의 유리한 조건과 한계. 머신러닝의 대표성·편향·환경 변화 검증 문구를 유지합니다.

**구현:** [comparison.html](../templates/html/comparison.html), 공통 cnn-feature-maps.js, styles/reference-layout CSS. **프리뷰:** [PNG](../previews/html-comparison.png).

**검증:** 두 사진 경로·로드 일치, 규칙 배지 두 개, 특징 맵은 #2와 같은 계산·색상, 좌우 행 구조·가독성·모바일 카드 순서.

## 04 Step-by-Step

**목적·독자:** convolution의 국소 계산을 처음 배우는 독자. **핵심 메시지:** 선택한 입력 영역의 원소별 곱 9개를 더하면 출력 한 칸이 됩니다.

**전체 구조:** 왼쪽 카드에서 입력 영역과 출력 위치를 연결하고, 오른쪽 카드에서 같은 선택 영역·커널·원소별 곱·합산을 풉니다. 두 카드 하단 설명 구분선은 데스크톱에서 같은 높이입니다.

**데이터:**

```text
입력 X (5×5)             커널 K (3×3)
1 2 3 1 0                1 0 -1
4 5 6 2 1                1 0 -1
7 8 9 3 1                1 0 -1
2 1 0 4 2
1 3 2 1 0

원소별 곱 (좌상단)        전체 출력 Y (3×3)
1 0 -3                   -6  9 16
4 0 -6                   -2  5 11
7 0 -9                   -1  4  8
```

**정확한 수식·조건:**

`Y[y,x] = Σ(ky=0…2) Σ(kx=0…2) X[y+ky,x+kx] K[ky,kx]`.

Stride 1, padding 0, 단일 채널, bias 0, 커널 반전 없음. 출력 한 변은 `floor((5+2×0−3)/1)+1=3`입니다. 화면의 (1,1)은 **1-based 좌상단 위치**, 코드의 y/x 인덱스는 0-based입니다.

`Y[0,0] = 1+0−3+4+0−6+7+0−9 = −6`.

**요소와 의미:** 왼쪽 5×5의 행·열 0…2에 해당하는 9칸을 강조하고 출력 좌상단 하나를 Navy로 강조합니다. 오른쪽은 같은 9칸·같은 커널·각 곱셈 식과 값·합·출력 위치를 보여줍니다. 나머지 출력 8개도 실제로 계산된 값입니다.

**색·화살표·배치:** 선택 영역은 Blue 계열, 커널은 작은 Teal 면, 최종 출력은 Navy입니다. 연결은 Blue SVG 경로입니다. 원소별 곱 기호는 원·점 SVG이며 다른 텍스트 글꼴을 쓰지 않습니다.

**초급자 최소 설명·삭제 금지:** 기호의 뜻, 9개 곱을 전부 더한다는 문구, 한 칸씩 커널을 움직여 전체 출력이 만들어진다는 설명, 실제 CNN의 가중치는 학습된다는 조건.

## 06 Architecture

**목적·독자:** CNN의 연산·모듈 경계와 차원 변화를 읽는 독자. **핵심 메시지:** 이 모델의 Conv는 특징 채널을 만들고 Pool은 공간을 줄이며 Flatten 후 분류합니다.

**최종 구조:** Input → Conv Block 1 → Conv Block 2 → Flatten → FC Layer → Softmax.

| 단계 | 연산 | 전후 Shape |
| --- | --- | --- |
| Input | RGB 사진 한 장, batch 생략 | 64×64×3 |
| Block 1 Conv | 3×3, S1, P1, out=16 | 64×64×3 → 64×64×16 |
| Block 1 ReLU | max(0,x) | Shape 유지 |
| Block 1 Pool | MaxPool 2×2 S2 | 64×64×16 → 32×32×16 |
| Block 2 Conv | 3×3, S1, P1, out=32 | 32×32×16 → 32×32×32 |
| Block 2 ReLU | max(0,x) | Shape 유지 |
| Block 2 Pool | MaxPool 2×2 S2 | 32×32×32 → 16×16×32 |
| Flatten | 원소 순서 재배열 | 16×16×32 = 8,192 |
| FC | z=Wx+b, W는 3×8192 | 8,192 → 3 logits |
| Softmax | p_i=exp(z_i)/Σ exp(z_j) | 3 probabilities |

**차원 수식:** `out=floor((n+2p−d(k−1)−1)/s)+1`, dilation d=1. Conv는 H/W를 유지하고 Pool은 두 번 절반으로 줄입니다. 다른 CNN에 이 역할을 보편 규칙으로 강제하지 않습니다.

**확률 예시:** logits `[2,1,0]`의 softmax는 `[0.665240956,0.244728471,0.090030573]`, 표시는 `P(class0)=66.5%`, `P(class1)=24.5%`, `P(class2)=9.0%`, 합 100.0%입니다. 사진에 대한 실제 추론 결과가 아닙니다.

**Figure 요소·배치:** 입력 사진 한 개. 두 Block 내부의 큰 Conv Stack → 작은 Pool Stack. Stack 평면 7개는 채널 수의 축약 표현입니다. Flatten은 Stack → 세로 1D 벡터이며 34개 대표 셀과 생략점으로 8,192차원을 축약합니다. FC는 벡터와 세 노드, Softmax는 클래스별 막대입니다. Feature Extractor/Classifier 범위 선으로 역할을 구분합니다.

**색·화살표·중앙축:** 외부 Blue 5개, 내부 Teal 3개. 각 화살표의 직선·화살촉은 한 path이며 같은 tip 좌표를 씁니다. 실제 Stack bounding box 사이의 간격으로 내부 화살표를 계산합니다. 제목·그림·Shape 중심축은 desktop/tablet에서 2px 이내입니다. 폰트 로딩 후 `getBBox()`로 그림 중심을 다시 맞춥니다. 520px 이하의 왼쪽 그림/오른쪽 텍스트 배치는 의도된 예외입니다.

**최소 설명·삭제 금지:** 모든 출력 Shape, Conv/ReLU/MaxPool 순서, 첫 Block의 역할 설명, Flatten 차원, FC의 logits와 Softmax 확률 구분, 설명용 확률 표기, 단일 사진.

**데이터 단순화:** 맵 패턴은 SVG 구조 설명을 위한 모식도이며 #2·#3 고정 필터 엔진을 사용하지 않습니다. 그려진 작은 격자 수·평면 수를 실제 Tensor 크기로 해석하지 않습니다.

## 07 Experiment

**목적·독자:** 혼동행렬에서 정확도·정밀도·재현율·F1이 어떻게 나오는지 배우는 독자. **핵심 메시지:** 같은 판정 개수를 다른 질문의 분모로 해석합니다.

**구조:** 왼쪽 흰색 Confusion Matrix 카드, 오른쪽 4개 Metrics 카드. 지표별 이름·값·짧은 뜻·일반식·대입식을 묶습니다. FP/FN 설명은 행렬 카드 안에 있습니다.

| 모델 예측 / GT | 실제 이상 | 실제 정상 |
| --- | ---: | ---: |
| 예측 이상 | TP=4 | FP=1 |
| 예측 정상 | FN=2 | TN=5 |

평가 샘플 총 12, 실제 이상 6·정상 6, 양성은 이상입니다. GT는 상단 가로축, 모델 예측은 좌측 세로축이며 **예측 이상이 위 행**입니다.

| 지표 | 식 | 대입 결과 |
| --- | --- | --- |
| Accuracy | (TP+TN)/(TP+TN+FP+FN) | 9/12 = 75.0% |
| Precision | TP/(TP+FP) | 4/5 = 80.0% |
| Recall | TP/(TP+FN) | 4/6 = 66.7% |
| F1 | 2TP/(2TP+FP+FN) | 8/11 = 72.7% |

동치식 `F1=2PR/(P+R)`을 함께 표기합니다. 표시용으로 반올림한 80.0/66.7을 다시 넣어 계산하지 않고 원래 비율에서 반올림합니다.

**색·기하:** TP/TN Teal, FP/FN Amber. 축·행열 라벨·각 셀의 코드와 숫자는 중앙 정렬. GT 아래 가로선, 모델 예측과 행 라벨 사이 중앙의 세로선. 세로선은 실제 텍스트 경계를 Range로 측정하고 zoom·선 두께를 보정합니다.

**최소 설명·삭제 금지:** `FP: 정상인데 이상으로 예측`, `FN: 이상인데 정상으로 예측`, 예시 12개·양성 정의, 모든 수식과 실제 계산 결과. 최초 구상보다 우선하는 최종 축 순서를 유지합니다.

**구현:** [experiment.html](../templates/html/experiment.html)의 HTML 표·inline CSS·세로선 정렬 JS, 공통 CSS. **프리뷰:** [JPG](../previews/html-experiment.jpg).

**검증:** 행렬 합·정답 개수·행열 위치·네 지표와 두 F1 식, 코드/숫자/축 정렬 오차<2px, 세로선 양쪽 간격 차이<0.25px, 카드/푸터·폰트·모바일. [상세 패턴](EXPERIMENT_PATTERN.md).

**전체 구조:** 왼쪽 넓은 흰색 카드 안에 3개의 KPI 그룹, 각 그룹은 기존 Blue / 개선안 Teal 세로 막대·실제 수치/단위·지표 이름·변화율입니다. 오른쪽 흰색 카드에는 우선순위 설정 / 파일럿 기준 통일 / 확대 판단의 세 항목입니다.
