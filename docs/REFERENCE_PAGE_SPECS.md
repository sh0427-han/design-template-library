## 01 Concept

**목적·독자:** 이미지의 숫자 표현을 처음 배우는 독자. **핵심 메시지:** 한 픽셀은 RGB 세 값, 전체 이미지는 H×W×3 구조입니다.

**전체 구조:** 왼쪽 흰색 카드에 사진·선택 영역·오른쪽 화살표·4×4 픽셀 확대. 오른쪽 흰색 카드에 선택 색상·RGB/HEX·R/G/B 막대·HWC Shape. 마지막 캡션에서 픽셀과 전체 구조를 연결합니다.

**데이터·계산:**

1. 사진을 80×80 Canvas에 high-quality smoothing으로 리샘플합니다.
2. 좌상단 `(52,38)`부터 너비 4·높이 4의 RGBA를 읽습니다.
3. 행 우선 16개 셀을 그 RGB 색으로 칠하고 index 6(로컬 x=2,y=1)을 선택합니다. 전역 선택 위치는 `(54,39)`입니다.
4. `HEX = '#' + R/G/B 각각의 2자리 16진수`, `채널 막대 너비 = 값/255 × 100%`.
5. 기준 렌더링에서 RGB `(223,54,56)`, HEX `#DF3638`. 사진 또는 리샘플 조건이 바뀌면 고정값으로 유지하지 않습니다.

**요소와 의미:** 사진은 입력, ROI는 확대하는 위치, 16개 색 셀은 실제 래스터 값, 테두리가 있는 한 셀은 수치 카드와 대응합니다. 색 채널 막대는 채널 값의 크기이며 클래스 확률이 아닙니다.

**배치·색·화살표:** 사진/확대의 그림 높이와 화살표 중심을 맞춥니다. 사진 자체에 추가 배경·중첩 프레임을 붙이지 않습니다. RGB 막대는 채널에 의미가 있는 작은 색상 영역입니다.

**초급자 최소 설명·삭제 금지:** 8-bit 범위 0–255, 확대 배열 4×4, 실제 선택 픽셀, HWC의 높이/너비/채널 의미. 선택 수치만 남기고 픽셀과의 대응을 없애지 않습니다.

**구현:** [concept.html](../templates/html/concept.html)의 inline JS, 공통 styles/reference-layout CSS. **프리뷰:** [PNG](../previews/html-concept.png).

**검증:** 16개 셀과 같은 Canvas 래스터, 선택 RGB/HEX/스와치/막대의 일치, 사진 로드, 확대 화살표 중심, 모바일 가로 폭, 실제 글꼴.

## 02 Process

**목적·독자:** CNN 또는 다른 파이프라인의 단계별 역할을 배우는 독자. **핵심 메시지:** 입력에서 표현을 추출하고 목적별 처리로 출력을 만듭니다.

**전체 구조:** Input → Feature → Task → Output 4개 노드, 단계 사이 화살표 3개. 마지막 캡션은 특징 추출기와 Task Head의 역할을 구분합니다.

**데이터·계산:** 특징 맵 그림은 실제 사진에서 유도한 고정 필터 예제입니다.

- 64×64 RGB를 휘도 `Y=(0.2126R+0.7152G+0.0722B)/255`로 바꾸고 Float32에 저장합니다.
- 3×3 Sobel 방향성 차분 `gx`, `gy`를 계산합니다. 경계는 가장자리 픽셀 반복입니다.
- 채널 c의 방향은 `θ=cπ/8`, c=0…15.
- `A_c=max(0,(gx cosθ + gy sinθ + (c mod 4)×0.007)×3.2)`.
- 대표 채널 0/3/6/9의 64×64 맵을 4개 평면으로 표시합니다. 화면 색상은 `t=clamp(4.5A)^0.74`, 밝은 `[242,247,253]`에서 진한 `[30,74,142]`까지 보간한 값입니다.

**요소와 의미:** 사진=RGB 입력, 4개 맵=특징 표현 모티프, Task Head 노드=목적별 출력 변환, 출력 막대=클래스 점수 등의 개념적 출력. 막대에 학습 모델의 실제 확률이라는 의미를 부여하지 않습니다.

**배치·색·화살표:** 동일한 노드 높이와 외부 Blue 흐름. Feature는 작은 Pale Blue, Output은 Pale Teal로 기능을 구분합니다. 모바일 읽는 순서를 유지합니다.

**초급자 최소 설명·삭제 금지:** 입력 이미지·계층적 특징 추출·목적별 처리·결과라는 역할 구분. 표현 학습과 출력 변환의 차이를 설명하는 마지막 캡션.

**구현:** [process.html](../templates/html/process.html), [cnn-feature-maps.js](../templates/html/assets/cnn-feature-maps.js), styles/reference-layout CSS. 엔진의 `window.CNNFeatureMaps`는 로딩 상태와 계산된 gray/conv1을 제공하며 `.status==='ready'` 후 사용할 수 있습니다.

**프리뷰:** [PNG](../previews/html-process.png). **검증:** 16채널×7개 위치의 독립 방향성 차분 계산, 대표 맵 4개×7픽셀의 색상 일치, 사진과 맵 로드·흐름 방향. 이 엔진은 #6의 구조 모식도와 별개입니다.

## 04 Step-by-Step

**목적·독자:** convolution의 국소 계산을 처음 배우는 독자. **핵심 메시지:** 선택한 입력 영역의 원소별 곱 9개를 더하면 출력 한 칸이 됩니다.

**전체 구조:** 왼쪽 카드에서 입력 영역과 출력 위치를 연결하고, 오른쪽 카드에서 같은 선택 영역·커널·원소별 곱·합산을 풉니다. 두 카드 하단 설명 구분선은 데스크톱에서 같은 높이입니다.

**데이터:**

```text
입력 X (5×5)             커널 K (3×3)
1 2 3 1 0                1 0 -1
4 5 6 2 1                1 0 -1
7 8 9 3 1                1 0 -1
2 1 0 4 2
1 3 2 1 0

원소별 곱 (좌상단)        전체 출력 Y (3×3)
1 0 -3                   -6  9 16
4 0 -6                   -2  5 11
7 0 -9                   -1  4  8
```

**정확한 수식·조건:**

`Y[y,x] = Σ(ky=0…2) Σ(kx=0…2) X[y+ky,x+kx] K[ky,kx]`.

Stride 1, padding 0, 단일 채널, bias 0, 커널 반전 없음. 출력 한 변은 `floor((5+2×0−3)/1)+1=3`입니다. 화면의 (1,1)은 **1-based 좌상단 위치**, 코드의 y/x 인덱스는 0-based입니다.

`Y[0,0] = 1+0−3+4+0−6+7+0−9 = −6`.

**요소와 의미:** 왼쪽 5×5의 행·열 0…2에 해당하는 9칸을 강조하고 출력 좌상단 하나를 Navy로 강조합니다. 오른쪽은 같은 9칸·같은 커널·각 곱셈 식과 값·합·출력 위치를 보여줍니다. 나머지 출력 8개도 실제로 계산된 값입니다.

**색·화살표·배치:** 선택 영역은 Blue 계열, 커널은 작은 Teal 면, 최종 출력은 Navy입니다. 연결은 Blue SVG 경로입니다. 원소별 곱 기호는 원·점 SVG이며 다른 텍스트 글꼴을 쓰지 않습니다.

**초급자 최소 설명·삭제 금지:** 기호의 뜻, 9개 곱을 전부 더한다는 문구, 한 칸씩 커널을 움직여 전체 출력이 만들어진다는 설명, 실제 CNN의 가중치는 학습된다는 조건.

**구현:** [step-by-step.html](../templates/html/step-by-step.html)의 편집 가능한 정적 행렬·inline CSS, 공통 CSS. 별도 JS는 없으며 검증이 모든 출력 값을 독립 계산합니다. **프리뷰:** [JPG](../previews/html-step-by-step.jpg).

**검증:** 25개 입력·커널 2곳의 동일성·패치 9개·곱 9개·합 −6·전체 3×3 출력, 좌상단 대응, 카드 구분선 Y차이≤1px, 실제 폰트·SVG 기호·오버플로. 모바일의 합산식은 공백에서 자연스럽게 줄을 바꾸며 실제 글자 경계까지 카드 패딩 안에 유지합니다.

## 05 Interactive

**목적·독자:** 임계값 조절과 오탐·미탐의 관계를 체험하는 학습자. **핵심 메시지:** 실제값은 고정이고 임계값이 예측을 바꿔 행렬과 지표를 바꿉니다.

**구조·배치:** 왼쪽 실제 이상 #2·#4·#5 / 실제 정상 #1·#3·#6의 고정 그룹. 점수 → 예측 배지 → 유형을 같은 행에 놓습니다. 판정 규칙과 주황 점선 범례는 분리합니다. 오른쪽에 행렬과 두 지표, 마지막에 Teal 캡션.

| ID | 점수 | 실제값 | 기본 0.60의 예측·유형 |
| --- | ---: | --- | --- |
| #1 | .15 | 정상 | 정상 TN |
| #2 | .32 | 이상 | 정상 FN |
| #3 | .48 | 정상 | 정상 TN |
| #4 | .67 | 이상 | 이상 TP |
| #5 | .82 | 이상 | 이상 TP |
| #6 | .94 | 정상 | 이상 FP |

**수식:** `score ≥ threshold → 이상(양성)`. 범위 0.00–1.00, 간격 .05, 초기 .60. `Precision=TP/(TP+FP)`, `Recall=TP/(TP+FN)`이며 일반식과 실제 대입식을 함께 표시합니다. 분모가 0이면 `정의 불가`, 비율은 소수 1자리입니다.

**기본 결과:** TP=2, FP=1, FN=1, TN=2, Precision/Recall=66.7%. 0.70으로 올리면 #4만 TP→FN, 두 지표는 50.0%/33.3%입니다.

**색·강조:** 예측 이상 Blue / 예측 정상 Muted, 정오 판정 TP/TN Teal / FP/FN Amber. 실제 예측이 바뀐 배지만 550ms 강조하며 모션 감소 설정에서는 생략합니다.

**최소 설명·삭제 금지:** 양성=이상, 실제값 그룹, 임계값 기준, 예측 클래스와 유형의 구분, 한 줄 지표 뜻·일반식·대입식, 요약 개수, 마지막 임계값 캡션. 샘플 위치를 매번 재정렬하지 않습니다.

**구현:** [interactive.html](../templates/html/interactive.html), [interactive-reference.js](../templates/html/interactive-reference.js), 공통 CSS. [공유용 단일 HTML](../previews/review/interactive-live.html)은 생성본입니다. **프리뷰:** [JPG](../previews/html-interactive.jpg).

## 06 Architecture

**목적·독자:** CNN의 연산·모듈 경계와 차원 변화를 읽는 독자. **핵심 메시지:** 이 모델의 Conv는 특징 채널을 만들고 Pool은 공간을 줄이며 Flatten 후 분류합니다.

**최종 구조:** Input → Conv Block 1 → Conv Block 2 → Flatten → FC Layer → Softmax.

| 단계 | 연산 | 전후 Shape |
| --- | --- | --- |
| Input | RGB 사진 한 장, batch 생략 | 64×64×3 |
| Block 1 Conv | 3×3, S1, P1, out=16 | 64×64×3 → 64×64×16 |
| Block 1 ReLU | max(0,x) | Shape 유지 |
| Block 1 Pool | MaxPool 2×2 S2 | 64×64×16 → 32×32×16 |
| Block 2 Conv | 3×3, S1, P1, out=32 | 32×32×16 → 32×32×32 |
| Block 2 ReLU | max(0,x) | Shape 유지 |
| Block 2 Pool | MaxPool 2×2 S2 | 32×32×32 → 16×16×32 |
| Flatten | 원소 순서 재배열 | 16×16×32 = 8,192 |
| FC | z=Wx+b, W는 3×8192 | 8,192 → 3 logits |
| Softmax | p_i=exp(z_i)/Σ exp(z_j) | 3 probabilities |

**차원 수식:** `out=floor((n+2p−d(k−1)−1)/s)+1`, dilation d=1. Conv는 H/W를 유지하고 Pool은 두 번 절반으로 줄입니다. 다른 CNN에 이 역할을 보편 규칙으로 강제하지 않습니다.

**확률 예시:** logits `[2,1,0]`의 softmax는 `[0.665240956,0.244728471,0.090030573]`, 표시는 `P(class0)=66.5%`, `P(class1)=24.5%`, `P(class2)=9.0%`, 합 100.0%입니다. 사진에 대한 실제 추론 결과가 아닙니다.

**Figure 요소·배치:** 입력 사진 한 개. 두 Block 내부의 큰 Conv Stack → 작은 Pool Stack. Stack 평면 7개는 채널 수의 축약 표현입니다. Flatten은 Stack → 세로 1D 벡터이며 34개 대표 셀과 생략점으로 8,192차원을 축약합니다. FC는 벡터와 세 노드, Softmax는 클래스별 막대입니다. Feature Extractor/Classifier 범위 선으로 역할을 구분합니다.

**색·화살표·중앙축:** 외부 Blue 5개, 내부 Teal 3개. 각 화살표의 직선·화살촉은 한 path이며 같은 tip 좌표를 씁니다. 실제 Stack bounding box 사이의 간격으로 내부 화살표를 계산합니다. 제목·그림·Shape 중심축은 desktop/tablet에서 2px 이내입니다. 폰트 로딩 후 `getBBox()`로 그림 중심을 다시 맞춥니다. 520px 이하의 왼쪽 그림/오른쪽 텍스트 배치는 의도된 예외입니다.

**최소 설명·삭제 금지:** 모든 출력 Shape, Conv/ReLU/MaxPool 순서, 첫 Block의 역할 설명, Flatten 차원, FC의 logits와 Softmax 확률 구분, 설명용 확률 표기, 단일 사진.

**데이터 단순화:** 맵 패턴은 SVG 구조 설명을 위한 모식도이며 #2·#3 고정 필터 엔진을 사용하지 않습니다. 그려진 작은 격자 수·평면 수를 실제 Tensor 크기로 해석하지 않습니다.

## 07 Experiment

**목적·독자:** 혼동행렬에서 정확도·정밀도·재현율·F1이 어떻게 나오는지 배우는 독자. **핵심 메시지:** 같은 판정 개수를 다른 질문의 분모로 해석합니다.

**구조:** 왼쪽 흰색 Confusion Matrix 카드, 오른쪽 4개 Metrics 카드. 지표별 이름·값·짧은 뜻·일반식·대입식을 묶습니다. FP/FN 설명은 행렬 카드 안에 있습니다.

| 모델 예측 / GT | 실제 이상 | 실제 정상 |
| --- | ---: | ---: |
| 예측 이상 | TP=4 | FP=1 |
| 예측 정상 | FN=2 | TN=5 |

평가 샘플 총 12, 실제 이상 6·정상 6, 양성은 이상입니다. GT는 상단 가로축, 모델 예측은 좌측 세로축이며 **예측 이상이 위 행**입니다.

| 지표 | 식 | 대입 결과 |
| --- | --- | --- |
| Accuracy | (TP+TN)/(TP+TN+FP+FN) | 9/12 = 75.0% |
| Precision | TP/(TP+FP) | 4/5 = 80.0% |
| Recall | TP/(TP+FN) | 4/6 = 66.7% |
| F1 | 2TP/(2TP+FP+FN) | 8/11 = 72.7% |

동치식 `F1=2PR/(P+R)`을 함께 표기합니다. 표시용으로 반올림한 80.0/66.7을 다시 넣어 계산하지 않고 원래 비율에서 반올림합니다.

**색·기하:** TP/TN Teal, FP/FN Amber. 축·행열 라벨·각 셀의 코드와 숫자는 중앙 정렬. GT 아래 가로선, 모델 예측과 행 라벨 사이 중앙의 세로선. 세로선은 실제 텍스트 경계를 Range로 측정하고 zoom·선 두께를 보정합니다.

**최소 설명·삭제 금지:** `FP: 정상인데 이상으로 예측`, `FN: 이상인데 정상으로 예측`, 예시 12개·양성 정의, 모든 수식과 실제 계산 결과. 최초 구상보다 우선하는 최종 축 순서를 유지합니다.

**구현:** [experiment.html](../templates/html/experiment.html)의 HTML 표·inline CSS·세로선 정렬 JS, 공통 CSS. **프리뷰:** [JPG](../previews/html-experiment.jpg).

**검증:** 행렬 합·정답 개수·행열 위치·네 지표와 두 F1 식, 코드/숫자/축 정렬 오차<2px, 세로선 양쪽 간격 차이<0.25px, 카드/푸터·폰트·모바일. [상세 패턴](EXPERIMENT_PATTERN.md).

## 08 Executive Summary

**목적·독자:** 운영 효율의 숫자와 실행 항목을 빠르게 검토하는 독자. **핵심 메시지:** 효율 지표의 변화와 파일럿 확대 시 확인할 위험을 함께 봅니다.

**전체 구조:** 왼쪽 넓은 흰색 카드 안에 3개의 KPI 그룹, 각 그룹은 기존 Blue / 개선안 Teal 세로 막대·실제 수치/단위·지표 이름·변화율입니다. 오른쪽 흰색 카드에는 우선순위 설정 / 파일럿 기준 통일 / 확대 판단의 세 항목입니다.

| KPI | 기존 | 개선안 | 변화율 | 개선안의 정규화 높이 |
| --- | ---: | ---: | ---: | ---: |
| 월간 수동 점검 | 120건 | 80건 | −33.3% | 0.6667 |
| 평균 처리 시간 | 45분/건 | 30분/건 | −33.3% | 0.6667 |
| 월말 미처리 | 20건 | 8건 | −60.0% | 0.4 |

**수식:** `ratio=after/before`, `change=(after−before)/before×100%`. 공통 Y축의 100%는 **각 지표의 기존 값**입니다. 절대 측정 단위가 다른 KPI를 같은 절대값 축으로 그리지 않습니다.

**도형·색·배치:** 기존 막대 3개는 같은 높이·공통 기준선, 개선 막대는 실제 비율 높이입니다. 숫자와 단위는 각각의 막대 바로 위, 지표·감소율은 그룹 아래 중앙에 둡니다. 모바일에서도 KPI 세 그룹을 가로로 유지하되 단위는 숫자 아래로 나눕니다.

**초급자 최소 설명·삭제 금지:** 지표별 기준 100% 문구, 기존/개선안 범례, 원래 수치·단위, 변화율, 효율과 미검출 위험을 함께 확인하는 실행 항목.

**데이터 조건:** 이 숫자는 디자인 예시이며 실측 파일럿 결과가 아닙니다. 현재 main 레이아웃을 보존한 통합입니다. 실제 보고에 재사용할 때 집계 기간·조건·출처·위험 검증과 확대 기준을 확보하며, 미제공 실측값이나 허용 기준을 만들어 넣지 않습니다.

**구현:** [executive-summary.html](../templates/html/executive-summary.html)의 정적 HTML/CSS·data-before/data-after·정규화 ratio, 공통 CSS. **프리뷰:** [JPG](../previews/html-executive-summary.jpg).

**검증:** 3개 KPI의 원래 값·단위·변화율·막대 높이 비율·기준선·Y축 눈금, 그룹 라벨 중앙, 숫자/막대 겹침, 좌우 카드/모바일 순서·폰트.
