## 01 Concept

**목적·독자:** 디지털 이미지의 숫자 표현을 처음 배우는 독자. **핵심 메시지:** 한 RGB 사진은 같은 높이(H)·너비(W)의 채널 세 장이며, 같은 위치의 세 정수가 한 픽셀의 색을 이룹니다. CNN·커널·특징 추출·분류는 이 페이지의 범위가 아닙니다.

**최종 출처:** [PR #15](https://github.com/sh0427-han/design-template-library/pull/15)의 사용자 검토 완료본. **제목·부제:** `이미지의 숫자 구조` / `입력 사진 → RGB 숫자 행렬 → 일부 확대 → 픽셀 하나의 RGB 값`.

### 전체 구조와 읽는 순서

White 패널 하나 안에서 4단계를 Blue 화살표 세 개로 연결합니다. 아래에는 한 픽셀의 성분 조합 행, 패널 밖 Content 마지막에는 전체 배열의 Teal 핵심 캡션을 둡니다. 별도의 오른쪽 설명 카드는 없습니다.

| 순서 | 구성 요소 | 의미·배치 |
| --- | --- | --- |
| 1 입력 이미지 | 실제 사과 사진 한 장 | 사진에는 ROI 테두리를 중복 표시하지 않음 |
| 2 채널 분리 | 실제 R/G/B Canvas 세 평면, H/W/C=3 축, 앞 R 평면의 ROI | 세 채널의 같은 위치를 대표하는 영역. 8×8 안내선은 데이터 해상도가 아님 |
| 3 일부 확대 | 같은 ROI의 4×4 격자 세 장, H=4/W=4, R/G/B 배지 | 전면은 원본 RGB 합성색, 뒤 G/B는 채널 강도에 따른 표시색. 16픽셀×3성분=48개 값 |
| 4 선택 픽셀 | 선택 Halo, Swatch·RGB·HEX, R/G/B 숫자와 막대 | 선택 index 6의 실제 세 값을 한 묶음으로 표시 |
| 패널 하단 | 같은 위치의 R/G/B 숫자 → 합성 Swatch | `+`는 세 성분의 조합이며 산술 합산을 뜻하지 않음 |
| 마지막 캡션 | H×W×3 배열 | 전체 이미지의 일반적인 HWC 표현. CHW도 가능하며 저장 바이트 수를 뜻하지 않음 |

### 데이터와 실제 계산

1. 입력 파일은 [concept-apple-photo.jpg](../templates/html/assets/concept-apple-photo.jpg) 하나입니다. `image.decode()` 후 `imageSmoothingEnabled=true`, `imageSmoothingQuality=high`로 전체를 80×80 Canvas에 그립니다. 원본 파일 크기·분석 해상도·화면 표시 크기를 구별합니다.
2. 각 채널 Canvas는 동일한 80×80 RGBA 버퍼를 사용합니다. R/G/B 중 해당 성분에만 원래 8-bit 값을 넣고 다른 두 성분은 0, alpha는 255입니다. 각 평면은 6,400개의 실제 채널 값입니다. 8×8 가는 안내선은 행렬의 모양을 설명할 뿐 8×8 다운샘플을 뜻하지 않습니다.
3. `getImageData(52,38,4,4)`의 0-based ROI는 16픽셀입니다. R 평면 위 테두리의 비율은 `left=52/80=65%`, `top=38/80=47.5%`, `width=height=4/80=5%`입니다. 세 채널이 같은 공간 좌표를 공유합니다.
4. 선택 index 6은 row-major 기준 로컬 `(x=2,y=1)`, 전체 분석 좌표 `(54,39)`입니다. 기준 Chromium의 RGB는 **(223,54,56)**, HEX는 **#DF3638**입니다. 독립 리샘플 결과와 비교하며, 이미지/좌표/분석 조건을 바꾸면 이 값도 다시 계산합니다.
5. 채널 값은 각각 0–255 정수, 막대 길이는 `100×value/255%`입니다. 세 막대의 합이 100%일 필요가 없으며 클래스 확률이 아닙니다. RGB 문자열·대문자 HEX·Swatch·세 수치·막대·하단 조합은 같은 선택값에서 갱신합니다.

### 확대의 원본 값과 표시색

전면 4×4는 16개의 원본 RGB 합성색입니다. 전면에 R 배지를 사용하지만 **순수 R 채널의 색상 평면은 아닙니다**. 중간 G·후면 B는 원본 채널 강도를 읽기 쉽게 표시합니다. 각 셀의 `data-raw-value`에 원본 성분을 유지하고, CSS `outlineColor`에서 읽은 기준색 G `#279467`, B `#427ec5`에 다음 표시 전용 보간을 적용합니다.

```text
t = 0.22 + 0.78 × (rawValue / 255)
displayComponent = Math.round(255 + (baseComponent − 255) × t)
```

이 표시색을 RGB/HEX·막대·하단 Swatch 계산에 사용하지 않습니다. 채널별 원본 수치와 가독성을 위한 색 표현을 혼동하지 않습니다. 확대의 DOM/z-index 순서는 B → G → RGB이며, 전면의 선택 index 6에만 White 2px Halo와 Navy 5px 외곽 강조 및 선택점을 둡니다. 각 격자는 숫자를 반복하지 않고 색 셀 16개를 유지합니다.

### PC Figure·Typography·정렬

- 패널 padding `22px 25px`, border 1px, radius 18px, White, 그림자 없음. IMAGE REPRESENTATION 라벨은 Blue/16px/20px/800, 아래 간격 8px. 제목은 Navy/23px/800입니다. 4단계는 `.95fr / 25px / 1.15fr / 25px / .85fr / 25px / 1.25fr`, gap 9px입니다.
- 각 Figure 슬롯 높이는 254px이며 단계 안 Figure/라벨/짧은 설명 간 gap은 9px입니다. 단계 제목은 Navy/17px/1.28, 설명은13px/1.35를 사용합니다. 제목과 설명은4단계에서 같은 Y좌표를 유지합니다.
- 사진 최대 207px 정사각형. 전체 채널 Stack은 244×245px, 평면은 157px 정사각형이며 R/G/B의 좌상단은 `(15,68)/(42,43)/(69,18)`입니다. C=3은 평면 밖 위쪽, H/W는 공간축에 둡니다.
- 확대는 셀 28px×4 + gap 2px×3 = 118px입니다. G/B는 전면 대비 `(+16,−16)/(+32,−32)px`이며 우상단 배지는 15px입니다. 윤곽은 각 채널색의 동일한 2px outline, radius 2px, 동일한 작은 그림자입니다. outline은 셀 치수를 바꾸지 않습니다.
- H=4는 전면 왼쪽의 세로 중심에 회전한 글자, W=4는 전면 격자의 가로 중심 아래입니다. 확대에는 축 가이드선과 C=3을 추가하지 않습니다. `4×4×3=48개 값`은 확대 Figure 아래 짧은 설명에 둡니다.
- 선택 Swatch는 42px, 상세 영역 최대 236px, RGB 17px/1.25, 채널 수치 21px/1.35입니다. 하단 조합 행은 1px 구분선·위 padding 12px·16px/1.35, 합성 Swatch 29px입니다.
- 전역 Pretendard Variable/−1pt, Navy/Blue/Teal을 상속합니다. R/G/B 고유색은 데이터의 성분 구분용이며 과정마다 다른 장식색을 붙이지 않습니다. 큰 패널 아래 마지막 캡션과 Footer가 겹치지 않아야 합니다.

기존 호환 CSS는 900px 이하에서 4단계를 세로로 배치하며 520px 이하에서는 확대 셀 26px/gap 2px(110px), G/B 노출 폭 12px, 배지 11px, Swatch 40px, 상세 영역 최대 214px를 사용합니다. 이 정보는 현재 구현 설명이며 새 자료의 필수 제작 대상은 PC 4개 크기입니다.

## 02 Process

**목적·독자:** CNN 예측 과정을 처음 배우는 독자. **핵심 메시지:** 입력 이미지는 CNN에서 특징으로 표현되고, Task Head는 그 특징을 목적에 맞는 예측 결과로 변환합니다.

**#6과 역할 구분:** #2는 입력→특징 추출→목적별 처리→출력의 역할을 설명합니다. #6은 Conv/ReLU/Pool/Flatten/FC/Softmax와 Tensor Shape를 설명합니다. 사진·평면 Stack·Blue 외부 화살표·Teal 내부 변환·Navy 제목의 표현은 공유하되, #6의 내부 구조 전체를 #2 안에 축소 복제하지 않습니다. #2에는 커널/stride/padding·Flatten 차원·FC 연결·Softmax 수식을 나열하지 않습니다.

**제목·부제:** `CNN의 예측 흐름` / `이미지 → 특징 추출 → 목적별 처리 → 예측 결과`.

**전체 구조:** INPUT → FEATURE → TASK → OUTPUT의 동일 크기 카드 4개와 Blue 외부 화살표 3개. 각 카드는 Stage Label, 독립 Figure 슬롯, Title, Description 순서입니다. 마지막 흰색 캡션/Teal 왼쪽 선에 `역할 분리`와 `CNN은 이미지에서 특징을 추출하고, Task Head는 이를 목적에 맞는 예측으로 변환`을 둡니다.

**화살표 위치:** 카드 바깥 Blue 연결 화살표는 카드 컨테이너 전체 높이 기준으로 수직 중앙 정렬(`top: 50%` + `translateY(-50%)`)합니다. Figure 슬롯 속 그림 중앙과 혼동하지 않습니다. 좁은 화면에서 세로로 회전하는 기존 동작과 TASK Figure 안의 Teal 화살표 두 개는 그대로 유지합니다.

| 단계 | Figure·의미 | 제목 | 설명 | 카드 배경·경계 |
| --- | --- | --- | --- | --- |
| INPUT | 기존 사과 사진 한 장, RGB 입력 | 입력 이미지 | RGB 픽셀 데이터 | White / Border |
| FEATURE | 실제 계산한 대표 맵 4장의 Stack | CNN | 이미지에서 특징 추출 | Pale Blue / Blue |
| TASK | 짧은 특징 벡터 → 분류 Head → 예시 점수 3개 | Task Head | 특징을 목적에 맞게 처리 | White / Border |
| OUTPUT | 사과/토마토/기타 확률과 수평 막대 | 예측 결과 | 클래스별 예측 확률 | White / Border |

**강조 정책:** CNN 특징 추출을 학습 초점으로 드러내기 위해 FEATURE만 컬러 배경을 씁니다. OUTPUT의 Pale Teal 배경과 Teal 카드 테두리는 `.process-slide .node:not(.feature)`에서 White/Border로 덮어씁니다. 공통 `.node.output` 규칙은 변경하지 않습니다. 카드별 의미는 문자·위치로도 전달합니다.

### 사진과 특징 맵 계산

입력 파일은 `assets/concept-apple-photo.jpg` 그대로입니다. 사진 한 장을 desktop 124×124px / mobile 120×120px, object-fit cover로 표시합니다. #6의 단일 사진처럼 추가 장식 배경·외곽 프레임·그림자 없이 사용합니다. RGB Tensor의 내부 구조는 #1에서 설명합니다.

화면 사진 크기·원본 해상도와 아래 계산용 64×64 크기는 서로 다릅니다. 공통 엔진은 #3과 공유하며 수정하지 않습니다.

1. Canvas를 64×64로 만들고 `imageSmoothingEnabled=true`, `imageSmoothingQuality='high'`로 RGB 사진을 리샘플합니다.
2. `Y=(0.2126R+0.7152G+0.0722B)/255`를 Float32 배열에 저장합니다.
3. `gx`는 `[[−1,0,1],[−2,0,2],[−1,0,1]]/8`, `gy`는 `[[−1,−2,−1],[0,0,0],[1,2,1]]/8`로 계산합니다. 경계는 가장자리 픽셀 반복입니다.
4. 채널 c=0…15의 방향 `θ=cπ/8`에서 `A_c=max(0,(gx cosθ + gy sinθ + (c mod 4)×0.007)×3.2)`를 계산합니다.
5. 대표 채널 0/3/6/9를 표시합니다. 색상은 `t=clamp(4.5A)^0.74`, 밝은 `[242,247,253]`에서 진한 `[30,74,142]`까지 보간합니다.

### Feature Stack 재구현 규격

### Task Head · 기존 그림 유지

기존의 **짧은 특징 벡터 → 분류 Head → 점수 3개** 그림을 사용합니다. 7개 대표 직사각형 셀은 특징을 요약하는 기호이며 실제 차원·Flatten 크기·레이어 수를 뜻하지 않습니다. 실제 학습된 분류기를 호출하지 않는 역할 **모식도**입니다. 복잡한 FC 교차 연결이나 Flatten/FC/Softmax의 독립 블록은 추가하지 않습니다.

TASK 제목 `Task Head`, 설명 `특징을 목적에 맞게 처리`, White 배경, FEATURE 단독 강조, 최신 Stack·Output·전체 정렬은 유지합니다. TASK의 예시 점수와 Output의 확률·막대·강조·접근성 설명은 같은 JS 점수 배열에서 함께 갱신합니다.

## 03 Comparison

**목적·독자:** 같은 이미지 분류 문제에서 규칙 기반과 지도학습의 차이를 처음 배우는 독자. **핵심 메시지:** 서로 다른 것은 판단 기준을 만드는 방법이며, 두 방식 모두 준비된 판단 체계를 새 이미지에 적용합니다. 어느 한 방식이 모든 상황에서 우월하다는 결론을 만들지 않습니다.

동일한 White 카드 2개를 사용합니다. 각 카드의 Label → 핵심 제목 → 소개 → 준비 도식 → 예측 도식 → 동일한 3개 비교 행 → 장점/한계 순서입니다. 준비와 예측은 작은 단계 라벨·가는 구분선으로 나누고, 준비한 규칙/모델을 아래 적용 노드로 연결하는 Teal 직교 화살표를 둡니다.

| --- | --- | --- |

Figure는 과정, 비교표는 차이점 요약입니다. 표의 설명을 Figure 안에서 긴 문장으로 다시 반복하지 않습니다. #2는 예측의 역할 흐름, #3은 기준 준비 방법과 적용의 비교, #6은 내부 모듈·Tensor Shape를 담당합니다. #3에 Conv/ReLU/Pool/Flatten/FC/Softmax 전체를 복제하지 않습니다.

### 규칙 기반 · 사람이 정의한 기준

SVG 사람 기호와 작은 조건 표를 묶습니다. 조건은 `색상: 붉은색 영역`, `형태: 둥근 윤곽`입니다. `조건 조합` 화살표 뒤 판단 규칙의 `색상 AND 형태`가 두 조건을 함께 만족시키는 논리를 뜻합니다. 규칙 블록에서 아래 조건 검사로 연결합니다.

개념식은 `R(x)=색상조건(x) AND 형태조건(x)`입니다. 실제 색상 비율·둥근 정도·수치 임계값을 측정하거나 이 규칙을 실행하지 않습니다. `사과 판정 / 예시`는 설명용 결과이며 검증된 규칙 엔진의 출력이나 정확도가 아닙니다. 규칙 변경은 개발자의 조건·임계값 수정이라는 점을 표에 남깁니다.

### 머신러닝 · 지도학습 준비와 추론 분리

학습 자료는 HTML 안에 직접 작성한 **서로 다른 SVG 일러스트 3개**입니다.

1. 붉은 사과의 윤곽과 오른쪽 잎 / 라벨 `사과`.
2. 다른 윤곽·색상·잎 방향의 초록 사과 / 라벨 `사과`.
3. 납작한 타원과 별 모양 꼭지의 토마토 / 라벨 `토마토`.

이것은 실제 데이터셋도, 실제 사진 3장도 아닙니다. 예측 사진을 복사해 독립 학습 샘플처럼 사용하지 않습니다. 화면에는 `지도학습 · 일러스트 예시`, aria-label에는 이미지와 정답 라벨의 관계를 명시합니다.

`학습` 화살표와 `학습된 모델 / 파라미터 최적화`는 지도학습에서 데이터·정답을 통해 파라미터를 맞추는 개념을 보여줍니다. 일반적인 개념식 `θ*=argmin_θ Σ_i L(f_θ(x_i),y_i)`는 목적을 설명할 뿐이며 이 HTML이 최적화·손실 계산·가중치 학습을 실행하지 않습니다. 모든 머신러닝이 정답 라벨을 요구한다고 일반화하지 않습니다.

아래 입력은 왼쪽과 동일한 `assets/concept-apple-photo.jpg` 한 장입니다. 학습 완료된 모델을 새 이미지에 적용하는 역할을 `학습된 CNN` 상징과 연결합니다. `사과 예측 / 예시`는 실제 학습 모델의 추론이나 실측 성능이 아닙니다. 예측값·확률·정확도를 임의로 만들어 넣지 않습니다.

### 실제 계산 맵과 모델 모식도의 경계

공통 [cnn-feature-maps.js](../templates/html/assets/cnn-feature-maps.js)는 그대로 사용합니다. 실제 계산은 #2의 [필터 명세](#02-process)와 같습니다. 입력 사진을 64×64로 리샘플하고 휘도·고정 3×3 방향성 필터 16개·ReLU를 계산합니다. 대표 채널 0/3/6/9의 PNG 데이터 URL과 Blue 색상 ramp를 변경 없이 사용합니다.

**실제인 부분은 사진→고정 필터 반응 맵뿐입니다.** 이를 학습된 CNN의 실측 활성화로 해석하지 않습니다. 모델 학습과 준비→적용 연결은 역할 모식도이며, 두 결과 모두 예시입니다. 화면의 `맵: 고정 필터 설명용`, SVG의 `학습된 모델의 실측 활성화가 아님`, JS의 `ruleEngineExecuted:false`, `modelInferenceExecuted:false`를 유지합니다.

#3 전용 표시 스크립트는 뒤쪽 채널 9/6/3/0 순서로 평면을 겹칩니다. SVG viewBox `136×124`, 이미지 `88×88`, depth k의 위치 `(10+11k,30−8k)`, 외곽 면 `92×92`/radius 1.5입니다. 전면 경계 `#4679b8`/1.5px, 뒤쪽 `#6e94c6`/1.05px, 배경 `#b7cdea`로 #2/#6과 오른쪽 위 깊이 방향·가는 Blue 면 스타일을 맞춥니다. #6의 손으로 만든 활성화 패턴은 사용하지 않습니다. SVG 실제 `getBBox()`를 양축 중앙으로 옮깁니다.

## 04 Step-by-Step

**목적·독자:** convolution의 국소 계산을 처음 배우는 독자. **핵심 메시지:** 선택한 입력 영역의 원소별 곱 9개를 더하면 출력 한 칸이 됩니다.

**전체 구조:** 왼쪽 카드에서 입력 영역과 출력 위치를 연결하고, 오른쪽 카드에서 같은 선택 영역·커널·원소별 곱·합산을 풉니다. 두 카드 하단 설명 구분선은 데스크톱에서 같은 높이입니다.

**데이터:**

```text
입력 X (5×5)             커널 K (3×3)
1 2 3 1 0                1 0 -1
4 5 6 2 1                1 0 -1
7 8 9 3 1                1 0 -1
2 1 0 4 2
1 3 2 1 0

원소별 곱 (좌상단)        전체 출력 Y (3×3)
1 0 -3                   -6  9 16
4 0 -6                   -2  5 11
7 0 -9                   -1  4  8
```

**정확한 수식·조건:**

`Y[y,x] = Σ(ky=0…2) Σ(kx=0…2) X[y+ky,x+kx] K[ky,kx]`.

Stride 1, padding 0, 단일 채널, bias 0, 커널 반전 없음. 출력 한 변은 `floor((5+2×0−3)/1)+1=3`입니다. 화면의 (1,1)은 **1-based 좌상단 위치**, 코드의 y/x 인덱스는 0-based입니다.

`Y[0,0] = 1+0−3+4+0−6+7+0−9 = −6`.

**요소와 의미:** 왼쪽 5×5의 행·열 0…2에 해당하는 9칸을 강조하고 출력 좌상단 하나를 Navy로 강조합니다. 오른쪽은 같은 9칸·같은 커널·각 곱셈 식과 값·합·출력 위치를 보여줍니다. 나머지 출력 8개도 실제로 계산된 값입니다.

**색·화살표·배치:** 선택 영역은 Blue 계열, 커널은 작은 Teal 면, 최종 출력은 Navy입니다. 연결은 Blue SVG 경로입니다. 원소별 곱 기호는 원·점 SVG이며 다른 텍스트 글꼴을 쓰지 않습니다.

**초급자 최소 설명·삭제 금지:** 기호의 뜻, 9개 곱을 전부 더한다는 문구, 한 칸씩 커널을 움직여 전체 출력이 만들어진다는 설명, 실제 CNN의 가중치는 학습된다는 조건.

**구현:** [step-by-step.html](../templates/html/step-by-step.html)의 편집 가능한 정적 행렬·inline CSS, 공통 CSS. 별도 JS는 없으며 검증이 모든 출력 값을 독립 계산합니다. **프리뷰:** [JPG](../previews/html-step-by-step.jpg).

**검증:** 25개 입력·커널 2곳의 동일성·패치 9개·곱 9개·합 −6·전체 3×3 출력, 좌상단 대응, 카드 구분선 Y차이≤1px, 실제 폰트·SVG 기호·오버플로. 모바일의 합산식은 공백에서 자연스럽게 줄을 바꾸며 실제 글자 경계까지 카드 패딩 안에 유지합니다.

## 05 Interactive

**목적·독자:** 임계값 조절과 오탐·미탐의 관계를 체험하는 학습자. **핵심 메시지:** 실제값은 고정이고 임계값이 예측을 바꿔 행렬과 지표를 바꿉니다.

**구조·배치:** 왼쪽 실제 이상 #2·#4·#5 / 실제 정상 #1·#3·#6의 고정 그룹. 점수 → 예측 배지 → 유형을 같은 행에 놓습니다. 판정 규칙과 주황 점선 범례는 분리합니다. 오른쪽에 행렬과 두 지표, 마지막에 Teal 캡션.

| ID | 점수 | 실제값 | 기본 0.60의 예측·유형 |
| --- | ---: | --- | --- |
| #1 | .15 | 정상 | 정상 TN |
| #2 | .32 | 이상 | 정상 FN |
| #3 | .48 | 정상 | 정상 TN |
| #4 | .67 | 이상 | 이상 TP |
| #5 | .82 | 이상 | 이상 TP |
| #6 | .94 | 정상 | 이상 FP |

**수식:** `score ≥ threshold → 이상(양성)`. 범위 0.00–1.00, 간격 .05, 초기 .60. `Precision=TP/(TP+FP)`, `Recall=TP/(TP+FN)`이며 일반식과 실제 대입식을 함께 표시합니다. 분모가 0이면 `정의 불가`, 비율은 소수 1자리입니다.

**기본 결과:** TP=2, FP=1, FN=1, TN=2, Precision/Recall=66.7%. 0.70으로 올리면 #4만 TP→FN, 두 지표는 50.0%/33.3%입니다.

**색·강조:** 예측 이상 Blue / 예측 정상 Muted, 정오 판정 TP/TN Teal / FP/FN Amber. 실제 예측이 바뀐 배지만 550ms 강조하며 모션 감소 설정에서는 생략합니다.

**최소 설명·삭제 금지:** 양성=이상, 실제값 그룹, 임계값 기준, 예측 클래스와 유형의 구분, 한 줄 지표 뜻·일반식·대입식, 요약 개수, 마지막 임계값 캡션. 샘플 위치를 매번 재정렬하지 않습니다.

**구현:** [interactive.html](../templates/html/interactive.html), [interactive-reference.js](../templates/html/interactive-reference.js), 공통 CSS. [공유용 단일 HTML](../previews/review/interactive-live.html)은 생성본입니다. **프리뷰:** [JPG](../previews/html-interactive.jpg).

## 06 Architecture

**목적·독자:** CNN의 연산·모듈 경계와 차원 변화를 읽는 독자. **핵심 메시지:** 이 모델의 Conv는 특징 채널을 만들고 Pool은 공간을 줄이며 Flatten 후 분류합니다.

**최종 구조:** Input → Conv Block 1 → Conv Block 2 → Flatten → FC Layer → Softmax.

| 단계 | 연산 | 전후 Shape |
| --- | --- | --- |
| Input | RGB 사진 한 장, batch 생략 | 64×64×3 |
| Block 1 Conv | 3×3, S1, P1, out=16 | 64×64×3 → 64×64×16 |
| Block 1 ReLU | max(0,x) | Shape 유지 |
| Block 1 Pool | MaxPool 2×2 S2 | 64×64×16 → 32×32×16 |
| Block 2 Conv | 3×3, S1, P1, out=32 | 32×32×16 → 32×32×32 |
| Block 2 ReLU | max(0,x) | Shape 유지 |
| Block 2 Pool | MaxPool 2×2 S2 | 32×32×32 → 16×16×32 |
| Flatten | 원소 순서 재배열 | 16×16×32 = 8,192 |
| FC | z=Wx+b, W는 3×8192 | 8,192 → 3 logits |
| Softmax | p_i=exp(z_i)/Σ exp(z_j) | 3 probabilities |

**차원 수식:** `out=floor((n+2p−d(k−1)−1)/s)+1`, dilation d=1. Conv는 H/W를 유지하고 Pool은 두 번 절반으로 줄입니다. 다른 CNN에 이 역할을 보편 규칙으로 강제하지 않습니다.

**확률 예시:** logits `[2,1,0]`의 softmax는 `[0.665240956,0.244728471,0.090030573]`, 표시는 `P(class0)=66.5%`, `P(class1)=24.5%`, `P(class2)=9.0%`, 합 100.0%입니다. 사진에 대한 실제 추론 결과가 아닙니다.

**Figure 요소·배치:** 입력 사진 한 개. 두 Block 내부의 큰 Conv Stack → 작은 Pool Stack. Stack 평면 7개는 채널 수의 축약 표현입니다. Flatten은 Stack → 세로 1D 벡터이며 34개 대표 셀과 생략점으로 8,192차원을 축약합니다. FC는 벡터와 세 노드, Softmax는 클래스별 막대입니다. Feature Extractor/Classifier 범위 선으로 역할을 구분합니다.

**색·화살표·중앙축:** 외부 Blue 5개, 내부 Teal 3개. 각 화살표의 직선·화살촉은 한 path이며 같은 tip 좌표를 씁니다. 실제 Stack bounding box 사이의 간격으로 내부 화살표를 계산합니다. 제목·그림·Shape 중심축은 desktop/tablet에서 2px 이내입니다. 폰트 로딩 후 `getBBox()`로 그림 중심을 다시 맞춥니다. 520px 이하의 왼쪽 그림/오른쪽 텍스트 배치는 의도된 예외입니다.

**최소 설명·삭제 금지:** 모든 출력 Shape, Conv/ReLU/MaxPool 순서, 첫 Block의 역할 설명, Flatten 차원, FC의 logits와 Softmax 확률 구분, 설명용 확률 표기, 단일 사진.

**데이터 단순화:** 맵 패턴은 SVG 구조 설명을 위한 모식도이며 #2·#3 고정 필터 엔진을 사용하지 않습니다. 그려진 작은 격자 수·평면 수를 실제 Tensor 크기로 해석하지 않습니다.

**구현:** [architecture.html](../templates/html/architecture.html)의 SVG 생성 JS·페이지 CSS, 공통 CSS. **프리뷰:** [JPG](../previews/html-architecture.jpg).

**검증:** 독립 차원 계산, 사진 1개·중복 프레임 0, 6단계 순서, 3개 내부/5개 외부 화살표의 연결 좌표, 실제 그림 중심, Flatten=8192, softmax 수치·합, 모든 텍스트 실제 폰트. 상세 기하는 [Figure 표준](FIGURE_PRODUCTION_STANDARD.md)을 참고합니다.

## 07 Experiment

**목적·독자:** 혼동행렬에서 정확도·정밀도·재현율·F1이 어떻게 나오는지 배우는 독자. **핵심 메시지:** 같은 판정 개수를 다른 질문의 분모로 해석합니다.

**구조:** 왼쪽 흰색 Confusion Matrix 카드, 오른쪽 4개 Metrics 카드. 지표별 이름·값·짧은 뜻·일반식·대입식을 묶습니다. FP/FN 설명은 행렬 카드 안에 있습니다.

| 모델 예측 / GT | 실제 이상 | 실제 정상 |
| --- | ---: | ---: |
| 예측 이상 | TP=4 | FP=1 |
| 예측 정상 | FN=2 | TN=5 |

평가 샘플 총 12, 실제 이상 6·정상 6, 양성은 이상입니다. GT는 상단 가로축, 모델 예측은 좌측 세로축이며 **예측 이상이 위 행**입니다.

| 지표 | 식 | 대입 결과 |
| --- | --- | --- |
| Accuracy | (TP+TN)/(TP+TN+FP+FN) | 9/12 = 75.0% |
| Precision | TP/(TP+FP) | 4/5 = 80.0% |
| Recall | TP/(TP+FN) | 4/6 = 66.7% |
| F1 | 2TP/(2TP+FP+FN) | 8/11 = 72.7% |

동치식 `F1=2PR/(P+R)`을 함께 표기합니다. 표시용으로 반올림한 80.0/66.7을 다시 넣어 계산하지 않고 원래 비율에서 반올림합니다.

**색·기하:** TP/TN Teal, FP/FN Amber. 축·행열 라벨·각 셀의 코드와 숫자는 중앙 정렬. GT 아래 가로선, 모델 예측과 행 라벨 사이 중앙의 세로선. 세로선은 실제 텍스트 경계를 Range로 측정하고 zoom·선 두께를 보정합니다.

**최소 설명·삭제 금지:** `FP: 정상인데 이상으로 예측`, `FN: 이상인데 정상으로 예측`, 예시 12개·양성 정의, 모든 수식과 실제 계산 결과. 최초 구상보다 우선하는 최종 축 순서를 유지합니다.

**구현:** [experiment.html](../templates/html/experiment.html)의 HTML 표·inline CSS·세로선 정렬 JS, 공통 CSS. **프리뷰:** [JPG](../previews/html-experiment.jpg).

**검증:** 행렬 합·정답 개수·행열 위치·네 지표와 두 F1 식, 코드/숫자/축 정렬 오차<2px, 세로선 양쪽 간격 차이<0.25px, 카드/푸터·폰트·모바일. [상세 패턴](EXPERIMENT_PATTERN.md).

## 08 Executive Summary

**목적·독자:** 운영 효율의 숫자와 실행 항목을 빠르게 검토하는 독자. **핵심 메시지:** 효율 지표의 변화와 파일럿 확대 시 확인할 위험을 함께 봅니다.

**전체 구조:** 왼쪽 넓은 흰색 카드 안에 3개의 KPI 그룹, 각 그룹은 기존 Blue / 개선안 Teal 세로 막대·실제 수치/단위·지표 이름·변화율입니다. 오른쪽 흰색 카드에는 우선순위 설정 / 파일럿 기준 통일 / 확대 판단의 세 항목입니다.

| KPI | 기존 | 개선안 | 변화율 | 개선안의 정규화 높이 |
| --- | ---: | ---: | ---: | ---: |
| 월간 수동 점검 | 120건 | 80건 | −33.3% | 0.6667 |
| 평균 처리 시간 | 45분/건 | 30분/건 | −33.3% | 0.6667 |
| 월말 미처리 | 20건 | 8건 | −60.0% | 0.4 |

**수식:** `ratio=after/before`, `change=(after−before)/before×100%`. 공통 Y축의 100%는 **각 지표의 기존 값**입니다. 절대 측정 단위가 다른 KPI를 같은 절대값 축으로 그리지 않습니다.

**도형·색·배치:** 기존 막대 3개는 같은 높이·공통 기준선, 개선 막대는 실제 비율 높이입니다. 숫자와 단위는 각각의 막대 바로 위, 지표·감소율은 그룹 아래 중앙에 둡니다. 모바일에서도 KPI 세 그룹을 가로로 유지하되 단위는 숫자 아래로 나눕니다.

**초급자 최소 설명·삭제 금지:** 지표별 기준 100% 문구, 기존/개선안 범례, 원래 수치·단위, 변화율, 효율과 미검출 위험을 함께 확인하는 실행 항목.

**데이터 조건:** 이 숫자는 디자인 예시이며 실측 파일럿 결과가 아닙니다. 현재 main 레이아웃을 보존한 통합입니다. 실제 보고에 재사용할 때 집계 기간·조건·출처·위험 검증과 확대 기준을 확보하며, 미제공 실측값이나 허용 기준을 만들어 넣지 않습니다.

**구현:** [executive-summary.html](../templates/html/executive-summary.html)의 정적 HTML/CSS·data-before/data-after·정규화 ratio, 공통 CSS. **프리뷰:** [JPG](../previews/html-executive-summary.jpg).

**검증:** 3개 KPI의 원래 값·단위·변화율·막대 높이 비율·기준선·Y축 눈금, 그룹 라벨 중앙, 숫자/막대 겹침, 좌우 카드/모바일 순서·폰트.
