# 기술 Figure 제작 표준 · HTML / SVG

이 문서는 PC에서 보는 HTML 웹페이지를 위한 제작 절차이며, 새로운 개념에서도 **정확성·구조·정렬·가독성·재현성**을 같은 수준으로 구현하는 기준입니다. PR #10의 도식 기준을 통합하고 일반화했습니다. #6 CNN은 구체적인 예시이며 모든 자료에 사진·두 Conv Block·3분류를 강제하지 않습니다.

[디자인 시스템](../DESIGN_SYSTEM.md) · [페이지 상세 명세](REFERENCE_PAGE_SPECS.md) · [재사용 워크플로](REFERENCE_REUSE_WORKFLOW.md)

패널·Typography·간격·행렬·지표·그래프·상태와 화면 전환의 실제 수치는 [재사용 컴포넌트 설계 규격](DESIGN_COMPONENT_RECIPES.md)을 확인합니다. 공통 기본값과 예제 전용 값을 구분하고, 새 개념의 설계 기록표에 적용한 값과 예외 이유를 남깁니다.

## 1. 개념과 학습 목표 정의

한 장을 보고 청중이 설명할 수 있어야 하는 한 문장을 정합니다. 제목은 짧은 한국어 명사구·핵심 구문으로 작성합니다. 그림을 그리기 전에 다음 설계 시트를 채웁니다.

새 개념은 [첫 장의 그림·키워드·일반식 → 다음 장의 실제 값·상세 과정](../DESIGN_SYSTEM.md#개념-설명의-기본-순서)으로 나눕니다. 첫 장에서 예시 입력·계수·결과·선택 점을 모두 설명하려 하지 않습니다. 다음 장에서는 같은 기호에 값을 대입하고 중간 결과를 다음 입력에 연결합니다. 수치와 그래프를 함께 설명할 때는 한 계산에서 곡선·교점·양 축 값·투영선을 생성합니다.

| 필드 | 정할 내용 |
| --- | --- |
| 청중·목표 | 선수 지식과 핵심 질문 한 가지 |
| 용어·약어 | 독립 학습 단위, 새 용어의 정식 명칭·짧은 뜻·첫 설명 위치·이후 표기 |
| 입력 | 데이터 유형·차원·단위·실제 자산 경로 |
| 처리 | 연산 순서·파라미터·반복 모듈 |
| 중간 표현 | Shape·정의역·단위·범위 |
| 출력 | 수치·벡터·지도·클래스·확률 중 무엇인가 |
| 관계 | 화살표·묶음·비교 행이 뜻하는 관계 |
| 단순화 | 생략한 채널·모식도·예시 숫자의 조건 |
| 검증 | 독립 계산값·기하 조건·화면 크기 |

실제 수치나 출처가 없으면 학습 성능·운영 개선 실적으로 꾸미지 않습니다. 설명용 예제라는 범위를 명확히 합니다.

## 2. 기술적 정확성 검증

- 식·연산 조건·그림의 숫자를 먼저 검산합니다. 표시용 반올림값을 다음 계산의 입력으로 쓰지 않습니다.
- Conv 출력: `floor((n+2p−d(k−1)−1)/s)+1`. stride·padding·dilation·채널·bias·커널 반전 여부를 확인합니다.
- Softmax: `p_i=exp(z_i−max(z))/Σ exp(z_j−max(z))`. logits와 확률을 구분합니다.
- 분류 지표: 양성 정의와 GT/Prediction 축을 먼저 고정합니다. 분모 0을 임의의 0%로 대체하지 않습니다.
- 비교 그래프: 단위·기간·분모·기준 집단이 같은지 확인합니다. 정규화한 높이와 원래 값의 역할을 분리합니다.
- 독립 검증은 원본 DOM의 입력에서 결과를 다시 계산해야 합니다. 화면의 답을 그대로 복사한 테스트는 근거가 되지 않습니다.

#6의 정확한 계약은 `64×64×3 → 32×32×16 → 16×16×32 → 8,192 → 3 logits → 3 probabilities`입니다. 두 Block 각각 Conv 3×3 S1 P1 → ReLU → MaxPool 2×2 S2입니다. Conv의 중간 출력 64×64×16, 32×32×32도 그림과 대조합니다.

## 3. 입력·처리·출력 관계 설계

청중의 읽는 방향과 원인→결과 방향을 일치시킵니다. 병렬 비교는 같은 입력·기준, 순차 처리는 같은 상태의 전후 변화, 상호작용은 조작값과 바뀌는 결과를 가깝게 둡니다.

- #1: 한 사진 → 실제 채널 분리 → 같은 ROI 확대 → 한 픽셀의 수치. 원본과 확대의 공간 좌표를 유지.
- #2: 입력 → 특징 → Task Head → 결과의 역할 분리.
- #4: 입력 패치 → 9개 곱 → 합 → 출력 위치.
- #5: 임계값 → 샘플 예측 → 행렬 개수 → 지표.
- #6: 반복 특징 추출 Block → Flatten → 분류기.

관계가 없는 도형을 장식 화살표로 연결하지 않습니다. 한 상자에 서로 다른 개념을 과도하게 합치지 않습니다.

## 4. 도형 유형 선택

| 설명 대상 | 권장 표현 | 피할 오해 |
| --- | --- | --- |
| 실제 사례 | 이미지 한 장과 가까운 라벨 | 의미 없는 중복 프레임·그림자 |
| 행렬·국소 계산 | 편집 가능한 셀·강조 영역 | 단순 색 격자를 실제 데이터라고 주장 |
| 다채널 공간 표현 | 대표 Feature Map Stack + 정확한 Shape | 그린 평면 수를 실제 채널 수로 해석 |
| 1D 특징 | 한 열 벡터·셀·생략점 | 다시 2D Feature Map으로 그리기 |
| 클래스 점수 | 분리된 노드·숫자 | logits를 확률로 부르기 |
| 확률·비율 | 동일 기준선 막대·단위·값 | 근거 없는 실제 모델 성능 암시 |
| 조건 비교 | 같은 행·같은 순서의 두 패널 | 한쪽만 다른 측정 조건 사용 |

HTML은 문서·표·입력 UI, SVG는 좌표·도형·화살표, Canvas는 실제 래스터 계산에 사용합니다. 렌더링 이미지를 원본 대신 넣지 않습니다.

## 5. 행렬·Tensor·Feature Map 표현

#1은 같은 사진을 80×80로 리샘플한 R/G/B 채널과 ROI `(52,38,4,4)`를 연결합니다. 8×8 안내선과 실제 80×80 데이터는 다릅니다. 확대 4×4는 16픽셀·48개 채널 값이고 선택 index 6은 로컬 `(2,1)`입니다. 확대 전면의 실제 RGB 합성과 뒤 G/B의 표시 전용 강도 보간을 구분합니다. 표시색으로 원본 RGB·HEX·막대를 역산하지 않습니다. 이 원칙은 다채널 신호나 표의 부분 확대에도 적용하며, 실제 수식은 [#1 명세](REFERENCE_PAGE_SPECS.md#01-concept)를 따릅니다.

#4는 모든 5×5 입력과 3×3 커널·출력 값을 표시합니다. 선택된 3×3은 정확히 9개 셀이며 출력 한 칸과 연결됩니다. H/W/C와 행·열의 순서, 0-based 코드 인덱스와 1-based 화면 좌표를 구분합니다.

#6의 Stack은 대표 평면 7개를 그리지만 실제 채널은 Shape의 16/32입니다. Conv/Pool 공간 크기가 달라지는 것을 면의 크기로 표현하며 Pool에서 채널 수를 줄이지 않습니다. Flatten은 `16×16×32=8192`를 1열 벡터와 생략점으로 표현합니다.

사진에서 실제로 계산한 #2·#3 고정 필터 맵과 #6 구조 모식도를 구분합니다. 전자는 휘도 기반 방향성 필터의 결과이고 후자는 모듈·차원을 설명하는 SVG 패턴입니다. 둘 모두 학습된 모델의 사진 추론이라고 주장하지 않습니다.

## 6. 중앙축과 도형 간격

연결의 단위를 먼저 선택합니다. 역할 카드 전체를 연결하는 #2의 Blue 화살표는 **카드 전체의 수직 중앙**, 실제 도형끼리 연결하는 #6은 **도형의 경계와 중심**이 기준입니다. 측정할 DOM/SVG 요소와 기준축을 명세에 기록하고 둘을 혼용하지 않습니다. #1은 4단계의 하단 라벨·설명 기준선을 맞춘 뒤 축 라벨과 배지를 포함한 각 Figure의 시각 중심을 확인합니다.

제목·실제 Figure·Shape·짧은 설명이 같은 축을 공유하는지 실측합니다. SVG `viewBox`의 가운데와 실제 내용의 가운데는 다를 수 있습니다.

```js
const bounds = artwork.getBBox();
const offset = viewBox.x + viewBox.width / 2 - bounds.x - bounds.width / 2;
artwork.setAttribute('transform', `translate(${offset} 0)`);
```

텍스트가 포함된 그림은 `document.fonts.ready` 후 다시 측정합니다. SVG `<title>` 등 비시각 메타데이터는 경계 계산 대상에서 제외합니다. PC 단계 축 오차는 권장 2px 이내입니다. 의도적으로 다른 축에 배치하는 경우에는 그 이유와 기준을 명세에 기록합니다.

반복 Block 내부 연산은 서로 가깝게, 다른 Stage 사이는 더 넓게 둡니다. 도형 사이 11px 미만의 공간에 화살표를 억지로 집어넣지 않습니다. 카드 안의 요약·각주까지 패딩을 지키고 `overflow:hidden`으로 문제를 감추지 않습니다.

## 7. SVG 화살표와 Bounding Box 계산

**외부 Stage connector**는 Blue, **내부 변환 connector**는 Teal입니다. 색뿐 아니라 블록 제목·공간적 묶음도 역할을 전달합니다.

Stack 평면이 k번째에 `(x+k·dx, y−k·dy)`로 놓이면 전체 경계는 다음과 같습니다.

```text
left = x
right = x + size + (n−1)·dx
top = y − (n−1)·dy
bottom = y + size
centerY = (top + bottom) / 2
```

두 도형 경계를 얻은 뒤 화살표의 시작·끝·중앙을 계산합니다.

```js
const fromX = bboxA.right + 3.5;
const tipX = bboxB.left - 3.5;
const centerY = (bboxA.centerY + bboxB.centerY) / 2;
const d = `M${fromX} ${centerY} H${tipX} ` +
          `M${tipX-5} ${centerY-3.8} L${tipX} ${centerY} ` +
          `L${tipX-5} ${centerY+3.8}`;
```

같은 tip 좌표를 쓰는 **한 path**로 직선과 화살촉을 연결하고 round linecap/linejoin을 사용합니다. 따로 그린 삼각형을 눈대중으로 붙이지 않습니다. 도형과 양 끝 간격은 기준 크기에서 약 3.5px이며 축소 배율에 맞게 유지합니다. #6은 외부 5개·내부 3개를 검증합니다. 다른 도식에 이 개수를 강제하지 않습니다.

## 8. 이미지 사용과 중복 도형 방지

원본 자산을 먼저 확인합니다. #6 입력은 `assets/concept-apple-photo.jpg`를 가리키는 SVG image **한 개**이며 그 위에 같은 사진·사과 실루엣·색 덮개·여러 외곽 rect를 덧그리지 않습니다. RGB 3채널을 사진 세 장으로 표현하지 않습니다.

채널 분리·부분 확대를 설명하는 #1의 파생 Canvas/격자는 의미 있는 변환입니다. 같은 사진을 복제하는 장식과 구분하며, 같은 픽셀 버퍼·좌표에서 나온 값인지 검사합니다. 확대의 원본 위치 표시는 관련 행렬 위에, 확대값 설명은 확대 Figure 가까이에 둡니다. 입력 사진 위에 같은 ROI를 중복 표시해야 하는지는 학습 목표로 판단합니다.

외부 Figure는 가까이에 원문 URL을 둡니다. 자체 도형이라도 실제 측정·모식도·계산 예시의 차이를 설명합니다. 이미지의 크기와 경계가 예측 가능하도록 preserveAspectRatio와 object-fit을 목적에 맞게 지정합니다. 새 사진을 쓰면 파생 픽셀·맵·라벨도 다시 계산합니다.

## 9. 색상 의미와 일관성

[색 토큰 표](../DESIGN_SYSTEM.md)를 사용합니다. 일반 카드 White, 캔버스 Off-white, 핵심 텍스트 Navy, 흐름 Blue, 내부 변환·결론 Teal, 오류·임계값·대조 조건 Amber입니다.

클래스와 정오 판정을 같은 색 의미로 섞지 않습니다. 색만 보지 않아도 문자·위치·묶음으로 이해할 수 있어야 합니다. 정보가 없는 장식 배경, 임의의 단계별 무지개색, 의미 없는 그라디언트를 추가하지 않습니다.

## 10. Typography와 자간

공통 `styles.css`의 로컬 Pretendard Variable을 본문·일반 영문에 사용하며, 새로 만드는 수식·변수·계수는 [수식 전용 규격](../DESIGN_SYSTEM.md#본문과-수식의-서체-분리)의 STIX Two Math/Native MathML로 분리합니다. 전체 텍스트는 −1pt이며 SVG·푸터·입력 UI도 포함합니다. 원본 폰트를 동봉하고 라이선스를 보존합니다. 기존 승인 레퍼런스의 폰트를 일괄 교체하지 않습니다.

CSS family 이름만 확인하지 않습니다. 실제 글리프를 역할별로 검사해 본문 Pretendard와 수학 STIX를 구분합니다. 폰트가 제공하지 않는 도형형 기호는 #4처럼 SVG로 구현할 수 있습니다. 다른 폰트로 몰래 대체하지 않습니다. 자세한 크기·굵기 계층은 디자인 시스템을 따릅니다.

단계 아래 정의도 Figure와 같은 열·중앙을 공유합니다. 개념 장에는 핵심 일반식과 뜻, 상세 장에는 실제 값과 곱·합·결과를 둡니다. 입력 박스는 첫 장의 기호, 다음 장의 변수=값을 각각 한 묶음으로 중앙 정렬하고 충분한 패딩을 둡니다. 상세 장도 개념 장과 같은 단계 순서를 유지하고 위에는 실제 값, 아래에는 해당 그림·식을 둡니다. 한 흐름은 짧은 인접 화살표로 연결합니다. 여러 계산 카드가 필요한 경우의 SVG 선은 `getBoundingClientRect()`와 실제 배율로 정규화한 출력/입력 경계에 연결합니다. 줄바꿈·폰트 로딩·탐색·배율·값 변경 후 다시 측정하고 선의 끝과 화살촉을 같은 좌표로 만듭니다. 아래첨자·분수·지수를 넣은 뒤 실제 높이도 검사합니다.

문장 내부의 행간과 요소 사이 간격은 [공통 행간·간격 기준](../DESIGN_SYSTEM.md#행간과-요소-사이-간격)을 따릅니다. 일반 본문 `--line-height-body:1.45`, 같은 그룹의 라벨/제목/소개 `--gap-related:8px`, 다음 구역 `--gap-section:16px`을 구분합니다. 고정 높이의 행렬·도식은 검증된 픽셀 행간을 유지할 수 있으며, 같은 의미의 라벨은 동일한 기준을 적용합니다.

## 11. 문구 길이와 정보 배치

용어는 [공통 첫 등장 규칙](../DESIGN_SYSTEM.md#용어와-약어의-첫-등장)에 따라 정식 명칭과 짧은 뜻을 먼저 설명하고 이후 약어를 씁니다. 독립 레퍼런스는 각 페이지, 연속 강의는 처음 사용하는 학습 단위를 기준으로 합니다. 제목·Figure의 실제 읽는 순서에서 약어가 설명을 앞서지 않는지 확인합니다. 새 정의가 또 다른 미정의 용어에 의존하지 않도록 풀어 씁니다.

긴 영문명은 제목에 모두 넣지 않고 Figure 앞의 소개·관련 카드 설명에서 연결합니다. 노드에는 이미 정의한 짧은 약어를 사용합니다. 필수 정의를 마지막 캡션·Footer·툴팁·접근성 속성에만 두지 않습니다. 정의가 차지하는 행 높이와 구역 간격도 높이 예산에 포함하며, 같은 콘텐츠의 Scroll/Slide에서 기본 뜻을 공통으로 유지합니다.

설명은 관련 도형 바로 옆이나 아래에 둡니다. Shape → 연산 조건 → 짧은 의미 설명 순서를 우선합니다. 반복되는 Conv/ReLU/Pool 역할은 첫 Block에 설명하고 두 번째에는 차이만 남깁니다.

판정 규칙과 범례, 실제값과 예측처럼 별개의 정보는 충분한 간격·구분선·그룹으로 나눕니다. 한 문장에 붙여 뜻이 섞이지 않게 합니다. 핵심 캡션을 추가하면 콘텐츠의 마지막에 놓고 필수 회색 설명은 관련 카드 안에 포함합니다. 긴 문단·모호한 제작자 메모로 공간을 채우지 않습니다.

제목의 내부 간격을 늘린 뒤에는 소개→첫 단계의 실제 간격도 다시 측정합니다. 고정 Slide는 트랙 높이·구역 간격·패딩의 합을 계산하고, 아래 Figure·표·Footer로 밀림이 이어지지 않도록 바깥 여백을 함께 배분합니다. PC 창 크기별 줄바꿈과 카드 내부 높이를 확인합니다. 간격 하나만 바꾼 CSS 선언으로 검토를 끝내지 않습니다.

## 12. PC 창 크기와 배치

PC 브라우저의 너비와 높이를 함께 고려합니다. Slide는 1440×810 설계 캔버스를 16:9로 축소하고, Scroll은 PC 문서의 자연스러운 세로 흐름을 사용합니다.

- 순차 Figure는 단계 순서와 연결 방향을 유지합니다.
- 비교 Figure는 같은 비교 기준과 입력/결과의 대응을 유지합니다.
- 행렬은 수치·조건·축과 셀 크기의 관계를 유지합니다.
- 수식·단위·범례·화살표·Footer의 잘림과 가로 넘침을 확인합니다.
- 내용이 많으면 도식 분리·추가 슬라이드·Scroll을 검토합니다.

## 13. Chromium 렌더링 검증

```bash
python scripts/check_sources.py
python scripts/validate_references.py
python scripts/check_interactive.py
python scripts/check_documentation.py
```

새 자료의 필수 PC 화면 크기는 1600×950, 1440×810, 1366×768, 1280×720입니다. 실제 소스·사진·로컬 폰트를 로드하며 placeholder 또는 폴백 폰트 프리뷰로 최종본을 대체하지 않습니다.

검사에는 독립 수식, 실제 폰트/CDP, 전역 자간, 도형 중심·화살표 연결, 카드 패딩·푸터·가로 폭·이미지 로드·JS 오류를 포함합니다. 자동 검사 후 PC 캡처를 직접 엽니다. 프리뷰는 source checksum과 함께 기록하고 최신 HTML과 동기화합니다. 현재 저장소의 공통 검증 스크립트는 기존 회귀용 작은 화면 2개도 실행합니다. 이는 새 PC 자료의 필수 제작 범위와 구분합니다.

여러 장이 한 DOM에 남는 뷰어는 반복 폰트 감사 전에 이전 검사 ID를 제거하고 실제 보이는 요소를 측정합니다. 숨겨진 이전 장의 ID가 먼저 선택되면 실제 표시 요소와 다른 글리프 결과를 얻습니다. 제목·수식 외에 내비게이션·폼도 포함하며, `font:inherit`와 자간 상속을 별도로 확인합니다. Scroll 마지막 장은 문서 끝에서 읽기 기준선에 도달하지 못하는 경우도 모드 왕복 검사에 포함합니다. [로지스틱 회귀 검증본](../examples/logistic-regression/README.md)은 문서 우선 제작과 이 경계 검사의 적용 사례입니다.

## 14. 품질 체크리스트

- [ ] 한 줄 목표·청중·입출력·수식·단위·조건을 정했다.
- [ ] 새 용어의 정식 명칭·짧은 뜻이 약어보다 먼저 나오며, 독립 페이지/연속 강의/두 모드의 정의 범위를 확인했다.
