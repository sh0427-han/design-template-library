# 독립 제작 시험 절차

이 폴더의 제공 자료와 TASK.md만 제작 근거로 사용한다. 이전 대화는 제공되지 않는다. 다른 /workspace·/tmp 폴더, 원격 저장소·PR·과거 사례·사용자 피드백은 열람하지 않는다. 공통 문서의 사례 링크가 폴더 밖/미제공 파일을 가리키면 따라가지 말고 차단된 참조로 기록한다. 과거 검증 이력 두 절은 제공본에서 제외했고 INPUT_MANIFEST.json에 출처 해시와 제외 절을 기록했다. 현재 공통 규칙 안에 남은 설명용 예는 공통 규칙의 일부다.

전용 설계 답안은 없다. 공통 Markdown과 기존 8종 원본/프리뷰에서 적합한 패턴을 직접 선택한다. 외부 기술 사실 조회는 허용하지만 디자인 참조는 금지하며 별도 출처로 기록한다. 환경 확인·패키지/Chromium 도구 사용은 가능하다.

1. 구현 전에 examples/rag-architecture/DESIGN.md와 D0.md를 작성하고 Git commit한다. 규칙 출처·선택 판단·미해결/추가 가정·읽은 자료를 기록한다.
2. 예제를 구현하고 실제 Chromium에서 PC4×Scroll/Slide를 확인한다. 자체 수정 가능. 실제 로컬 글꼴/경계/오류/기술 사실과 시각 검토를 기록한다.
3. 구현/검사 스크립트/화면/첫 결과 평가를 커밋하고 FIRST_RESULT.md에 커밋과 파일 근거를 기록하여 Coordinator에게 인계한다. 외부 피드백 전 첫 결과를 별도 보존한다.
4. 입력 자료는 수정하지 않는다. 결과는 examples/rag-architecture 안에만 작성한다. 외부 의존 경로는 ../../templates/html 이하 원본을 사용한다.
5. 읽은 입력 경로, 기술 출처, 질문/가정, 자체 수정, 문서 누락·탐색 실패·구현 오류·주제 판단을 구분한 READ_LOG.md/VALIDATION.md를 작성한다. 픽셀 복제가 아닌 의미·위계·색·정렬·정확성의 재현을 판단한다.

이 폴더는 별도 입력 사본이며 Git에는 결과 폴더만 추적한다. 파일시스템 보안 격리 자체를 입증하는 시험은 아니다. 다른 폴더를 읽었다면 숨기지 말고 보고한다.
