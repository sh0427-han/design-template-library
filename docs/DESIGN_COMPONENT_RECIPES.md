# 재사용 컴포넌트 설계 규격

[디자인 시스템](../DESIGN_SYSTEM.md) · [Figure 제작 표준](FIGURE_PRODUCTION_STANDARD.md) · [페이지별 의미·계산 명세](REFERENCE_PAGE_SPECS.md) · [재사용 순서](REFERENCE_REUSE_WORKFLOW.md)

이 문서는 **다른 개념의 자료를 만들 때 무엇을 선택하고 어떤 수치를 기록할지** 정합니다. 색·폰트·행간·기본 간격은 디자인 시스템, 계산·실제 데이터는 페이지 명세, 좌표 계산 절차는 Figure 표준이 기준입니다. 같은 내용을 여러 문서에서 독립적으로 수정하지 않습니다.

대조 범위는 사용자 검토를 마친 **#1–#8 전체**입니다. #1은 PR #15, #2의 카드 사이 화살표는 PR #18까지 반영한 `main`의 `889cc6e`를 기준으로 실제 Chromium PC 1600×950의 computed style과 원본을 다시 대조했습니다. 캡처 이미지의 픽셀을 눈대중으로 잰 값이 아닙니다. 화면에 따라 변하는 카드 전체 높이를 상수로 복사하지 않습니다. 출처와 현행 검증은 [8종 검토 완료 상태](REFERENCE_RELEASE_STATUS.md)에 모읍니다.

## 1. 규격을 선택하는 방법

| 구분 | 사용 방법 | 예 |

예제 전용 수치를 모두 전역 토큰으로 만들지 않습니다. 새 토큰은 여러 페이지에서 같은 의미로 사용할 때 도입하고, 실제 CSS 정의와 문서의 이름·값을 맞춥니다. 현재 radius·border·화살표·행렬 셀 규격은 일부가 페이지 CSS의 명시적 값입니다. 존재하지 않는 `--radius-card` 같은 변수를 임의로 참조하지 않습니다.

## 3. PC 창 크기와 텍스트 처리

| PC 브라우저 viewport | 확인할 사항 |
| --- | --- |
| 1600×950 | 기준 프리뷰와 1440×810 설계 좌표 |
| 1440×810 | 일반 열람·발표 창의 전체 구성 |
| 1366×768 | 축소된 글자·수식·화살표의 가독성 |
| 1280×720 | 높이 제한, 카드 내부 잘림·Footer·가로 넘침 |

Slide는 PC 창의 너비·높이에 맞춰 16:9 캔버스를 비례 축소합니다. 비교 카드의 좌우 구조, 단계 순서, 입력/결과와 실제 Figure의 기준선을 유지합니다. Scroll은 PC 문서의 자연스러운 세로 스크롤과 필요한 상세 설명을 사용합니다. 내용이 많으면 한 장에 축소해 넣기 전에 도식 분리·추가 슬라이드를 검토합니다.

제목은 한국어 단어 단위 줄바꿈을 허용하고 같은 비교 카드에는 같은 줄 수 공간을 둡니다. 긴 수식은 필요한 경우 항 단위로 나누고, 단위·퍼센트·음수 부호와 결과의 대응을 유지합니다. `white-space:nowrap`은 짧은 기술 라벨·Shape·값에 한정하고 실제 폭을 검사합니다. 모든 문단에 일괄 적용하지 않습니다.

PC 범위 안에서 별도의 열 전환이 필요하면 전환 이유와 전환 전후의 도식·캡션·연결·수식 배치를 명세에 기록합니다. 기존 예제에 포함된 900/650/520px 호환 CSS는 현행 구현 참고이며 새 자료의 필수 설계 조건이 아닙니다.

## 4. 컴포넌트별 설계 계약

### 동일 데이터의 표현과 확대: #1

한 White 패널에서 **전체 입력 → 채널 분리 → 같은 위치의 확대 → 한 원소의 수치**를 연속으로 읽게 합니다. 변환·확대마다 다른 자산을 끼워 넣지 않습니다. 사진 원본 크기, 분석용 리샘플 크기, 화면 표시 크기, 데이터 Shape, 안내 격자의 칸 수를 각각 기록합니다. #1의 8×8 안내선은 실제 채널의 80×80 데이터 크기를 대체하지 않습니다.

현재 PC 구성은 사진 최대 207px 정사각형, 채널 Stack 244×245px 안의 157px 평면 3개, 확대 셀 28px/gap 2px의 4×4 격자(118px), 선택 Swatch 42px, 상세 수치 영역 최대 236px입니다. 채널 평면 R/G/B의 좌상단은 `(15,68)/(42,43)/(69,18)`이며, 확대의 G/B는 전면 대비 `(+16,−16)/(+32,−32)px`입니다. 우상단 배지 15px보다 노출 폭 16px이 커야 뒤 채널의 이름이 가려지지 않습니다. 같은 구조라도 새로운 크기로 옮기면 축 라벨·테두리·선택 강조까지 포함한 경계를 다시 측정합니다.

확대의 전면은 실제 RGB 합성색이고, G/B는 강도 차이를 읽기 위한 채널색 보간입니다. 확대 전면에 쓰인 R 배지를 순수 R 채널의 실측 색이라고 해석하지 않습니다. 원본 데이터와 표시 전용 색상 변환을 분리하고 선택 RGB·HEX·막대·하단 Swatch는 같은 원본 세 값에서 갱신합니다. 구체적인 보간식과 좌표는 [#1 명세](REFERENCE_PAGE_SPECS.md#01-concept)에 있습니다.

H/W는 공간축, C는 채널축입니다. `4×4×3=48개 값`을 48픽셀이나 저장 바이트 수로 바꾸지 않습니다. 확대에서 H/W 글자만으로 충분하면 보조 가이드선을 추가하지 않습니다. ROI 표시·선택 Halo·축·레이어 테두리가 각각 다른 역할을 갖도록 구분합니다. 이 패턴은 센서 채널·주파수 대역·표의 부분 확대에도 사용할 수 있으며 사진·RGB를 필수로 강제하지 않습니다.

### 흐름과 구조: #2·#6

새 개념에서는 입력·처리·중간 표현·출력의 역할을 먼저 정합니다. 바깥 단계 연결은 Blue, 같은 블록 안 변환은 Teal입니다. 화살표의 시작/끝은 도형 경계 기준으로 계산하고 선·화살촉의 tip 좌표를 공유합니다. 선 굵기·도형과의 간격·실제 중앙축 계산은 [Figure 표준 6–7절](FIGURE_PRODUCTION_STANDARD.md#6-중앙축과-도형-간격)을 따릅니다.

먼저 **무엇을 연결하는 화살표인지** 정합니다. #2의 외부 연결은 카드 전체의 역할 흐름이므로 카드 중심에, #6의 연결은 실제 연산 도형 사이이므로 도형 경계와 중심에 맞춥니다. #2 카드 높이 376px의 외부 축은 위에서 188px이며 Figure 중심 146px과 다릅니다. 한쪽 기준을 모든 Figure에 일괄 적용하지 않습니다.

사진은 같은 객체를 설명할 때 한 장을 사용하고, Tensor·Feature Map·1D 벡터·클래스 점수·확률을 다른 모양과 라벨로 구분합니다. 대표 평면 수나 생략 셀은 실제 채널 수가 아닙니다. 다른 개념에 CNN의 사진·두 Block·3분류 구성을 그대로 요구하지 않습니다.

### 대칭 비교: #3

각 카드의 단계·입력·결과·세 비교 행·장점/한계가 대응하는지 먼저 표로 정합니다. 두 카드 폭·높이뿐 아니라 그림의 실제 경계·입력 크기/기준선·결과 위치·분리선·본문 시작 X좌표를 맞춥니다. Figure는 과정, 아래 행은 차이 요약을 담당합니다.

준비한 판단 체계와 실제 적용을 분리하는 패턴은 학습/추론 외에도 설정/실행, 구축/사용, 측정/판정 등으로 재사용할 수 있습니다. 같은 비교 기준과 입력 조건을 유지하며 어느 한 카드 전체의 강조색으로 우열을 암시하지 않습니다.

### 행렬·계산: #4·#7

행렬은 같은 행·열을 같은 크기로, 셀 숫자는 양축 중앙에 둡니다. #4의 desktop 입력 셀 38px, 커널 46px, 출력 44px은 데이터 역할별 값입니다. 선택 영역은 Blue 경계/작은 면, 커널은 Teal 면, 선택된 출력은 Navy/White를 사용합니다. 입력 영역→수식→출력 위치의 대응을 유지합니다.

분류 행렬의 축 제목·행/열 라벨·셀 코드를 별도 요소로 둡니다. #7은 GT 가로축 실제 이상/정상, 모델 예측 세로축 이상/정상이며 TP FP / FN TN입니다. 셀 100px 높이/radius 12px, 코드 19px와 개수 44px을 구분합니다. #5는 같은 의미의 작은 행렬로 56px/radius 9px을 사용합니다. 다른 문제로 옮길 때 양성 정의와 행·열 계약부터 새로 정합니다.

축 구분선은 카드의 임의 비율이 아니라 실제 텍스트와 라벨 구역 사이 중앙에 둡니다. #7의 세로선은 `Range.getBoundingClientRect()`와 zoom/선 두께로 보정합니다. 구체적인 식과 허용 오차는 [Experiment 패턴](EXPERIMENT_PATTERN.md#6-축라벨구분선의-정렬)을 따릅니다.

### 지표와 수식: #5·#7

이름·값 → 짧은 뜻 → 일반식 → 대입 결과를 하나의 지표 안에서 읽게 합니다. #7의 작은 지표는 radius 12px/padding 10px 14px, #5는 radius 10px/padding 8px 12px입니다. 값의 크기와 식의 크기를 구분하고 분수·긴 동치식의 높이를 미리 확보합니다. 문장 한 줄을 추가하면 아래 대입식·다른 카드의 바닥까지 측정합니다.

일반식에서 쓰는 개수와 표시한 행렬 값은 같은 데이터에서 나와야 합니다. 계산은 원래 정밀도로 수행하고 표시할 때만 반올림합니다. 분모 0은 `정의 불가`로 표시합니다. 기존 HTML 분수·SVG·텍스트는 편집 가능하게 보존하며, 새 수식은 [수학 Typography](../DESIGN_SYSTEM.md#본문과-수식의-서체-분리)의 STIX Two Math/Native MathML을 사용합니다. 일반 영문과 수학량을 구분하고 글꼴·첨자·분수의 실제 경계를 검사합니다.

개념 장은 입력·핵심 식·결과의 역할을 보여주고, 상세 계산 장은 각 곱의 기호→대입→결과·합산을 펼칩니다. 첫 장에 일반식·계수 목록·대입·합산을 모두 중복해 넣지 않습니다. 짧은 뜻은 같은 패널의 하단 설명으로 분리할 수 있습니다. 입력 값이 단독 박스라면 식을 한 묶음으로 중앙에 두고 안쪽 패딩을 확보합니다. 아래 정의는 Figure와 같은 열·중앙축을 공유합니다. [로지스틱 회귀의 1장 설계](../examples/logistic-regression/DESIGN.md#01-figure의-구성과-좌표)가 예입니다.

확률식과 그래프를 나란히 두면 동일 계산의 점·두 축 값·투영선을 실제 함수 좌표에서 생성합니다. 축 값 표시는 반올림할 수 있지만 점 위치는 원래 값이며, 선택 라벨과 가까운 기본 눈금은 겹치지 않게 합니다. 그래프를 넣기 위해 필요한 공간은 카드 비율과 내부 열로 배분하고 식·숫자를 과도하게 줄이지 않습니다.

### 조작과 상태: #5

실제값·샘플 식별자·입력 데이터는 고정한 채 조작값과 달라지는 예측·집계·수식을 연결합니다. 판정 규칙과 범례, 예측 클래스와 정오 유형을 구분합니다. 값이 바뀔 때 DOM 여러 곳이 서로 다른 계산 결과를 쓰지 않도록 하나의 계산 경로에서 갱신합니다.

기본 상태·중간 상태·경계값·분모 0·다른 데이터 구성을 명세에 기록합니다. 키보드·포인터 입력과 모션 감소 설정을 함께 검사합니다. 현재 구현 계약은 [Interactive 패턴](INTERACTIVE_PATTERN.md)에 있습니다.

### 그래프와 실행 항목: #8

축의 단위·분모·기준값·정규화 방식을 먼저 정합니다. 서로 다른 원래 단위를 가진 KPI를 함께 그릴 때는 각 기준값을 100%로 정규화하고 원래 값/단위도 표시합니다. 동일 단위와 같은 측정 조건의 비교라면 그 조건을 먼저 명시합니다.

#8의 PC bar는 52px 폭/radius 위쪽 5px입니다. plot 높이와 값 공간을 분리하며 숫자와 단위를 막대 위에 둡니다. 기존 Blue/개선안 Teal 범례, 기준선과 0/50/100% 눈금, 지표 이름·변화율을 보존합니다. 기간·출처·실측/예시 조건이 바뀌면 그래프 설명도 바꿉니다. 오른쪽 실행 항목은 3행·구분선 1px·padding 위아래 24px로 같은 위계를 유지합니다.

### 마지막 핵심 캡션

공통 `.ref-takeaway`는 White 배경, Teal 왼쪽 선 4px, radius `0 10px 10px 0`, padding 12px 17px, 위 margin 14px입니다. 짧은 핵심어와 설명 사이 gap 15px, 글자 19px/1.45입니다. #5는 padding 10px 16px/20px 글자로 검증된 변형입니다.

핵심 캡션은 Content의 마지막, Footer 앞에 둡니다. 아래에 회색 설명을 흘리지 않고 필수 조건은 관련 카드에 포함합니다. PC에서도 설명이 길면 핵심어·설명·캡션의 실제 높이를 함께 검토합니다. 모든 패턴에 형식적으로 추가하는 요소는 아닙니다.

## 5. 상태와 실패 표현

| 상태 | 표시 계약 | 현재 참고 구현 |
| --- | --- | --- |
| 픽셀 계산 대기/실패 | RGB·HEX를 성공값처럼 남기지 않고 중립 Swatch·0% 막대·오류 상태 사용 | #1 `data-sampled` 상태 |
| 계산 대기 | 준비 중인 그림/값의 의미를 구분하고 아직 성공으로 표시하지 않음 | #2 Feature pending, #3 layout/maps loading |
| 정상 | 실제 계산과 표시가 모두 성공한 경우 파생 그림·값 표시 | #2/#3 fixed-filter 결과 |
| JS/엔진/Canvas 실패 | 안내나 편집 가능한 정적 역할 도식을 사용하고 계산 결과라고 주장하지 않음 | #2 안내, #3 정적 CNN 기호/안내 |
| 사진 실패 | 빈 영역만 남기지 않고 해당 입력을 읽지 못했다는 안내 | #2 photo fallback |
| 수학적 정의 불가 | 0%로 꾸미지 않고 뜻과 함께 `정의 불가` | #5 지표 분모 0 |
| 폰트 실패 | 기술 검증 실패로 처리하고 최종 프리뷰 갱신 중단 | 실제 글리프 검사 |

정적 설명용 결과는 계산 성공 여부와 별개의 예시입니다. 고정 필터 맵·실제 학습 활성화·수동 모식도·예시 확률을 명세와 그림 가까운 최소 라벨로 구분합니다. 지금 구현하지 않은 학습·추론·측정이 수행된 것처럼 표시하지 않습니다.

접근성은 네이티브 조작, 명확한 이름/값, 의미 있는 이미지 설명, 색 외의 문자/위치, 키보드 focus를 포함합니다. #5의 상태 알림은 전체 카드에 `aria-live`를 주는 대신 전용 status를 사용합니다. 실제 스크린리더 청취 평가나 모든 색 조합의 대비 평가를 수행했다고 확대 해석하지 않습니다.
