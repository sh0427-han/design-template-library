# 8종 레퍼런스·Markdown 재사용 검증 프롬프트

목표는 **로지스틱 회귀 검토의 교훈을 반영한 공통 Markdown과 기존8종을 새 개념에 다시 적용해 템플릿을 검증하는 것**입니다. 새 자료는 검증 산출물입니다. 로지스틱 회귀를 새로운 기준 템플릿으로 복제하는 작업과 구분합니다. 절차·첫 사례의 교훈·분류/판정은 [검증 기준](TEMPLATE_REUSE_VALIDATION.md)을 따릅니다.

프롬프트에서 서식의 정답을 모두 미리 주지 않습니다. 제작자가 공통 Markdown과8종에서 규칙을 찾고 출처·누락을 기록해야 문서의 재현 가능성을 확인할 수 있습니다. 기준 브랜치는 이 문서와 최신 공통 규격이 실제로 존재하는 브랜치를 선택합니다.

```text
Repository: sh0427-han/design-template-library
기준 브랜치: [교훈이 반영된 최신 공통 Markdown과8종이 포함된 브랜치]
검증할 새 개념: [로지스틱 회귀와 다른 개념]
대상 독자: [기본: 해당 개념을 처음 배우는 초급자]
이번 분량: 개념 설명 한 장
작업 경로: examples/[새-개념-slug]/

목표는 기존8종 레퍼런스와 공통 Markdown만으로 새 개념의 자료를
동일한 품질로 제작할 수 있는지 검증하는 것이다.
새 슬라이드는 검증 산출물이고, 문서의 충분성과 누락을 함께 판정해줘.

1. AGENTS.md, DESIGN_SYSTEM.md, TEMPLATE_CATALOG.md와
   docs/TEMPLATE_REUSE_VALIDATION.md를 먼저 읽어줘.
   docs/DESIGN_COMPONENT_RECIPES.md, FIGURE_PRODUCTION_STANDARD.md,
   REFERENCE_PAGE_SPECS.md, REFERENCE_REUSE_WORKFLOW.md,
   REFERENCE_REVIEW_GUIDE.md도 확인해줘.
   시작 Commit과 읽은 자료 버전을 VALIDATION.md에 D0로 기록해줘.

2. 8종 모두의 용도·명세·최신 프리뷰를 검토하고,
   이 개념에 적합한 패턴과 선택 이유를 정해줘.
   선택한 원본 HTML/CSS/SVG/JS를 확인하고 재구성해줘.
   로지스틱 회귀는 첫 검증 사례이며 새 제작의 원본 템플릿이 아니야.
   그 소스를 복제하거나 이전 대화의 기억으로 디자인 규칙을 보충하지 마.
   교훈은 이미 공통 Markdown에 반영됐으므로 그 문서를 기준으로 해줘.

3. 구현 전에 DESIGN.md를 작성해줘.
   목표·독자·용어/기호·일반 관계·Figure 구조·서식·크기/간격·정렬·
   화살표·높이 예산·검증 계획을 정하고 중요한 결정의 출처 파일/절을 적어줘.
   서식값은 이 프롬프트가 아닌 공통 Markdown과8종에서 찾아 적용해줘.
   개념 고유의 새로운 설계는 이유와 조건을 별도로 기록해줘.
   공통 제목/분류 라벨 규칙의 적용 단위와 각 단위 소유 라벨·제목의
   선택자/개수·읽는 순서를 명세에 남겨줘. 페이지 Kicker로 대신하지 마.

4. 문서만으로 결정할 수 없거나 서로 모순되는 항목을 발견하면,
   보완하기 전에 VALIDATION.md에 문제와 근거를 기록해줘.
   문서에 명시된 규칙, 구현에서만 확인된 규칙, 개념 고유 설계,
   문서 누락/모순, 구현 오류를 구분해줘.
   완성 화면을 좋게 만든 뒤 원래 문서가 충분했다고 소급해서 판정하지 마.

5. 이번에는 그림·키워드·일반 관계 중심의 개념 한 장을 만들어줘.
   같은 원본을 Scroll/Slide 두 HTML로 제공하고 계산 장·실습·부록은 추가하지 마.
   단계 수·도형·수식은 새 개념에 맞게 정하고 로지스틱 회귀의 구조를 강제하지 마.
   원본8종·공통 구현·기존 검증 산출물은 보존해줘.

6. 공통 검증 기준에 따라 새 주제 자체를 실제 Chromium으로 렌더링해줘.
   PC1600×950/1440×810/1366×768/1280×720의 두 모드를 확인하고,
   독립 기술/수학 검산·실제 글리프·DOM/SVG 경계·콘솔/요청 오류를 검사해줘.
   캡처를 직접 검토해 수정하고 재검증해줘.
   기존8종의 회귀 통과와 새 주제의 재사용 성공은 별도로 기록해줘.

7. 발견한 공통 누락은 해당 Markdown에 반영하고,
   개념 전용 수치는 새 DESIGN.md에만 기록해줘.
   보완 후 버전을 D1로 남기고 명세·소스·프리뷰·검증 기록을 일치시켜줘.
   VALIDATION.md에는 D0에서 재현된 부분, 보완이 필요했던 부분,
   D1의 최종 결과, 미검증 패턴/규칙과 남은 문제를 구분해줘.
   새 한 장의 성공으로8종 전부가 검증됐다고 보고하지 마.

8. 새 브랜치에 Commit/Push하고 기준 브랜치를 base로 PR을 생성해줘.
   main에는 Merge하지 마.
   최종 보고는 새 자료와 함께 템플릿/Markdown의 검증 결과를 중심으로 작성해줘.
   사용한 패턴·문서 누락/수정·고유 설계·실제 검증·미검증 항목을 보고하고,
   접근 가능한 실제 Preview를 채팅에 표시해줘.
```

이번 분량은 직전 사용자 범위에 맞춘 개념 한 장입니다. 다른 라운드에서 비교·계산·상호작용 등 다른 패턴을 검증하려면 목표와 분량을 명시해 바꿉니다. 모든 라운드에 한 장이나8종 전부를 강제하는 공통 규칙은 아닙니다.

위 템플릿의 기본 병합 보류와 별개로, 실제 세션에 사용자의 명시적 Merge 승인이 있으면 최종 검증 후 그 승인 범위에서 진행합니다. 사용자 시각 승인·문서 충분성·자동 검사·병합 결과는 각각 기록합니다.
