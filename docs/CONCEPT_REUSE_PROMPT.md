# 다른 개념의 한 장 제작 프롬프트

[공통 디자인](../DESIGN_SYSTEM.md)과 [현재 한 장의 명세](../examples/logistic-regression/DESIGN.md)를 다른 개념에 적용하는 복사 가능한 요청문입니다. 입력란을 바꾸어 사용합니다. 기준 브랜치는 이 문서와 최신 명세가 실제로 존재하는 브랜치를 선택합니다. 상세 계산이나 여러 장의 강의가 필요하면 별도 작업으로 요청합니다.

```text
Repository: sh0427-han/design-template-library
기준 브랜치: [아래 Markdown이 모두 포함된 브랜치]
새 개념: [개념 이름]
대상 독자: [기본: 해당 개념을 처음 배우는 초급자]
핵심 메시지: [한 장을 보고 이해해야 할 관계 한 문장]
새 작업 경로: examples/[새-개념-slug]/

목표는 Markdown과 검토된 레퍼런스를 사용해 새 개념을 설명하는
편집 가능한 개념 슬라이드 한 장을 제작하는 것이다.
Scroll/Slide 두 HTML은 같은 한 장을 표시한다.
다음 작업을 설계부터 구현·검증·PR까지 완료해줘.

1. 먼저 읽을 문서
- AGENTS.md, DESIGN_SYSTEM.md, TEMPLATE_CATALOG.md
- docs/DESIGN_COMPONENT_RECIPES.md
- docs/FIGURE_PRODUCTION_STANDARD.md
- docs/REFERENCE_PAGE_SPECS.md
- docs/REFERENCE_REUSE_WORKFLOW.md
- examples/logistic-regression/DESIGN.md와 README.md
그다음 개념에 적합한 8종 레퍼런스의 HTML과 최신 Preview,
로지스틱 회귀 #1의 실제 HTML/CSS/JS를 확인해.

2. 먼저 새 경로의 DESIGN.md에 학습 목표·선수 지식·용어/기호,
일반식/조건·입력/출력·Figure 구조·색의 의미·Typography,
열 비율/크기/간격/중앙축·화살표·높이 예산·검증 항목을 작성해.
공통값은 출처를 링크하고, 이 개념만의 수치는 구체적으로 적어.
Markdown만 읽어도 그림과 식을 재구성할 수 있어야 해.

3. 한 장은 그림·중요한 키워드·정확한 일반 관계에 집중해.
용어는 정식 명칭과 짧은 뜻을 먼저 설명한 뒤 약어를 사용해.
변수 뜻은 대응 Figure와 같은 열/중앙축의 하단 설명에 배치해.
예시 수치 대입·상세 계산·실습·부록·두 번째 장은 추가하지 마.
정의에 필요한 상수/축 눈금과 예시 계산값은 구분해.
일반식을 줄이느라 필수 항이나 조건을 생략하지 마.

4. 레퍼런스의 완성도와 정보 위계를 재사용하되,
로지스틱 회귀의 네 단계·변수·시그모이드를 강제로 복제하지 마.
이 개념의 의미에 맞는 그림·단계 수·관계 구조를 설계해.
짧은 화살표와 명확한 중앙축을 사용하고 긴 우회 선을 피해야 해.
스크린샷을 그림 대신 붙이지 말고 HTML/CSS/SVG/JS로 편집 가능하게 구현해.

5. PC 웹페이지, 1440×810의 16:9 프레임을 기준으로 해.
본문/일반 영문은 실제 로컬 Pretendard Variable,
변수·계수·수식·수학 축은 실제 로컬 STIX Two Math/MathML,
전체 자간은 -1pt, 색상은 Navy/Blue/Teal을 유지해.
행간과 요소 사이 간격을 구분하고 공통 8/16/24px 기준을 참조해.
White 카드 안의 패딩·글자 잘림·정렬·분수/첨자를 확인해.
Teal 핵심 캡션은 마지막 콘텐츠로 Footer 직전에 배치해.
회색 보조 설명은 관련 카드 안에 포함해.

6. PC 1600×950, 1440×810, 1366×768, 1280×720에서
새 자료 자체를 Chromium/Playwright로 렌더링하고 캡처를 직접 검토해.
독립 계산으로 수식/그래프를 검산하고 실제 DOM/SVG 경계를 측정해.
document.fonts와 실제 글리프 검사로 두 서체와 -1pt를 검증해.
Scroll/Slide 내용·서식 일치, 그림 로드, 가로 넘침, Footer 겹침,
JS/요청 오류와 한 장 탐색을 확인하고 문제를 수정한 뒤 재검증해.
기존 예제의 통과 기록을 새 자료의 검증으로 대신하지 마.

7. 최종 구현에 맞춰 DESIGN.md, README, 카탈로그, 실제 Preview와
검증 기록을 동기화해. 공통 문서는 새 재사용 기준이 생길 때만 보완해.
원본 8종과 로지스틱 회귀 기준선, 다른 작업 브랜치는 보존해.
계산/부록 전용 코드와 일회성 파일을 새 자료에 남기지 마.

8. 새 작업 브랜치에 Commit/Push하고 PR을 생성하되 main에 Merge하지 마.
최종 보고에는 학습 목표, 선택한 구조의 이유, 문서 보완점,
실제 검증 결과, 새 Preview와 PR 링크를 적어.
최종 Preview는 접근 가능한 Commit 고정 HTTPS 이미지 주소를 검증한 뒤
채팅 본문에 Markdown 이미지로 보여줘. 로컬 경로만 전달하지 마.
```

이 프롬프트는 제작할 주제나 Figure 구조를 미리 확정하지 않습니다. 새 개념의 의미에 맞는 구조를 설계하는 능력과 Markdown의 재현 가능성을 함께 검토합니다. 같은 제작자의 후속 작업과 별도 제작자의 독립 재현 결과는 구분해 기록합니다.
