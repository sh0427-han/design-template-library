## 1. 목적과 패턴 선택

핵심은 **같은 예측 결과를 오류 유형과 평가 지표로 연결해 읽는 것**이다. 왼쪽은 실제/예측 조합별 개수, 오른쪽은 그 개수에서 유도한 네 지표다. 숫자와 그림을 장식적으로 나열하지 않는다.

- 고정된 평가 결과를 설명하거나 보고할 때 Experiment를 선택한다.
- 임계값을 조작해 판정과 지표가 달라지는 모습을 보여줄 때는 Interactive가 적합하다. 그 경우에도 여기의 축·의미·계산 계약은 함께 적용한다.
- 모델 구조나 데이터 처리 순서를 설명하는 Architecture/Process와 구별한다. 혼동행렬에는 처리 흐름 화살표를 붙이지 않는다.

## 3. 축과 셀의 고정 계약

이번 라이브러리에서 승인한 이진 혼동행렬의 표시 순서는 다음과 같다. 다른 문헌의 관례를 자동 적용해 뒤집지 않는다.

| 모델 예측 / GT(실제값) | 실제 이상 — 양성 | 실제 정상 — 음성 |
| --- | ---: | ---: |
| **예측 이상 — 양성** | **TP = 4** | **FP = 1** |
| **예측 정상 — 음성** | **FN = 2** | **TN = 5** |

- 상단 가로축 제목: `GT (실제값)`.
- 열: 왼쪽 실제 이상, 오른쪽 실제 정상.
- 좌측 세로축 제목: `모델 예측`.
- 행: 위쪽 예측 이상, 아래쪽 예측 정상.
- 읽기 순서: **TP → FP / FN → TN**.
- GT가 실제 이상인 왼쪽 열 합 `TP+FN=6`, 실제 정상인 오른쪽 열 합 `FP+TN=6`, 전체 합 12.
- 예측 이상인 위 행 합 `TP+FP=5`, 예측 정상인 아래 행 합 `FN+TN=7`.
- 레이아웃을 바꾸면 셀 이름만 옮기지 말고 열/행 라벨, 접근성 headers, 설명, 검증도 함께 바꾼다.

행렬 아래에는 다음 두 문구를 둔다.

- `FP: 정상인데 이상으로 예측`
- `FN: 이상인데 정상으로 예측`

Positive를 좋은 결과, Negative를 나쁜 결과라는 의미로 표현하지 않는다. 여기서는 이상이 Positive이며 TP/TN 모두 정분류다.

## 4. 구조와 정보 위계

### 두 개의 큰 흰색 카드

- 왼쪽: `CONFUSION MATRIX` → `혼동행렬` → 예시/양성/표본 분포 → 축과 2×2 표 → FP/FN 의미.
- 오른쪽: `METRICS` → `같은 데이터의 네 가지 평가 지표` → 지표 네 개.
- `EXAMPLE`을 카드 유형 제목으로 쓰지 않는다. 예시임을 알리는 정보는 표본 조건 문장에 포함한다.
- 두 카드의 위·아래 경계를 일치시키되, 빈 문단이나 장식 요소로 공간을 채우지 않는다.
- 1440×810 캔버스 기준 콘텐츠 그리드는 약 `.94fr : 1.16fr`, 간격 20px다. 숫자가 아니라 읽기 밀도와 균형이 목적이므로 새 내용에 맞게 재조정할 수 있다.
- 카드 안에 제목, 조건, 수식, 설명을 넣는다. 카드 밖에 회색 설명을 늘리지 않는다. 강조 캡션을 추가하는 작업에서는 콘텐츠 맨 마지막에 두고 그 아래에는 식별 푸터만 둔다.

### 오른쪽 지표 하나의 구성

각 지표는 **이름·핵심 수치 → 짧은 해석 → 분수식 → 실제 대입 결과**를 한 묶음으로 배치한다. 이름과 값은 한 줄, 짧은 해석은 그 아래에 둔다. 수식 목록을 카드 하단에 따로 떼어 청중이 대응 관계를 찾아야 하는 구성을 피한다.

| 이름 | 이름 아래 짧은 설명 | 핵심 수치 |
| --- | --- | ---: |
| Accuracy | 전체 샘플 중 맞힌 비율 | 75.0% |
| Precision | 이상 예측 중 실제 이상 비율 | 80.0% |
| Recall | 실제 이상 중 찾아낸 비율 | 66.7% |
| F1-score | 정밀도·재현율의 조화평균 | 72.7% |

설명을 더 줄일 때도 분모의 의미는 유지한다. Precision과 Recall을 모두 ‘맞힌 비율’이라고만 적지 않는다.

## 5. 수식과 대입값

```text
Accuracy  = (TP + TN) / (TP + TN + FP + FN)
          = 9/12 = 75.0%

Precision = TP / (TP + FP)
          = 4/5 = 80.0%

Recall    = TP / (TP + FN)
          = 4/6 = 66.7%

F1        = 2 × Precision × Recall / (Precision + Recall)
          = 2TP / (2TP + FP + FN)
          = 8/11 = 72.7%
```

- 실제 화면에서는 분자와 분모를 선으로 구분한 HTML 분수로 표현한다. 수식의 접근성 이름에는 `/`와 괄호를 사용해 같은 의미를 제공한다.
- F1에는 조화평균식과 개수 기반 동치식을 모두 보인다. `F1=72.7%`만 제시하지 않는다.
- 계산은 반올림 전의 분수로 수행하고, 표시할 때만 소수 첫째 자리까지 반올림한다. 표시된 66.7%를 다시 입력으로 삼아 F1을 계산하지 않는다.
- 새 데이터에서 분모가 0이면 그 지표의 수학적 정의와 처리 규칙을 먼저 정한다. `0%`와 `정의 불가`를 임의로 혼용하지 않는다.
- JS/다중 클래스 등으로 확장하면 confusion counts를 단일 데이터 정의로 두고 표와 지표를 함께 유도한다. 현재 고정 예시도 검증에서 DOM 셀 개수로부터 모든 지표를 독립 계산한다.

## 6. 축·라벨·구분선의 정렬

### 중심 정렬

- GT 제목 중심은 두 실제값 열 전체의 중심과 일치한다.
- 모델 예측 제목 중심은 두 예측 행 전체의 세로 중심과 일치한다.
- 열 라벨과 해당 열의 셀 중심, 행 라벨과 해당 행의 셀 중심을 맞춘다.
- 셀 안 코드(TP 등)와 개수는 각각 가로 중앙, 두 요소의 묶음은 셀 세로 중앙에 둔다.
- 의미 있는 표 구조를 실제 HTML `table`, `th scope`, 셀 `headers`로 보존한다. 위치만 맞춘 일반 div 격자로 접근성 의미를 잃지 않는다.

### GT 아래의 가로선

GT 제목 아래에서 두 데이터 열의 너비를 가로지르는 얇은 선을 둔다. 실제 이상/정상 라벨과 제목을 분리하는 선이며, 글자 밑줄처럼 제목 너비에만 맞추지 않는다.

### 모델 예측 오른쪽의 세로선

**셀 오른쪽 border에 붙이지 않는다.** 승인 기준은 ‘모델 예측’ 글자의 오른쪽 경계와 ‘예측 이상/예측 정상’ 글자의 왼쪽 경계 사이의 정확한 중앙이다.

```text
A = 모델 예측 텍스트의 실제 right
B = 두 행 라벨 텍스트 left 중 작은 값
선의 중심 X = (A + B) / 2
```

- `Range.getBoundingClientRect()`로 실제 텍스트 노드 경계를 측정한다. 셀 폭이나 글자 수로 위치를 추정하지 않는다.
- 줄바꿈된 ‘모델 / 예측’은 각 텍스트 노드의 경계를 합쳐 측정한다.
- 선을 `confusion-figure`의 독립 장식 요소로 둬 표 셀의 크기나 스크롤 폭을 바꾸지 않는다.
- 뷰포트에 따른 CSS zoom을 보정해 좌표를 로컬 CSS pixel로 변환하고, 선 자체 두께의 절반을 빼서 **선의 중심**을 목표에 맞춘다.
- 선 높이는 두 예측 행을 합친 축 제목 셀의 높이와 일치시킨다.
- `document.fonts.ready` 후 배치하고, ResizeObserver와 창 크기 변경 시 재계산한다.
- 검증 시 선 중심에서 좌우 텍스트 경계까지의 거리 차이를 0.25 화면 px 미만으로 제한한다. 승인본의 6개 화면에서는 최대 0.03125px였다.

## 7. 스타일과 반응형

- Pretendard Variable 및 모든 텍스트의 자간 `-1pt`는 공유 styles.css에서 상속한다. 제목·표·수식에 별도 자간을 주지 않는다.
- 캔버스 Off-white, 카드 White, 핵심 텍스트 Navy, 축·계산 강조 Blue.
- TP/TN 셀은 Pale Teal, FP/FN 셀은 Pale Amber. 코드/개수/라벨로 의미를 전달해 색에만 의존하지 않는다.
- 데스크톱 출발값: 제목 49px, 카드 제목 25px, 축·라벨 18–21px, 셀 개수 44px, 지표 수치 30px, 수식 18px, 지표 설명 16.5px. 작은 화면에서 단순 전체 축소만으로 가독성을 해결하지 않는다.
- #7 스타일은 HTML 안 `.experiment-slide` 범위에 한정한다. 다른 슬라이드나 공유 CSS의 결과를 바꾸지 않는다.
- 900px 이하는 큰 카드를 위아래로, 520px 이하는 네 지표도 한 열로 재배치한다. 혼동행렬의 2×2 의미와 행·열 순서는 유지한다.
- 긴 Accuracy 분모는 분수로 표시하고, F1 조화평균식은 의미 단위에서 줄바꿈한다. 식이 잘리도록 font-size를 과도하게 줄이지 않는다.

## 8. 실제 검증과 프리뷰 갱신

```sh
python scripts/validate_references.py --templates experiment --report /tmp/experiment-validation.json
```

필요 환경은 Python, Playwright, Chromium이다. 공식 폰트는 저장소에 포함되어 외부 다운로드가 필요하지 않다. 기본 시스템 Chromium을 사용하고 필요하면 `CHROMIUM_EXECUTABLE`로 지정한다.

검사 화면:

```text
1600×950 · 1440×810 · 1366×768 · 1280×720 · 900×900 · 390×844
```

필수 검사:

- [ ] 축: GT 열 이상→정상, 예측 행 이상→정상
- [ ] 셀: TP4 / FP1, FN2 / TN5와 행·열 접근성 연결
- [ ] 총 12개, 실제 정상/이상 각 6개, 양성 이상 유지
- [ ] 개수에서 독립 계산한 네 분수·퍼센트와 화면 수식 일치
- [ ] F1 두 공식 일치, 지표별 짧은 설명 존재
- [ ] 색상과 코드 의미 일치
- [ ] 축·행·열·셀 중심 오차 2px 미만
- [ ] 세로선 좌우 글자 간격 차이 0.25px 미만
- [ ] 카드·수식·글자 잘림 없음, 푸터 겹침 없음
- [ ] PC 4개 크기에서 가로 넘침 없음
- [ ] 실제 Pretendard 로딩 및 전체 -1pt 확인
- [ ] 실제 스크린샷을 직접 보고 밀도·균형·가독성 재검토

부분 명령은 공통 검사를 실행해 대표 JPEG와 지정한 임시 JSON을 갱신하고, 6개 PNG를 기본 `/tmp/reference-integration-review/`에 저장한다. 실패 시 이전 통과 결과를 재사용하지 않도록 JSON 상태를 running/failed/passed로 구분한다.

통합 후 공통 CSS가 동봉된 Pretendard Variable WOFF2를 직접 로드한다. `document.fonts`와 CDP의 실제 렌더링 글꼴을 함께 검사하며 한글·영문·숫자·수식이 Pretendard로 표시되는지 확인한다. 이전의 CDN 응답 주입은 사용하지 않고 인증서 신뢰 설정도 변경하지 않는다. 상세 기록은 공통 검증의 각 experiment case에 수치·정렬·폰트 정보를 함께 보존한다.

## 9. 다른 주제로 재사용하는 절차

1. 목적, 양성 클래스, 실제 표본 분포, TP/FP/FN/TN을 설계 시트에 적는다.
2. 승인된 축 순서와 셀 의미를 유지하며 표를 채운다.
3. 각 지표의 분모가 어떤 집합인지 한 줄 설명을 먼저 작성한다.
4. 개수에서 수식과 표시값을 계산하고, 반올림 전 분수로 독립 검산한다.
5. 표와 지표를 두 카드로 구성하고 실제 텍스트 경계로 구분선을 배치한다.
6. PC 4개 크기(1600×950/1440×810/1366×768/1280×720)를 렌더링해 자동 검사와 직접 시각 검토를 모두 수행한다.
7. HTML·프리뷰·카탈로그·검증 결과를 동기화한다. 디자인 승인과 원격 게시 상태를 별도로 기록한다.

다른 Agent에게 전달할 최소 지시문:

> `AGENTS.md`, `DESIGN_SYSTEM.md`, `docs/EXPERIMENT_PATTERN.md`를 읽고 [평가 데이터]의 혼동행렬과 네 지표를 HTML로 작성하세요. 먼저 양성 클래스·표본 분포·개수·분수 정답을 확정하세요. GT는 이상→정상 열, 예측은 이상→정상 행으로 두어 TP/FP, FN/TN을 유지하세요. 축 제목 구분선은 실제 글자 경계로 정렬하고, 각 지표에 짧은 의미·공식·대입 결과를 함께 표시하세요. PC 4개 크기의 실제 렌더링, 수치 검증, 폰트 상태, 프리뷰를 제출하세요.
