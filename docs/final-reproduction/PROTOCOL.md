# 독립 제작 프로토콜

이 폴더의 TASK, INPUT_MANIFEST와 제공된 공통 Markdown·기존8종 원본/프리뷰만 디자인 근거로 사용한다. 다른 workspace/tmp 프로젝트, GitHub 저장소/PR, 과거 사례와 사용자 피드백을 읽지 않는다. 제공되지 않은 디자인 링크는 따라가지 말고 차단 사실을 기록한다. 현재 공통 규칙 안의 설명용 예는 허용한다. 과거 검증 이력 두 절만 제공본에서 제외했고 원본/제공 해시를 manifest에 남겼다.

기술 사실/산술 확인은 허용하되 디자인 출처와 구분한다. 설치된 브라우저/라이브러리 등 환경 도구는 사용 가능하다. 지원 환경은 PC4×Scroll/Slide. 실제 Chromium/로컬 폰트/기하·오류와 기술 계산을 확인한다.

1. 구현 전 examples/service-summary/DESIGN.md와 D0.md를 작성하여 commit한다. 패턴은 직접 선택하고 문서 출처·가정·탐색 문제·주제 고유 판단을 기록한다.
2. 한 장을 구현하고 자체 수정·검산·실제 화면 검증을 수행한다. 모든 결과는 examples/service-summary 안에 둔다. 공유 자산 경로는 ../../templates/html 아래를 사용한다. 입력은 변경하지 않는다.
3. 첫 완료 결과(소스·검증 코드·JSON·PC4×2 캡처·READ_LOG·VALIDATION)를 commit한다. 외부 교정 전 SHA를 Coordinator에게 인계한다. 자체 수정은 외부 피드백과 구분해 기록한다.
4. 이 폴더의 출력 Git만 사용하며 다른 저장소 탐색/Push/PR은 하지 않는다. 문제를 A~E로 분류하고 규칙 탐색 실패도 구분한다. 미검증 범위, 실제 사용자 화면 승인·학습자 이해도 미확인을 명시한다.

공유 호스트에서 별도 대화 context로 수행하며 OS 보안 격리 시험이 아니다. 규칙 밖 열람이 있었다면 보고한다. 첫 결과 보존 전에는 외부 디자인 교정을 받지 않는다. 검증기는 이 폴더 이외의 저장소에서도 상대 경로를 기반으로 실행 가능하게 작성한다.
