**수정 후 기술 검증은 통과했습니다. 최초 결과는 역할별 수학 서체 규칙을 놓쳐 전체 합격이 아니었습니다. 새 중대 공통 문서 누락은 확인되지 않았지만, 사용자 화면·릴리스 승인과 실제 독자 이해도 확인은 남아 있습니다. v1.0 완료/승인을 선언하지 않습니다.**

## 1. 선언할 지원 범위

승인 후 사용할 수 있는 **제한된 범위의 선언안**은 'PC용 편집 가능한 HTML Scroll/Slide 디자인 레퍼런스 8종과 제작·검토 가이드'입니다. 무검토 자동 생성기, 모든 새 주제의 즉시 합격, 범용 계산/레이아웃 엔진을 뜻하지 않습니다.

이번 신규 재현 근거는 **#8 Executive Summary의 세 지표 비교·각 기준100 정규화·원래 단위 유지·관측 근거→후속 판단**입니다. 응답시간/비용의 감소와 실패율 상승을 함께 다루고, 상대 변화%와 퍼센트포인트를 구분했습니다. #3의 같은 기준/정렬과 #7의 개수·분모 의미는 일부 참고했을 뿐 전체 패턴을 검증한 것은 아닙니다.

환경은 Chromium, 로컬 Pretendard/STIX 역할 분리, 전체 −1pt, PC1600×950/1440×810/1366×768/1280×720, 두 모드입니다. 실제 서비스 통계분석 도구가 아니라 제공된 가상 관측값을 설명하는 보고 한 장입니다. 고정 데이터용 문구·권고까지 모든 임의 데이터로 자동 생성되는 기능은 지원하지 않습니다.

기존8종 원본 회귀, 과거 사례, 이전 RAG 재현과 이번 #8 재현은 각각 다른 증거입니다. 검증하지 않은 #1~#7 전체 전이까지 통과로 묶지 않습니다. [이전 커버리지](../REUSE_COVERAGE.md)의 역사적 판정은 소급 수정하지 않았습니다.

## 2. 새 제작자의 첫 결과에서 발견한 문제

첫 결과의 수치·단위·정규화·권고·화면 기하는 맞았으나, **E-01: 신규 계산 결과도 모두 Pretendard로 처리**했습니다. 독립 검토144항목 중136통과, 같은 서체 문제가8화면에서 실패했습니다. 이를 결함8건으로 중복 집계하지 않습니다.

근거는 [첫 독립 보고서](review-first/REVIEW.md), [실제 JSON](review-first/results.json), 고정 첫 소스/캡처입니다. 최초 Builder의131검사 통과는 '전부 Pretendard'를 허용한 검사였으므로 역할별 서체 준수까지 증명하지 못했습니다. Coordinator가 새 계산 결과와 승인8종 보존 예외의 구분을 쟁점으로 제시한 뒤 Reviewer가 원문/CDP로 확정했습니다. 이를 Reviewer가 아무 쟁점 없이 처음부터 발견한 것으로 과장하지 않습니다.

Builder는 첫 결과 이전에 패널 높이 초과와 로딩 실패 안내 timeout을 자체 수정했고 [초기 실패 JSON](../../examples/service-summary/previews/self-correction-initial.json)을 보존했습니다. 이 자체 수정은 외부 교정 후 수정과 구분합니다. '퍼센트포인트'를 풀어 쓴 것은 자체 가독성 편집입니다.

이번 새 과제는 **무교정 첫 결과 전체 합격 사례가 아닙니다**. 이후 통과로 최초 판정을 덮어쓰지 않습니다.

## 3. 중대한 공통 문서 누락·모순

선택한 패턴/조건에서 **새 중대 D 누락·모순은 발견되지 않았습니다**. DESIGN_SYSTEM의 '본문과 수식의 서체 분리'와 `.math-number` 적용, Regular400, 합성 글리프 금지, 역할별 실제 폰트 검사가 이미 명시돼 있었습니다. 승인8종 보존 예외를 새로운 보고에 적용할 근거는 없습니다.

이는 기존 규칙 적용과 검사 누락 E이며 새 공통 기준을 추가해야 하는 D가 아닙니다. 별도 규칙 탐색 실패나 소스에만 있는 필수 공통 기준 B도 이번 범위에서 확정되지 않았습니다. 따라서 공통 Markdown/8종 원본은 수정하지 않았고 보완 단계로 돌아갈 신규 D 사유는 없었습니다. 전체 문서의 모든 잠재 결함이 없다는 뜻은 아닙니다.

| 분류 | 이번 근거 |
| --- | --- |
| A 명시 규칙 | 색·서체·자간·기준 정규화·높이/정렬·검토 절차 |
| B 소스에만 있는 필요한 공통 규칙 | 입증된 신규 결함 없음 |
| C 주제 고유 | 가상 데이터, 개선/악화 해석, p95 뜻, 후속 조치, 예제 배치와 축 범위 |
| D 공통 누락/모순 | 선택 범위에서 신규 결함 없음 |
| E 구현/검증 | 역할별 폰트 누락과 이를 통과시킨 검사; 자체 높이/실패경로 오류; 후속 감사용 span의 CSS 영향 수정 |

예제 전용 데이터·수치는 [DESIGN](../../examples/service-summary/DESIGN.md)에 남깁니다.

## 4. 구현 오류와 수정 결과

공유 math CSS를 로드하고 계산된 비율/퍼센트포인트/차이값에만 수학 역할을 적용했습니다. 반복되는 차이값도 포함합니다. 원시 관측값·일반 문구·단위·번호를 일괄 STIX로 바꾸지 않았습니다. 실제 STIX Regular400, font-synthesis:none 및 본문 Pretendard를 직접 텍스트 run의 CDP로 확인합니다.

최종 Reviewer는 11개 수학 결과 출현을 검사해 E-01 해소를 확인했습니다. 후속 검사 중 감사용 임시 span이 축의 CSS에 영향을 주는 검증기 오류도 Builder가 직접 발견해, 감사 후 임시 요소를 제거하고 실제 DOM을 캡처하도록 수정했습니다. 최종 캡처8개는 이 상태로 다시 생성됐습니다. 모든 후속 수정은 최초 결과와 별도 커밋이며 [VALIDATION](../../examples/service-summary/VALIDATION.md)에 자체/외부 수정 경위를 구분했습니다.

## 6. 사용자 화면 검토와 학습자 이해도

**사용자의 최종 화면 승인: 미확인. 실제 대상 독자의 이해도 시험: 미실시.** 채팅에 화면을 표시하거나 Reviewer가 이미지를 연 사실은 사용자 승인이나 독자의 이해를 증명하지 않습니다. 검토자는 Agent이며 성인 제품/운영 담당자를 모집해 오해·해석·의사결정을 관찰한 시험이 아닙니다.

## 7. 미검증 범위와 남은 한계

- 이번 보고 외 모든 패턴의 새 제작자 재현, #6 전체 구조 전이, arbitrary 지표 수/긴 문구/단위 조합, 다중장 탐색은 미검증입니다.
- Firefox/Safari·모바일/태블릿·인쇄·투사 거리/저시력·스크린리더 실제 사용·전면 접근성 인증은 미검증입니다.
- 원시 요청 데이터가 없어 주어진 p95 자체를 재산출하거나 실제 유의성/인과/장기 재현성을 검증하지 않았습니다. 가상 값의 산술과 표시를 검산했습니다.
- 공유 호스트의 context 분리이며, 파일시스템 접근 차단/모델 사전학습 경험 부재를 입증하지 않습니다. 공통 문서에 축적된 설명 예는 입력에 남아 있습니다.
- 첫 제작에서 명시된 수학 역할 규칙을 놓쳤다는 사실 때문에 무검토 즉시 합격을 지원 범위로 선언할 수 없습니다. 독립 검토가 필요한 작업 흐름이라는 한계를 유지합니다.
- 사용자 승인 전의 stacked PR 묶음이며 main/배포/릴리스에 반영된 결과가 아닙니다.

## 8. v1.0 완료 기준 충족 여부

[1단계의 승인 전 초안](../REUSE_COVERAGE.md)을 기준으로 아래처럼 구분합니다. **현재 v1.0 완료/승인 조건 전체는 충족하지 않았습니다.**

| 초안 조건 | 현재 상태 |
| --- | --- |
| 8종/PC/Scroll·Slide/편집 원본이라는 제공 범위 고정 | 기술 범위와 제한을 문서화함. 최종 출시 문구는 승인 전 |
| 후보 소스·프리뷰·문서·실제 검증 대응 | 이번 원본8종 및 새 과제의 해시/실행 증거 확보. 최종 출시 후보/CI·전체 묶음의 승인 절차를 대신하지 않음 |
| 패턴별 증거와 실패 이력 보존 | 기존 커버리지와 이번 #8 전이·첫 E 실패·수정 근거 보존. 미검증 패턴 일괄 통과 아님 |

| 새 제작자의 최소1개 새 과제 설계→제작→검증 | 통제된 context 시험 수행. 이번은 첫 전체 합격이 아니며 검토 후 수정 통과. 앞선 RAG 첫 PASS와 구분 |

실제 독자 이해도는 초안의 최소 필수 완료 항목과 별개로 여전히 미검증입니다. 따라서 '초급자 이해까지 검증된 라이브러리'라는 강한 선언도 할 수 없습니다. 사용자 최종 승인 전에는 tag/release/main merge를 실행하지 않습니다.
