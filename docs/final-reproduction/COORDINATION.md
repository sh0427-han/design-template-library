## 역할·허용 입력·독립성

- Fresh Builder `/root/fresh_service_builder`, `fork_turns="none"`. 부모 대화·이전 설계 경험을 context로 전달하지 않았다.
- Independent Reviewer `/root/service_reviewer`, 별도 `fork_turns="none"`. Builder에게 연락하지 않고 첫 결과 전 기술 기대값/검토 기준만 준비했다.
- 입력 폴더 `/workspace/fresh-service-summary`에 공통 Markdown/기존8종/프리뷰/공통 mode 문서50개를 복사. 과거 사례 소스·DESIGN·피드백·검증 결과는 제공하지 않았다. 두 과거 이력 절을 제외한 제공본과 고정 원본의 해시를 INPUT_MANIFEST에 기록했다. 현재 규칙에 내장된 설명용 예를 제거한 시험은 아니다.
- 공유 호스트/도구를 사용한다. 대화 context와 제공 폴더는 분리했으나 OS 권한으로 경로 밖 접근을 차단한 보안 실험은 아니다. 열람 제한은 프로토콜·Agent 보고 및 산출물 출처 기록의 범위에서 평가한다. 모델의 일반 사전학습 지식 부재를 주장하지 않는다.
- 기술 사실 확인은 허용하지만 디자인 출처와 분리한다. 출력은 해당 예제 폴더로 한정한다.

## 첫 결과 보존 방침

DESIGN/D0 선행 커밋 → Builder 자체 제작·검산·렌더 → 첫 소스/화면/평가 커밋 → 독립 리뷰 순서. 첫 결과 이전에는 디자인 교정을 하지 않는다. 환경 상태 질문은 허용하되 피드백으로 구분한다. 결함이 발견되면 첫 평가를 남긴 뒤 후속 수정·재검토한다.

Reviewer 사전 계산 기준은 원자료에서 독립 Fraction으로 도출했다. 응답시간−35%, 비용−15%, 실패율0.5%→0.8%, +0.3%p/+60%, baseline100 지수65/85/160. 이는 Coordinator/Reviewer 기록이며 Builder 입력 폴더에 전달하지 않았다.

첫 결과 문제, 공통 D 누락/모순, B 소스에만 있는 규칙, A 탐색 실패, C 주제 판단, E 구현/검증 오류를 분리한다. 새 공통 결함이 입증되면 해당 범위는 보완 필요로 판정하고 별도 보완을 선행한다. 한 사례의 성공으로 모든8종을 통과시키지 않는다. 사용자 화면 승인·실제 학습자 이해도·v1.0 승인은 자동/Agent 검토와 구분한다.
