## 독립성 및 확인 범위

고정 SHA를 받기 전 TASK/PROTOCOL/INPUT_MANIFEST와 제공 AGENTS, DOCUMENTATION_MAP, REFERENCE_REVIEW_GUIDE, TEMPLATE_REUSE_VALIDATION만 읽고 raw TASK에서 Fraction으로 산술을 계산해 Coordinator에게 전달했다. 첫 결과 보존 후 현재 예제의 소스·DESIGN/D0/READ_LOG/VALIDATION/검증기와 제공 MODES, PAGE_SPECS §08, DESIGN_SYSTEM의 해당 서체 절을 확인했다. 이전 examples/피드백/미제공 링크/원격 자료는 열지 않았다. Builder에게 연락하거나 피드백을 주지 않았다. 공유 호스트의 별도 context 검토이며 보안 격리 시험이 아니다.

서체 문제의 검토 계기: 첫 결과 고정 후 Coordinator가 “신규 계산 결과 역할과 기존 8종 보존 예외를 구분하라”는 쟁점을 전달했다. 이를 독립 원문 대조와 CDP 증거로 확인했다. 이 발견을 사전 무교정 발견으로 주장하지 않는다. 첫 결과 자체는 외부 교정 전 보존되어 있다.

## raw TASK 독립 산술

Python `fractions.Fraction`으로 구현 JS를 호출하지 않고 계산했다. 결과는 results.json에 분수 문자열로 보존했다.

| 대상 | 원시 입력과 계산 | 기대 결과 |
|---|---|---|
| 응답시간 | (520−800)/800×100 | −35%, −280ms |
| 하루 비용 | (102−120)/120×100 | −15%, −18달러/하루 |
| 기존 실패율 | 50/10000×100 | 0.5% |
| 변경 실패율 | 80/10000×100 | 0.8% |
| 실패율 절대 차이 | (80/10000−50/10000)×100 | +0.3퍼센트포인트 |
| 실패율 상대 변화 | ((80/10000)/(50/10000)−1)×100 | +60% |
| 공통 비교지수 | after/before×100 | 65, 85, 160 |

세 지표 모두 낮을수록 유리하므로 앞의 둘은 개선, 실패율은 악화다. 각 지표 기존=100이라는 기준과 “중요도나 종합 점수는 아님”이라는 설명은 단위가 다른 원래 값을 단일 절대축으로 비교하는 오해를 막는다. 실패율 %와 퍼센트포인트를 구분한다. 평균이나 모든 요청의 시간으로 잘못 설명하지 않고 p95를 약95% 이내 응답으로 설명한다.

가상 예시, 설정별 별도 하루 10000건, 동일 요청혼합/부하 가정이 명시되어 있다. 인과효과·장기 재현성·유의성 미확인을 보이는 문구로 유지한다. 실패 원인 분석, 허용 실패율 합의, 실패 요청의 응답시간 집계 포함 기준 통일, 반복 관측 후 확대 판단은 관측상 손실에 근거한 적절한 조치다. 미제공 허용 기준이나 유의성 수치를 만들지 않았다. 실패 요청 집계 포함 여부의 단서는 p95 해석 범위에도 도움이 된다.

## 실제 독립 실행

`python docs/final-reproduction/review-first/check.py`로 Python Playwright / 실제 `/usr/bin/chromium` 154.0.8037.57에서 별도 로컬 HTTP 서버를 실행했다. Builder의 verify.py나 JSON을 실행 증거로 대신하지 않았다. 이 검토기는 자신의 위치를 기준으로 저장소를 찾는다.

PC 1600×950, 1440×810, 1366×768, 1280×720 × Scroll/Slide를 새로 렌더하고 8개 PNG를 생성했다. 모든 8개 PNG를 view_image로 직접 열었다. 원래 데이터 및 축/막대/라벨 대응, 카드/푸터 여유, 단위, 개선/악화 문자, 주의사항을 확인했다. 작은 Slide에서도 잘림은 없지만 작은 각주의 실제 청중 가독성 승인을 의미하지는 않는다. Scroll의 full-page PNG 높이가 작은 viewport보다 긴 것은 정상 스크롤이며 끝단 접근을 별도로 확인했다.

[results.json](results.json): 144개 검사 중 136개 통과, 역할별 수학 서체 검사 8개 실패(같은 E 문제의 8화면 재현이며 결함8건으로 중복 집계하지 않음).

- 산술표시, 실제 막대높이 `[60,39,60,51,60,96]`px, 공통 baseline, 숫자와 막대 분리, 패널-푸터 분리, 직접 text-node Range의 패널/캔버스 경계: 통과.
- 브라우저 콘솔/pageerror/HTTP/요청실패: 정상 화면에서 없음.
- 로컬 WOFF2, CDP 실제 글리프: Pretendard 로딩 확인. 본문·뷰어 전체 −1pt 확인. **전체 Pretendard라는 관측 자체는 수학 역할 준수 합격이 아님.**

## E-01 · 계산 결과 역할에 Pretendard만 적용

근거: 제공 `DESIGN_SYSTEM.md` §본문과 수식의 서체 분리(152–163행)는 새 자료의 수학 변수·계수·수식에 STIX Two Math를 요구하고, 160행은 “`.math-number`는 수식의 결과·계수·확률 같은 숫자에 사용”한다고 명시한다. 154행의 기존 승인8종 서체 보존은 기존 원본 예외이며 새 보고에 대한 포괄 예외가 아니다. 163행은 역할을 구분하지 않은 글꼴 허용 목록 검사가 부족하다고 명시한다.

이 보고의 `−35.0%`, `−15.0%`, `+0.3`, `+60.0%`는 과제의 명시적 계산 결과다. 실패율 `0.5%`, `0.8%` 역시 개수/분모에서 계산한 비율값이다. 현재 content.html은 math-typography.css를 로드하지 않고 report.js의 출력에 수학 결과 역할 표시도 없다. 실제 CDP는 해당 글리프를 포함해 전부 Pretendard로 확인했다. 따라서 E(명시 규칙 적용 및 검증 누락)이며 새로운 D(규칙 부재)로 분류하지 않는다.

수정 범위: 계산 결과 숫자와 그 수학 부호를 분리해 math-number로 표시하고 공유 math-typography.css를 로드한다. 한글 ‘개선/악화/퍼센트포인트/상대 변화’와 일반 본문, 페이지번호/행동번호는 Pretendard로 유지한다. 원시 관측값 800ms/520ms, 120달러/102달러나 본문 모든 숫자를 일괄 STIX로 교체할 필요는 없다. STIX Regular 400/font-synthesis:none과 −1pt를 지키고 PC4×2 실제 글리프·줄경계·캡처를 재검증해야 한다. 통계 내용이나 패턴을 다시 설계할 필요는 없다.

Builder의 “모든 텍스트 Pretendard” 검사와 VALIDATION의 폰트 통과는 이 역할 분리를 검증하지 못했다. 문서 발견 여부는 READ_LOG에 서체 규칙을 읽었다는 기록이 있지만 의도를 추정할 수 없으므로 **발견 가능한 규칙의 적용/검증 누락**으로 기록한다. 필수 규칙을 찾을 수 없었다는 문서 탐색 실패의 증거는 아니다.
