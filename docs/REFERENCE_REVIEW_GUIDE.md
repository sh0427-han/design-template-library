# 레퍼런스 검토 가이드

검토 대상은 HTML Scroll/Slide에 재사용하는 8개의 **설명 패턴**입니다. 가장 예쁜 한 장보다 새 데이터와 다른 주제에서도 정확하게 표현할 수 있는 원본·명세·검증을 평가합니다.

## 검토 순서

1. 사용자 목표·청중·선수 지식·실측/예시 구분과 학습 목표 한 문장. 새 용어의 정식 명칭·짧은 뜻·첫 등장 순서.
2. 개념 장의 그림·키워드·일반 관계와 다음 상세 장의 실제 값·과정 구분. 입력·처리·출력·비교 행·상호작용의 기술적 의미.
3. 실제 데이터·수식·Shape·단위·확률·축과 독립 계산의 일치.
4. 제목·실제 Figure 중심·설명의 축, 도형 간격, 내부/외부 화살표.
5. White 카드·의미 색상·텍스트 위계·전체 −1pt·본문의 실제 Pretendard. 새 수식은 STIX Two Math/MathML의 실제 글리프와 첨자·분수 경계도 역할별 검사.
6. 카드 패딩·구분선·본문과 Footer·가로 폭·이미지 로드.
7. 조작·키보드·경계값·분모 0과 다른 데이터의 재사용.
8. 실제 캡처와 소스·명세·카탈로그가 같은 최종 상태인지 확인.

## 필수 PC 화면

| 1600×950 | 1440×810 | 1366×768 | 1280×720 |
| --- | --- | --- | --- |
| 기준 캡처 | 일반 열람·발표 창 | 작은 PC 화면 | 높이 제한 |

모바일·태블릿 전용 검수는 새 자료의 필수 조건에서 제외합니다. PC 웹페이지의 실제 폰트·배치·계산·키보드/포인터 사용을 확인합니다.

```bash
python scripts/check_sources.py
python scripts/verify_character_spacing.py
python scripts/validate_references.py
python scripts/check_interactive.py
python scripts/verify_pretendard.py
python scripts/check_documentation.py
```

새 자료는 PC 4개 크기의 수치·기하·실제 글꼴 검사를 통과한 뒤 PC 이미지를 직접 엽니다. 위 공통 스크립트와 CI는 현재 기존 8종×6개 크기(48개 조합)의 회귀 검사를 실행하며, 추가 작은 화면 결과는 기존 구현의 호환성 기록입니다. 폰트 이름만 CSS에 적힌 상태, 일부 화면만 검사한 상태, 생성 이미지로 원본을 대체한 상태를 완료로 취급하지 않습니다.

## 디자인 명세 완성도

[컴포넌트 규격의 설계 기록표](DESIGN_COMPONENT_RECIPES.md#6-새-자료에-작성할-설계-기록표)와 실제 CSS/DOM을 대조합니다.

- [ ] [첫 등장 기준](../DESIGN_SYSTEM.md#용어와-약어의-첫-등장)에 따라 정의 전 약어가 없고, 정식 명칭과 쉬운 한 문장 뜻을 함께 제시했다.
- [ ] 독립 페이지·연속 강의의 정의 범위를 구분하고, 두 모드에서 필수 뜻이 보이며 용어·기호·양성 클래스 표기가 일관된다.
- [ ] 긴 영문명과 설명이 제목·노드를 압박하지 않고, 추가된 행 높이·Figure·캡션·Footer를 함께 검토했다.
- [ ] 크기·굵기·행간과 요소 사이 간격을 구분해 기록했다.
- [ ] 일반 영문과 수학 변수를 구분하고, 본문/수학 서체의 실제 글리프·기준선·첨자·분수·−1pt를 각각 확인했다.
- [ ] 첫 장은 일반 기호·그림·키워드이며 예시 입력/계수/결과/선택 점을 넣지 않았다. 상세 장은 요청된 경우에만 실제 값과 계산으로 확장하고 한 장 요청에 자동 추가하지 않았다.
- [ ] 상세 장이 있다면 개념 장과 같은 단계 순서이며 출력이 다음 입력과 같은 값이다. 단계 위의 값/아래 식·그림·결과가 대응하고 인접 단계의 짧은 화살표가 이를 보여준다.
- [ ] 수식과 그래프는 같은 계산을 사용하고 양 축 값·단위·교점·투영선·반올림을 대조했다. 하단 정의와 Figure의 중앙축이 일치한다.
- [ ] 패널 비율·padding·border·radius·그림자와 강조 이유를 기록했다.
- [ ] Header/Content/Footer 및 카드 행·간격·테두리의 높이 합을 계산했다.
- [ ] 실제 Figure 중심·대응 Y좌표·표 본문 시작선·축 구분선을 측정했다.
- [ ] 수치 정밀도·단위·분수·대입식·범례·예시/실측 범위가 명확하다.
- [ ] PC 창 크기별 축소·수식 줄바꿈·단위·화살표·Footer 배치를 기록했다.
- [ ] 초기/변경/경계/실패 상태와 키보드·모션 감소를 확인했다.
- [ ] `normal`이나 고정 픽셀 행간 등 공통 기준의 예외에 이유와 적용 범위가 있다.
- [ ] 실제로 정의된 토큰만 참조하며 새 전용 수치가 소스에만 남지 않는다.

## 결과 보고

변경한 페이지와 파일, 기술 검증·폰트·레이아웃 결과, 실제 대표 프리뷰, 재사용 검증 범위, 남은 제한을 기록합니다. #6의 Shape 계약이나 #7의 축 방향 같은 핵심 기준은 [페이지 명세](REFERENCE_PAGE_SPECS.md)를 따릅니다.

자동 검사·사용자 승인·Push·PR·main 반영은 각각 별도 상태입니다. 역사적 검토 문서를 현재 설계 명세로 사용하지 않습니다. [8종 검토 완료 상태](REFERENCE_RELEASE_STATUS.md)와 [프리뷰 증거](../previews/review/README.md)를 확인합니다.

## 템플릿 재사용 검증의 추가 판정

새 자료로 라이브러리를 검증할 때는 [검증 기준](TEMPLATE_REUSE_VALIDATION.md)을 적용합니다. 완성 화면뿐 아니라 주요 결정의 문서/원본 출처, 보완 전 누락·모순, 개념 고유 설계, 구현 오류와 사용/미사용 패턴을 `VALIDATION.md`에서 확인합니다. 문서 보완 전D0와 보완 후D1을 분리하며 새 과제가 사용하지 않은 패턴을 통과 처리하지 않습니다.
