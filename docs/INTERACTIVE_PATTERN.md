# #5 Interactive · 임계값과 분류 결과

상태: **개선 초안, 사용자 검토 대기**. #7의 승인된 축 방향과 설명 수준을 #5의 조작형 학습 목적에 적용한 기록입니다. 이 문서는 결과 이미지뿐 아니라 새 데이터·강의에서도 같은 수준으로 설명하는 데 필요한 기준을 정리합니다.

## 목적과 파일

학습자가 임계값 하나를 바꿨을 때 **샘플 판정 → 혼동행렬 개수 → Precision·Recall 대입식**이 함께 바뀌는 관계를 읽게 합니다. #7의 고정된 12개 평가 샘플을 복제하지 않고, 기존 #5의 6개 점수와 실제값을 유지합니다.

## 화면의 읽는 순서

1. 제목과 부제목으로 `임계값 조절 → 샘플별 판정 → 혼동행렬과 평가 지표`를 예고합니다.
2. 왼쪽 흰색 카드에서 점수·실제값·예측값·판정 유형을 같은 행에 놓습니다.
3. 오른쪽 흰색 카드의 혼동행렬로 여섯 샘플의 판정을 집계합니다.
4. 같은 오른쪽 카드 아래에서 지표 이름, 한 줄 뜻, 일반식, 현재 숫자의 대입식을 읽습니다.
5. 마지막 Teal 선 캡션에 일반화할 수 있는 결론을 놓습니다. 캡션 뒤에는 추가 설명 카드를 두지 않습니다.

두 주 카드는 같은 위·아래 경계를 사용합니다. 데스크톱 열 비율은 `1.07fr : 1fr`, 간격은 20px입니다. 왼쪽의 여섯 열을 억지로 줄이지 않으면서 오른쪽 행렬과 두 지표가 균형을 이루도록 조정했습니다. 여백을 채우기 위한 설명은 추가하지 않습니다.

샘플 행의 `실제`, `예측`, `유형`은 서로 다른 정보입니다. `TP`만 표시하고 예측 클래스가 이상이라는 해석을 학습자에게 맡기지 않습니다. 실제값은 Muted, 예측값은 굵은 Navy, 유형은 문자와 의미 색상이 있는 배지로 표현합니다. 색상만으로 판정을 전달하지 않습니다.

## 데이터와 판정 계약

양성 클래스는 **이상(1)**, 음성 클래스는 **정상(0)**입니다. 이상 점수가 임계값 **이상**이면 이상으로 예측합니다. `>`로 바꾸지 않습니다. 점수는 이 예제의 설명용 값이며, 확률 보정된 수치나 실측 성능이라는 주장은 하지 않습니다.

| 샘플 | 이상 점수 | 실제값 | 기본 0.60에서 예측 | 유형 |
| --- | ---: | --- | --- | --- |
| #1 | 0.15 | 정상 | 정상 | TN |
| #2 | 0.32 | 이상 | 정상 | FN |
| #3 | 0.48 | 정상 | 정상 | TN |
| #4 | 0.67 | 이상 | 이상 | TP |
| #5 | 0.82 | 이상 | 이상 | TP |
| #6 | 0.94 | 정상 | 이상 | FP |

- 슬라이더의 내부 정수 범위는 0–100, 간격은 5입니다. 표시·계산에 쓰는 값은 이를 100으로 나눈 0.00–1.00, 간격 0.05입니다.
- 기본값은 0.60입니다. 행렬과 지표의 기본 숫자는 이 상태와 일치해야 합니다.
- 각 점수 막대의 주황 점선은 같은 임계값의 위치입니다. 막대 길이는 점수이며 예측이나 TP 개수를 나타내지 않습니다.
- `samples`에서 예측·유형·개수·대입식·상태 알림을 한 경로로 계산합니다. 데이터 변경 시 별도 수치 배열을 수동 유지하지 않습니다.
- 샘플 총수와 실제 정상/이상 수 역시 `samples`에서 계산합니다. 재사용 때 `3개·3개` 같은 문구가 남지 않아야 합니다.

## 혼동행렬의 방향과 정렬

| 모델 예측 / GT | 실제 이상 | 실제 정상 |
| --- | ---: | ---: |
| 예측 이상 | TP | FP |
| 예측 정상 | FN | TN |

상단 제목은 **GT (실제값)**, 좌측 제목은 **모델 예측**입니다. #7에서 사용자가 확정한 **TP FP / FN TN** 순서를 유지합니다. 임계값을 조절할 때는 개수만 변하며 셀의 위치·레이블·색의 의미는 변하지 않습니다.

- TP/TN: Teal, FP/FN: Amber. 정상/이상 자체를 이 색으로 매핑하지 않습니다.
- GT 아래의 가로선은 두 실제값 열에 걸칩니다.
- 모델 예측 옆 세로선은 **모델 예측 글자의 오른쪽 경계와 예측 이상/예측 정상 글자의 왼쪽 경계 사이 정중앙**에 둡니다. 표 셀 테두리를 세로선 대신 사용하지 않습니다.
- 행렬은 실제 HTML `table`, 행·열은 `th`와 `scope`, 데이터 셀은 `headers`로 연결합니다. 화면용 그림과 접근성용 데이터의 축이 달라지지 않게 합니다.
- 제목·행열 라벨·셀 코드·숫자는 중앙 정렬합니다. 작은 TP 레이블과 큰 개수를 세로로 묶습니다.

세로선은 `Range`로 실제 텍스트 경계를 측정해 배치합니다. 글꼴 로딩 후와 `ResizeObserver`·창 크기 변경 시 다시 측정하며, CSS zoom 배율과 선 두께의 절반을 보정합니다. 고정 `left` 숫자만 복사하면 다른 폰트·화면 폭에서 간격이 달라집니다.

## 지표: 의미 → 일반식 → 현재 대입식

| 지표 | 짧은 설명 | 일반식 | 기본 0.60의 대입식 |
| --- | --- | --- | --- |
| Precision | 이상 예측 중 실제 이상 비율 | TP / (TP + FP) | 2 / (2 + 1) = 66.7% |
| Recall | 실제 이상 중 찾아낸 비율 | TP / (TP + FN) | 2 / (2 + 1) = 66.7% |

각 지표는 하나의 작은 흰색 카드로 묶습니다. 이름과 현재 비율을 같은 헤더에 두고 아래에 짧은 뜻·일반식·파란 대입식을 놓습니다. 다른 카드의 설명을 찾아야 식을 이해하는 구성을 피합니다.

백분율은 반올림 전 비율에서 소수 한 자리로 표시합니다. 분모가 0이면 **정의 불가**이며, `0%`, `NaN`, `Infinity`로 대체하지 않습니다. 기본 데이터에서 임계값 1.00은 이상 예측이 없으므로 Precision은 정의 불가, Recall은 0.0%입니다. 더 긴 `정의 불가` 상태에서도 카드가 잘리지 않게 검증합니다.

| 임계값 | TP | FP | FN | TN | Precision | Recall |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 0.30 | 3 | 2 | 0 | 1 | 60.0% | 100.0% |
| 0.60 | 2 | 1 | 1 | 2 | 66.7% | 66.7% |
| 0.85 | 0 | 1 | 3 | 2 | 0.0% | 0.0% |
| 1.00 | 0 | 0 | 3 | 3 | 정의 불가 | 0.0% |

마지막 캡션은 `임계값 ↑ → Recall은 증가하지 않음`과 `Precision은 샘플 구성에 따라 변동`입니다. 고정된 데이터·점수와 양성 클래스가 있을 때 임계값 상승으로 TP는 늘지 않고 실제 양성 총수는 고정이므로 Recall은 증가하지 않습니다. 항상 감소하는 것은 아니므로 구간별 동일값도 허용합니다. Precision이 반드시 증가한다고 설명하지 않습니다. 실제 양성이 없는 데이터에서는 Recall 자체가 정의 불가이므로 이 캡션도 해당 조건에 맞게 바꿉니다.

## 반응형·폰트·조작

- 900px 초과: 공통 1440×810 기준의 16:9 비례 축소. 창 너비와 높이를 모두 고려합니다.
- 900px 이하: 두 주 카드를 위·아래로 배치하고 페이지 세로 스크롤을 허용합니다.
- 520px 이하: Precision·Recall 카드도 세로로 배치합니다. 샘플의 실제·예측·유형 열은 유지하고 가로 오버플로를 만들지 않습니다.
- Pretendard Variable 및 모든 텍스트 `-1pt`를 공통 토큰에서 상속합니다. 읽기 어려운 특정 글자만 자간을 바꾸지 않습니다.
- 슬라이더는 네이티브 range이며 포인터, Home/End, 방향키를 지원합니다. `aria-valuetext`에 표시값과 판정 규칙을 제공합니다.
- 전체 오른쪽 카드를 `aria-live`로 지정하지 않습니다. 전용 비가시적 `role=status`에서 임계값·네 개 개수·두 지표를 간결하게 알립니다.
- 샘플별 접근성 이름에 점수·실제값·예측값·유형을 포함합니다. 키보드와 DOM 의미를 검사했으며 실제 스크린리더 청취 평가는 수행하지 않았습니다.

## 실행과 검증 범위

저장소 루트에서 Python Playwright, 시스템 Chromium, curl이 준비된 상태로 실행합니다.

```bash
python scripts/check_interactive.py
```

기본 예제는 아래 6개 화면 각각에서 0.00–1.00의 21개 임계값, 총 **126개 상태**를 독립 계산값과 비교합니다.

`1600×950 · 1440×810 · 1366×768 · 1280×720 · 900×900 · 390×844`

검사 범위: 각 샘플 실제·예측·유형, TP/FP/FN/TN, 두 백분율, 두 대입식, 임계값 표시, 예측 개수 요약, 상태 알림, 각 상태의 글자 잘림·컨테이너 오버플로입니다. 기본값으로 돌아와 행렬 축·순서, 세로선 양쪽 간격, 실제 Pretendard 로딩, 전 텍스트 자간, 마지막 캡션, 카드·푸터 겹침, 모바일 가로 폭, 키보드·포인터 조작을 추가로 확인합니다.

실제 렌더링 캡처는 `/tmp/interactive-draft-review/interactive-{width}.png`, 대표 JPG는 `previews/html-interactive.jpg`에 저장합니다. 브라우저 오류·실패 요청이 없어야 통과합니다. 최종 JPG와 모바일 PNG를 직접 열어 시각적으로도 확인합니다. 수치 검사를 미적 완성도 승인으로 간주하지 않습니다.

`previews/review/interactive-live.html`도 같은 스크립트가 생성합니다. 로컬 CSS·JS를 인라인으로 포함해 파일 하나로 열고 조작할 수 있습니다. 원본과 기본 화면의 콘텐츠 PNG 픽셀이 같은지 비교하고, 임계값 변경도 검사합니다. 네이티브 range는 조작 이력에 따른 미세한 브라우저 페인트 차이가 있어 픽셀 비교에서 마스킹하며, 값·키보드·포인터 동작은 별도 검사합니다. Pretendard 웹 폰트는 여전히 CDN 연결이 필요하며 오프라인에서는 시스템 폴백으로 표시됩니다. 이 생성 파일을 직접 고치지 말고 원본 수정 후 검증 스크립트를 다시 실행합니다.

이 환경에서는 Chromium의 외부 폰트 직접 요청에 인증서 문제가 있었습니다. 검증 스크립트는 curl의 정상 TLS 검증을 거쳐 원본 CDN CSS·폰트 바이트를 받고 SHA-256 캐시를 확인한 뒤 원래 URL에 응답합니다. 인증서 검증 해제나 신뢰 저장소 변경은 하지 않습니다. 이 방법으로 실제 Pretendard를 캡처했으며, 배포 브라우저의 CDN 연결 문제 해결을 의미하지는 않습니다.

공용 `render_previews.py`는 #5의 마지막 강조 캡션을 허용하고 비가시적 `.sr-only`를 시각적 경계 검사에서 제외하도록 맞췄습니다. 다른 슬라이드의 HTML·CSS·프리뷰는 변경하지 않습니다.

## 데이터 변경 재사용 검증

복사한 화면이 새 숫자에도 따라오는지 확인하기 위해, 검증 중 브라우저에 전달하는 JS의 샘플 배열만 다음처럼 바꿉니다. 저장소 원본 데이터와 대표 JPG는 바꾸지 않습니다.

- #1 실제값: 정상 → 이상.
- #6 점수: 0.94 → 0.60. 임계값과 같은 점수의 `>=` 판정도 포함합니다.
- 실제 정상 2개·실제 이상 4개로 문구가 자동 갱신되어야 합니다.
- 기본 0.60에서 TP=3, FP=1, FN=1, TN=1, Precision=75.0%, Recall=75.0%여야 합니다.
- 1600×950과 390×844에서 각각 21개, 총 **42개 상태**의 유형·예측·개수·백분율·대입식과 오버플로를 검사합니다.

검증 JSON의 `reuse`가 이 결과입니다. 샘플 개수 증가, 긴 다른 언어 라벨, 다중 클래스 확장은 이번 검증 범위가 아니며 새로 렌더링해야 합니다. 6개보다 샘플이 많아지면 슬라이드 내부에 줄을 억지로 넣기보다 Scroll 모드 또는 별도 슬라이드를 검토합니다.

## 다른 작업에 적용할 요청문 예시

> #5 Interactive 패턴으로 새로운 이진 분류 임계값 예제를 만들어줘. 양성 클래스와 점수의 의미를 먼저 정의하고, 각 샘플에 점수·실제·예측·유형을 분리해 보여줘. GT 실제 이상/정상 열, 예측 이상/정상 행의 TP FP / FN TN 순서를 유지해줘. 지표마다 짧은 뜻·일반식·현재 숫자 대입식을 묶고 슬라이더 변경 시 한 계산 경로로 갱신해줘. 분모 0과 경계값 동등 비교를 확인하고, 최종 Teal 캡션은 마지막에 둬. 공통 Pretendard/-1pt를 유지하고 6개 화면 크기에서 렌더링한 뒤 다른 샘플 구성으로 한 번 더 재사용을 검증해줘.

복사 후에는 양성 정의, 점수 범위, 임계값 범위·간격, 샘플 수, 캡션의 수학적 조건을 먼저 확인합니다. 화면·공식·미리보기·문서가 같은 예제를 설명할 때 재사용이 완료됩니다.
