# 8종 레퍼런스와 Markdown의 재사용 검증

## 목적과 기준 자료

목표는 **기존8종 HTML 레퍼런스와 공통 Markdown만으로 새로운 개념의 자료를 같은 품질로 제작할 수 있는지 검증하는 것**입니다. 새 슬라이드는 검증 산출물이며, 이를 만드는 과정에서 문서의 누락·모순·재현 가능성을 확인합니다. 로지스틱 회귀는 이 목적의 첫 검토 사례입니다. 아홉 번째 정본 템플릿이나 다음 제작의 출발 원본으로 취급하지 않습니다.

| 자료 | 역할 |
| --- | --- |
| [카탈로그](../TEMPLATE_CATALOG.md), templates/html의8종과 최신 프리뷰 | 검토된 시각 패턴·편집 가능한 구현의 정본 |
| [디자인 시스템](../DESIGN_SYSTEM.md), [컴포넌트 규격](DESIGN_COMPONENT_RECIPES.md), [Figure 표준](FIGURE_PRODUCTION_STANDARD.md), [페이지 명세](REFERENCE_PAGE_SPECS.md) | 공통 규칙과 역할별/레퍼런스별 계약 |
| [재사용 워크플로](REFERENCE_REUSE_WORKFLOW.md), [검토 가이드](REFERENCE_REVIEW_GUIDE.md) | 제작 순서와 실제 검수 방법 |
| 로지스틱 회귀의 소스·명세·캡처 | 첫 검증의 산출물과 추적 근거; 새로운 정본이 아님 |
| 새 과제의 DESIGN.md / VALIDATION.md | 새 개념의 설계와 문서 재사용성의 판정 기록 |

다음 라운드는 로지스틱 회귀를 복제하지 않고 **교훈을 반영한 공통 Markdown + 기존8종**에서 다시 출발합니다. 과거 대화나 제작자의 기억으로 문서에 없는 디자인 규칙을 조용히 보충하지 않습니다. 개념의 기술 정보는 별도 검산·확인이 필요하며, 디자인 규칙의 출처와 구분합니다.

## 로지스틱 회귀 검토에서 반영한 내용

현재 첫 사례의 구현 기준은 Commit `77eb1f0`의 개념 한 장입니다. [명세](../examples/logistic-regression/DESIGN.md), [현재 검토 이미지](../examples/logistic-regression/review/README.md), [검증 기록](../examples/logistic-regression/previews/validation.json)으로 구성과 결과를 확인합니다. 계산 장·부록은 검토 과정에서 제거했고 최종 정본에 포함하지 않습니다. 과거 시도의 문제에서 얻은 일반 기준은 아래처럼 공통 문서에 남깁니다.

| 검토에서 드러난 문제 | 반영한 재사용 기준 | 규칙의 위치·범위 |
| --- | --- | --- |
| 개념 Figure에 실제 계산과 상세 설명이 섞여 핵심 관계가 약해짐 | 개념 장은 그림·키워드·정확한 일반 관계로 완결. 상세 계산은 요청 범위일 때 별도 확장 | [개념 설명의 기본 순서](../DESIGN_SYSTEM.md#개념-설명의-기본-순서). 한 장 요청의 범위 규칙이며8종의 계산/평가 패턴을 금지하지 않음 |
| 값이나 기호만 보여주면 가중치·절편의 뜻과 입력/출력 관계가 불명확 | 필수 항과 기호 뜻을 보존하고 해당 Figure 가까운 설명에 연결 | [수치·수식·표·범례](../DESIGN_SYSTEM.md), [문구 배치](FIGURE_PRODUCTION_STANDARD.md#11-문구-길이와-정보-배치) |
| 변수만 바꿔도 시그모이드 분수·지수·축 일부가 본문 서체에 남음 | 본문/일반 영문과 수학량을 구분하고 모든 수식 경로의 실제 글리프를 역할별 확인 | [수학 서체](../DESIGN_SYSTEM.md#본문과-수식의-서체-분리). 특정 함수에만 적용하지 않음 |
| 입력 기호가 박스 안에서 치우치거나 답답해 보임 | 변수/식을 하나의 묶음으로 중앙 정렬하고 실제 안쪽 패딩 확인 | [컴포넌트 규격](DESIGN_COMPONENT_RECIPES.md).214px/16·24px 등의 구체값은 해당 예제 전용 |
| 하단 기호 설명이 위 Figure와 다른 중앙축을 사용 | 대응 그림·정의는 같은 grid 트랙과 중앙축을 공유 | [높이·정렬](../DESIGN_SYSTEM.md#높이-배분과-반복-요소의-정렬), [Figure 중앙축](FIGURE_PRODUCTION_STANDARD.md#6-중앙축과-도형-간격) |
| line-height와 별도 요소 간격이 혼용되면 제목·소개·다음 단계가 붙음 | 행간과 그룹/구역 간격을 따로 정의하고 전체 높이 예산 재측정 | [행간과 간격](../DESIGN_SYSTEM.md#행간과-요소-사이-간격).8/16/24px 공통 기준과 전용 예외 구분 |
| 한 계산을 나눈 두 카드 사이에 긴 z 전달 선이 생김 | 같은 의미 흐름은 인접 배치·짧은 연결을 우선하고 식/라벨을 가로지르지 않음 | [연결 규격](../DESIGN_SYSTEM.md). 모든 다중 카드·직교 화살표를 금지하는 규칙은 아님 |
| 실제 수식과 그래프를 함께 보여줄 때 값·반올림·축 라벨이 따로 움직일 수 있음 | 필요한 상세 설명에서는 동일 계산으로 점·투영선·축 값을 생성하고 실제 라벨 겹침을 검사 | [수식/그래프](DESIGN_COMPONENT_RECIPES.md). 최종 개념 장은 일반 곡선만 유지 |
| 재사용 테스트를 위해 장·유형을 늘리면 학습 목표를 벗어남 | 필요한 패턴만 선택하고 사용자 범위를 페이지 수·목차·코드·프리뷰에 일치시킴 | [재사용 절차](REFERENCE_REUSE_WORKFLOW.md).8종을 모두 사용하거나 네 단계를 고정하지 않음 |
| 도구가 읽은 이미지나 로컬 경로가 외부 검토 화면을 대신하지 못함 | 접근 가능한 실제 렌더링 이미지의 공개 주소를 확인하고 채팅에 표시 | [전달 방법](../examples/logistic-regression/README.md#검토-이미지를-전달하는-방법). 로컬 QA와 외부 전달을 구분 |

이 표는 검토에서 확정한 교훈의 추적표입니다. 모든 항목이 최초 문서에 없었다는 뜻은 아닙니다. 기존 규칙을 구현이 따르지 않은 경우와 문서를 보완해야 했던 경우를 다음 라운드에서 따로 판정합니다. 레퍼런스별 수치·전용 배치까지 공통 기본값으로 승격하지 않습니다.

## 다음 라운드의 절차

1. 시작 브랜치·Commit SHA와 사용할 공통 Markdown/8종 소스 버전을 기록합니다. 이 시점을 **D0**로 둡니다.
2. 8종의 목적·명세·프리뷰를 검토하고 새 개념에 적합한 패턴을 선택합니다. 선택한 원본의 HTML/CSS/SVG/JS를 확인하고 선택 이유를 기록합니다. 모든 패턴을 한 자료에 넣지 않습니다.
3. 새 작업 경로의 `DESIGN.md`에 목표·용어·일반 관계·Figure 구조·정렬·전용 수치·검증 방법을 먼저 정합니다. 주요 디자인 결정마다 출처 파일과 절을 기록합니다.
4. 문서만으로 결정되지 않는 항목은 **보완 전에** `VALIDATION.md`에 남깁니다. 필요하면 판단해 작업을 계속하되, 그 판단으로 문서의 빈틈을 숨기지 않습니다.
5. 새 주제 자체를 구현하고 독립 수학/기술 검산·실제 폰트·실제 DOM/SVG 경계·PC 네 크기의 Scroll/Slide를 검증합니다. 필요한 수정과 공통 문서 보완을 수행합니다.
6. 보완한 문서/소스의 Commit을 **D1**로 기록하고 새 결과를 다시 검증합니다. D0에서 부족했던 사실과 D1의 최종 통과를 함께 보존합니다.
7. 사용한 패턴·검사한 공통 규칙·문서 보완점·미검증 항목·최종 산출물을 보고합니다. 현재 라운드의 결과로 검증하지 않은 패턴까지 통과했다고 쓰지 않습니다.

## 디자인 결정과 문제의 분류

| 분류 | 의미 | 기록/처리 |
| --- | --- | --- |
| A · 문서에 명시 | 공통/역할별 규칙을 Markdown에서 찾을 수 있음 | 파일/절과 적용값 기록 |
| B · 레퍼런스에 명시 | 원본 구현에서 확인되지만 필요한 문서 설명은 부족 | 소스 근거 기록. 재사용 규칙이면 공통 문서 보완 |
| C · 개념 고유 설계 | 새 기술 개념의 단계 수·새 Figure·전용 크기/데이터 | 새 DESIGN.md에 이유/검증 기록. 그 자체를 문서 결함으로 세지 않음 |
| D · 누락/모순 | 공통 규칙이 없거나 문서끼리/구현과 충돌 | 보완 전 문제와 결정 근거 기록 후 관련 공통 Markdown 수정 |
| E · 구현 오류 | 명시된 규칙을 코드나 배치가 지키지 않음 | 구현 수정·재검증. 문서가 부족했다고 잘못 판정하지 않음 |

기술적으로 새로 확인한 식·도메인 조건은 그 근거를 별도로 적습니다. 임의 수치를 실측값으로 쓰거나, 새 Figure의 모든 좌표를 과거 템플릿에서 찾을 수 없다는 이유로 문서 전체를 실패 처리하지 않습니다.

## VALIDATION.md에 남길 최소 기록

- 라운드/새 주제/대상 독자/범위, D0·D1 브랜치/Commit, 사용한 입력 문서·레퍼런스 버전.
- 패턴별 선택 이유와 사용/미사용.8종 회귀 검사와 실제 새 주제 재사용 범위를 구분.
- `디자인 결정 | 분류 A–E | 문서/소스 절 | 적용/새 판단 | 보완 전 문제 | 수정과 검증`의 추적표.
- 공통 문서의 누락·모순, 새 개념 전용 결정, 구현 오류를 각각 구분한 결과.
- D0의 문서 충분성 판정과 D1의 구현/검증 판정. 부분 검증이면 부분 검증으로 기록.
- 실제 수학·폰트·배치·화면 크기·콘솔/요청·프리뷰 증거와 남은 수동 검토.
- 원래 문서로 재현된 부분, 보완 후 재현된 부분, 여전히 문서만으로 결정할 수 없는 부분.

## 판정의 한계

로지스틱 회귀의 현재 **8개 화면**은4개 PC 크기×2모드의 한 장이며 **8종 전체를 새 주제에 재사용한 시험이 아닙니다**. 일반 곡선161점과 서체/정렬을 검증했으며, 삭제한 계산/부록의 검증을 현행 결과로 인용하지 않습니다. 원본48화면/기존 두 모드64화면 회귀 통과는 기존 구현이 유지된다는 증거이고, 새 개념의 문서 재현성을 별도로 입증하지 않습니다.

첫 사례는 같은 제작자가 대화와 사용자 피드백을 가진 상태에서 다듬었습니다. 독립 제작자나 새로운 세션의 재현 시험을 통과했다고 주장하지 않습니다. 다음 라운드의 새 주제는 아직 제작/검증되지 않았습니다. 최종 화면 품질·기술 검증·문서의 충분성·사용자 승인·main 반영은 각각 구분합니다.

실행 요청은 [재사용 검증 프롬프트](CONCEPT_REUSE_PROMPT.md)를 사용합니다. 작업 순서는 [일반 재사용 워크플로](REFERENCE_REUSE_WORKFLOW.md)와 연결하며, 이 문서는 템플릿 검증의 목적·사례·판정만 담당합니다.
