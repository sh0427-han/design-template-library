# 로지스틱 회귀 · 한 장의 개념 설명 명세

이 문서는 기존8종과 공통 Markdown의 재사용성을 확인한 **첫 검증 산출물의 전용 명세**입니다. 로지스틱 회귀를 다음 주제의 기준 템플릿으로 승격하지 않습니다. 검토 교훈의 공통 반영과 다음 판정 방법은 [템플릿 검증 기준](../../docs/TEMPLATE_REUSE_VALIDATION.md)에 기록합니다.

현재 범위는 **개념 슬라이드 #1 한 장**입니다. 계산 슬라이드 #2와 임계값 부록은 사용자 요청에 따라 제거했습니다. Markdown·소스·프리뷰·검증은 이 한 장을 기준으로 합니다. 원본 8종의 레퍼런스는 변경하지 않습니다.

[디자인 시스템](../../DESIGN_SYSTEM.md) → [컴포넌트 규격](../../docs/DESIGN_COMPONENT_RECIPES.md) → [Figure 표준](../../docs/FIGURE_PRODUCTION_STANDARD.md) → [재사용 절차](../../docs/REFERENCE_REUSE_WORKFLOW.md)를 먼저 읽습니다. 다른 개념의 제작 요청은 [재사용 프롬프트](../../docs/CONCEPT_REUSE_PROMPT.md)를 사용합니다.

## 목적·청중·범위

곱셈·분수는 알지만 이진 분류를 처음 배우는 독자가 **입력 특성 → 선형 점수 → 시그모이드 → 양성 확률**의 관계를 이해하는 것이 목표입니다. 그림·일반식·중요한 키워드로 설명하고, 예시 입력/계수 대입·실제 결과·선택 점·모델 학습·임계값 판정·성능 평가는 포함하지 않습니다. 하나의 개념 장만 요청했을 때 상세 장이나 부록을 자동 추가하지 않습니다.

제목은 `로지스틱 회귀의 확률 예측`, 부제는 `입력 특성 → 선형 점수 → 확률 변환 → 양성 확률`입니다. White 패널의 제목에서 `로지스틱 회귀(Logistic Regression)`를 먼저 소개하고, `양성(1)·음성(0) 중 양성의 확률을 예측하는 분류 모델`이라는 뜻을 연결합니다. 우상단에는 `이진 분류 · 확률 모델`을 표시합니다.

## 용어·일반식·기술적 조건

| 기호/용어 | 화면에 보이는 뜻 | 위치 |
| --- | --- | --- |
| x₁/x₂ | 수치로 표현할 두 입력 특성 | 입력 박스, 하단 x 정의 |
| w₁/w₂ | 각 특성에 곱하는 가중치 | 두 번째 가중합+절편 단계의 위 라벨·식과 하단 가중치 정의 |
| b | 입력과 무관하게 더하는 절편 | 점수 일반식, 하단 절편 정의 |
| z | 확률로 변환하기 전의 선형 점수 | 두 번째 단계의 일반식과 식 아래 z 설명 |
| 시그모이드(Sigmoid), σ | 실수 점수를 0과1사이로 변환하는 함수 | 세 번째 단계의 제목·식·곡선·하단 정의 |
| 자연상수 e | 시그모이드 지수식의 밑 | 식과 하단 짧은 뜻; 근삿값은 표시하지 않음 |
| p | 양성 클래스의 예측 확률 | 출력 일반식, 하단 p 정의 |
| 양성(1)/음성(0) | 이진 분류의 두 출력 클래스 | 패널 소개; 정오·정상/이상과 동일시하지 않음 |

```text
z = w₁x₁ + w₂x₂ + b
σ(z) = 1 / (1 + e^(−z))
p = σ(z)
```

두 입력에 대한 전개식으로 벡터 전치 기호를 추가하지 않고 정확한 가중합+절편 관계를 보여줍니다. z=0.90, p=71.1% 같은 예시 결과는 없습니다. 곡선의 범위·눈금, 첨자의1/2, 클래스0/1은 개념 설명에 필요한 정의이며 샘플 대입값이 아닙니다. 유한한 실수 z에서0<p<1이고 그래프의0/1은 극한을 설명하는 축 눈금입니다. 확률과 최종 클래스 판정은 구분합니다.

## 프레임·색상·Typography

- 설계 캔버스1440×810, padding 위54/좌우66/아래30px. 제목49px/1.13, 부제21px/1.38, Category17px/800, Footer15px/1.25입니다. 제목 margin7px0 6px, Content 위25px, 마지막 캡션 위14px, Footer 위15px/안쪽 위11px/선1px입니다. Footer는 `01 / 01`입니다.
- White 패널은 border1px/radius17px/padding24px/shadow none입니다. 전체 색은 공통 Navy/Blue/Teal/Muted/Canvas/Border 토큰을 그대로 사용합니다. Blue는 처리 흐름·입력, Teal은 확률 관계와 마지막 핵심 캡션에 사용합니다.
- 본문·일반 영문은 실제 로컬 Pretendard Variable, 수학 변수·계수·분수·지수·축은 실제 로컬 STIX Two Math2.12입니다. `math-typography.css`를 opt-in으로 로드합니다. 수학은 Regular400·line-height1.25·font-synthesis none이며 Native MathML로 첨자·분수를 조판합니다. 모든 텍스트는 전역−1pt를 상속합니다.
- 패널 제목25px/1.2·800, 소개20px/1.45, 우상단 키워드15px/1.4입니다. 일반 그룹 간격8px, 구역 간격16px, 큰 그룹24px를 기준으로 하며 Figure의 고정 트랙은 아래 명세를 따릅니다.
- 마지막 캡션은 White 바탕·Teal 왼쪽4px·padding12px17px·19px/1.45입니다. `확률의 의미`와 `입력에서 계산한 선형 점수를 양성 클래스의 확률로 변환`을 표시합니다. 아래에 별도 회색 설명을 흘리지 않습니다.
- Header 약118.58px, 패널 약471.13px, 캡션 약51.55px+위14px, Footer30.75px+위15px로 배분합니다. 내용이 바뀌면 고정값을 덮지 않고 실제 줄 수와 경계를 다시 측정합니다.

## Figure의 구성과 좌표

한 패널의 제목/소개 아래 4단계를 `1fr 32px 1fr 32px 1.3fr 32px 1fr`로 배치합니다. 하단 정의도 **같은 열 토큰**을 사용하여 1/3/5/7번 트랙에 대응합니다. 각 단계는 Figure **210px**, 라벨 **26px**, gap **8px**입니다. 기존의 단계별 짧은 설명 슬롯은 제거하고 의미 설명은 하단 두 줄에 모읍니다. Blue connector는 32×16px의 단일 path `M2 8 H29 M23 2 L29 8 L23 14`이며 Figure 슬롯 중심축을 통과합니다.

입력은 **214px** 폭의 두 박스로 `x₁`, `x₂` 기호(28px)만 중앙 정렬합니다. padding은 **상하16/좌우24px**, 두 박스 gap10px입니다. 가중치·절편·실제 값·등호는 입력 박스에 넣지 않습니다. 두 번째 단계는 `가중치 w₁,w₂ · 절편 b`(18px) → 일반식 `z=w₁x₁+w₂x₂+b`(26px) → `z 확률 변환 전 점수`(18px)의 세 요소를 gap12px로 중앙 정렬합니다. 위·아래 설명은 baseline 정렬/gap6px이며, 입력 데이터와 연산 매개변수의 역할을 구분합니다. 확률은 `p=σ(z)`(34px)와 `0과1사이의확률`이라는 뜻만 보여주고 퍼센트·확률 막대는 제거합니다.

하단 첫 열은 x/입력 특성과 `대상의 속성을 수치로 표현`, 두 번째 열은 w/`특성에 곱하는 가중치`와 b/절편 뜻, 세 번째 열은 σ/시그모이드와 자연상수 e, 마지막 열은 p/양성 확률과 판정 구분의 두 줄입니다. w·b와 그 설명은 두 번째 단계에 모으고 z의 뜻은 해당 단계의 식 아래에 둡니다. 첫 줄16px, 보조15px/1.4, gap8px이며 대응 Figure와 같은 중앙축입니다. `b=0.10`·`e≈2.718` 같은 값도 이 한 장에는 표시하지 않습니다. 우상단은 `이진분류·확률모델`입니다.

시그모이드 단계에는 `σ(z)=1/(1+e⁻ᶻ)`(23px)의 Native MathML과 곡선을 함께 둡니다. 함수 괄호는 `stretchy=false`로 분수 높이만큼 늘어나지 않게 합니다. Figure 내부는 함수식44px + gap8px + 곡선158px입니다. 식·분수·지수·곡선의 수학 축은 모두 실제 STIX Two Math입니다.

시그모이드 SVG viewBox **300×210**, plot x=40…280/y=22…172, z축 −4…4/p축0…1입니다. `screenX=40+(z+4)/8×240`, `screenY=172−p×150`로 161개 곡선 점을 계산합니다. 일반적인 0/0.5/1 눈금과 중간 보조선만 유지하고 **샘플의 선택 점·투영선은 없습니다**. 모델·샘플 변경에도 이 곡선과 본문은 바뀌지 않습니다.

## 두 모드·파일·삭제된 경로

`scroll.html`과 `slides.html`만 출력합니다. `lesson.js`가 같은 한 장의 HTML/MathML/SVG를 만들고, `viewer.js`는 프레임 배율·보기 전환·URL·키보드 탐색만 담당합니다. Slide는 진행1/1·이전/다음 비활성, Scroll은 목차 항목 하나입니다. 두 모드는 내부 서식·내용·계산을 공유하고 바깥 배치만 다릅니다. PC 네 크기에서 전체 프레임을 비례 축소하며 모바일 전용 구성은 만들지 않습니다.

현재 공유 앵커는 `#ref-concept`입니다. 과거 `#ref-calculation`, `#ref-threshold`, `appendix/threshold/sample` 쿼리는 현재 개념 장으로 정규화하고 제거한 화면·조작을 되살리지 않습니다. JS 실패 시 오류 안내, JS 비활성 시 noscript 안내를 표시합니다. 마지막 장 선택에 대한 기존 8종 뷰어의 수정은 별도 공통 회귀 검사로 유지합니다.

## 검증 계약

1. PC1600×950 / 1440×810 / 1366×768 / 1280×720 × Scroll/Slide의 **8개 화면**을 실제 Chromium으로 렌더링합니다.
2. Python의 독립 함수값으로 곡선161개 점을 모두 대조합니다. 입력·출력의 일반식에 필요한 가중치/절편·분수/지수·기호 관계를 확인합니다.
3. 입력 기호 중앙 정렬·상하16/좌우24px 패딩·4개 정의 중앙축·세 화살표의 Figure 중앙축·단계 라벨 정렬·분자/분모·카드 안쪽 패딩·캡션 위14px·Footer 위15px·가로 넘침·잘림을 실제 DOM/SVG 경계로 검사합니다.
4. document.fonts와 CDP로 본문/일반 영문=실제 Pretendard, 수학량=실제 STIX를 역할별 확인합니다. 전역−1pt·normal이 아닌 행간·두 모드의 상대 경계/스타일도 대조합니다.
5. 한 장의 페이지 수·진행 표시·비활성 이전/다음·목차·키보드·모드 왕복·새로고침·과거 쿼리/앵커 정규화·JS/요청 오류를 검사합니다.
6. 설계/소스 변경 후 실제 프리뷰·검증 JSON을 다시 생성합니다. 과거40화면·606/404개 판정 기록을 현재 한 장의 검증 결과로 사용하지 않습니다.

## 다른 개념에 적용할 경계

그림·키워드·일반 관계 중심의 한 장이라는 정보 위계, 실제 수학 서체, 기호 정의와 Figure의 대응 중앙축, 짧은 연결, 마지막 캡션을 재사용합니다. **로지스틱 회귀의 네 단계·변수·시그모이드 곡선을 다른 개념에 강제하지 않습니다.** 새 개념의 청중/목표·용어·입력/출력·공식/조건·Figure 구조를 먼저 명세하고 필요한 레퍼런스를 선택합니다. 숫자 대입·계산 실습·상세 장은 별도 요청일 때만 추가합니다. 다음 검증은 본 소스를 복제하지 않고, 교훈을 반영한 공통 Markdown과 기존8종에서 다시 출발합니다. 실행용 요청문은 [검증 프롬프트](../../docs/CONCEPT_REUSE_PROMPT.md)를 따릅니다.
