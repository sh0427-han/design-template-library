# 로지스틱 회귀 · 재사용 검증본

검토를 마친 8종 레퍼런스의 Markdown 규격으로 다른 개념을 제작한 **3장짜리 연결 자료**입니다. 9번째 디자인 레퍼런스를 추가하는 작업이 아닙니다.

1. **확률 예측:** 입력 특성·각 가중치 → 일반식·절편·실제 합으로 설명하는 선형 점수 → 실제 시그모이드 곡선 → 양성 확률. 하단의 기호 정의 4개는 각 Figure와 같은 중앙축입니다.
2. **확률 계산:** 입력·가중치의 두 곱 → 절편과 합산 → 같은 점수의 확률 변환.
3. **임계값 판정:** 6개 확률은 고정하고 임계값·선택 샘플을 조작하여 판정을 확인.

### 세 장의 정지 화면

실행 환경의 `/tmp`·`/workspace` 경로는 외부 공유 주소가 아닙니다. 채팅이나 외부 검토에는 공개 저장소의 이미지 주소를 사용하며, Markdown 본문에 `![설명](이미지 주소)`로 삽입합니다. 도구가 읽은 이미지가 사용자 화면에도 첨부됐다고 간주하지 않습니다. 링크의 정상 응답과 브라우저 이미지 로딩은 확인할 수 있지만, 수신자의 채팅 앱이 이미지를 표시하는지는 별도 확인이 필요합니다.

- [① 개념 — 확률 예측](review/concept.png)
- [② 계산 — 한 샘플의 확률 계산](review/calculation.png)
- [③ 조작 — 임계값에 따른 판정 변화](review/threshold.png)

세 PNG는 실제 Chromium 검증에서 생성한 1440×810 슬라이드 캡처입니다. 세 번째는 임계값 0.60·샘플 4를 선택한 정지 화면이며 조작은 HTML에서 실행합니다. `review/`의 검토용 캡처는 두 모드의 대표 프리뷰를 대체하지 않습니다.

기본 입력 `(1.0,0.5)`, 계수 `(1.2,−0.8)`, 절편 `0.1`에서 **z=0.90, p≈0.710950(약 71.1%)**입니다. 임계값 0.60에서 샘플 4는 양성이며 전체 양성/음성은 3/3입니다. 실제 학습·성능 평가를 수행한 예제가 아니며 정답 라벨이 없는 데이터로 평가 지표를 만들지 않습니다.

샘플 버튼을 선택하면 세 장의 입력·수식·곡선 점·확률이 같은 샘플로 갱신됩니다. 임계값만 바꾸면 확률과 샘플 위치는 고정됩니다. `?threshold=72&sample=4#ref-threshold`처럼 조작값과 위치를 공유하며 모드 왕복·새로고침에도 복원합니다. Slide 탐색은 이전/다음·방향키·PageUp/Down·Home/End·Space를 지원합니다.

## 재현 검증

```bash
python scripts/check_sources.py
python scripts/verify_logistic_reuse.py
python scripts/check_documentation.py
```

새 자료의 대상은 PC 4개 크기입니다. 실제 Chromium 렌더링에서 두 모드의 상대 경계·스타일과 캡션 위 14px·Footer 위 15px을 검사합니다. 본문·일반 영문은 실제 Pretendard Variable, 수식·변수·계수·수식 결과는 실제 STIX Two Math인지 CDP로 역할별 확인합니다. 최신 측정치는 [검증 JSON](previews/validation.json)에 기록합니다.

- **24개 화면:** 1600×950/1440×810/1366×768/1280×720 ×3장×Scroll/Slide. 제목·패널·수식·Footer·실제 글리프·자간과 두 모드의 스타일/상대 경계를 대조합니다.
- **개념 장 정렬과 설명:** 하단 4개 정의와 해당 단계의 중심축을 실측하고, 일반식·실제 가중치·절편·합산·결과가 같은 모델과 선택 샘플을 사용하는지 검사합니다.
- **606개 기본 판정:** 101개 임계값×6개 샘플을 Python의 독립 계산과 비교합니다. 실제 입력/계수/곱/점수/확률/막대·표시값도 확인합니다.
- **404개 재사용 판정:** 다른 계수·절편·4개 샘플에서도 세 장의 값과 곡선 점을 확인합니다.
- **경계와 상태:** p=t의 양성 처리, 0/1, 원래 확률을 사용한 판정, ±1000의 수치 안정성, 잘못된 데이터 5개 거부, 선택 샘플·슬라이더 키보드·모드 왕복·새로고침·잘못된 URL.
- **기존 회귀:** 원본 48개 화면과 기존 두 모드 64개 화면을 확인하고 마지막 장 왕복 검사를 추가했습니다.

모드별 대표 이미지는 두 JPG만 저장하며, 외부 검토용으로 세 장의 PNG를 `review/`에 보관합니다. 나머지 화면별 캡처는 `/tmp/logistic-reuse-review`, CI 실행별 증거는 Actions artifact에 보관합니다. 검증 JSON은 설계 MD·실행 스크립트·화면 소스·공통 CSS/폰트·프리뷰의 해시를 기록합니다. 소스나 명세를 바꾼 뒤 이전 통과 보고서를 그대로 사용할 수 없습니다.
