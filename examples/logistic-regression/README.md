# 로지스틱 회귀 · 재사용 검증본

검토를 마친 8종의 Markdown 규격으로 다른 개념을 제작한 **본편 2장 + 선택 부록 A**입니다. 로지스틱 회귀가 입력에서 확률을 계산하는 과정이 본편의 목표입니다. 임계값은 계산된 확률에 별도의 판정 기준을 적용하는 후속 주제이므로 기본 페이지 수에 포함하지 않습니다.

1. **확률 예측:** 입력·가중치 기호 → `z=w₁x₁+w₂x₂+b` → 시그모이드 일반식·곡선 → `p=σ(z)`. 그림과 키워드로 개념을 먼저 설명하며 예시 수치·선택 점은 넣지 않습니다. 설명은 대응 열의 하단에 둡니다.
2. **확률 계산:** 입력 `x₁=1.00, x₂=0.50`과 가중치·절편을 두 줄의 Blue 박스로 제시 → 일반식 → 전체 값 대입 → `z=0.90` → **계산 결과 z를 오른쪽 카드의 입력으로 전달** → 시그모이드 대입·확률·동일 교점의 그래프.

선택 부록 A는 6개 확률을 고정한 채 임계값과 선택 샘플을 조작하는 실습입니다. Interactive 유형 재사용을 위해 본편에 필수로 끼워 넣지 않습니다.

### 본편과 부록의 정지 화면

실행 환경의 `/tmp`·`/workspace` 경로는 외부 공유 주소가 아닙니다. 채팅이나 외부 검토에는 공개 저장소의 이미지 주소를 사용하며, Markdown 본문에 `![설명](이미지 주소)`로 삽입합니다. 도구가 읽은 이미지가 사용자 화면에도 첨부됐다고 간주하지 않습니다. 링크의 정상 응답과 브라우저 이미지 로딩은 확인할 수 있지만, 수신자의 채팅 앱이 이미지를 표시하는지는 별도 확인이 필요합니다.

- [① 개념 — 확률 예측](review/concept.png)
- [② 계산 — 한 샘플의 확률 계산](review/calculation.png)
- [선택 부록 A — 임계값에 따른 판정 변화](review/threshold.png)

세 PNG는 실제 Chromium 검증에서 생성한 1440×810 캡처입니다. 본편 2장과 선택 부록을 구분합니다. 부록 이미지는 임계값 0.60·샘플 4를 선택한 정지 화면이며 조작은 HTML에서 실행합니다. 두 모드의 대표 JPG는 기본 본편 URL에서 캡처합니다.

기본 입력 `(1.0,0.5)`, 계수 `(1.2,−0.8)`, 절편 `0.1`에서 **z=0.90, p≈0.710950(약 71.1%)**입니다. 임계값 0.60에서 샘플 4는 양성이며 전체 양성/음성은 3/3입니다. 실제 학습·성능 평가를 수행한 예제가 아니며 정답 라벨이 없는 데이터로 평가 지표를 만들지 않습니다.

부록에서 샘플을 선택하면 계산 장의 입력·수식·전달 z·그래프의 점·확률도 갱신됩니다. 개념 장의 기호·일반 곡선은 그대로 유지합니다. 임계값만 바꾸면 확률은 고정됩니다. `?appendix=1&threshold=72&sample=4#ref-threshold`처럼 공유하며 부록 포함 여부·조작값·위치를 모드 왕복과 새로고침에도 복원합니다. 기본 Slide의 `End`는 본편2로 이동합니다. 부록을 닫을 때 현재 부록이면 본편2로 돌아가고 본편이면 위치를 유지합니다. 탐색은 이전/다음·방향키·PageUp/Down·Home/End·Space입니다.

## 재현 검증

```bash
python scripts/check_sources.py
python scripts/verify_logistic_reuse.py
python scripts/check_documentation.py
```

새 자료의 대상은 PC 4개 크기입니다. 실제 Chromium 렌더링에서 두 모드의 상대 경계·스타일과 캡션 위 14px·Footer 위 15px을 검사합니다. 본문·일반 영문은 실제 Pretendard Variable, 수식·변수·계수·수식 결과는 실제 STIX Two Math인지 CDP로 역할별 확인합니다. 최신 측정치는 [검증 JSON](previews/validation.json)에 기록합니다.

- **40개 화면:** PC 4개 크기 × 본편2장×2모드=16개, 부록 포함3장×2모드=24개를 구분합니다. 제목·패널·수식·Footer·실제 글리프·자간·두 모드 상대 경계를 대조합니다.
- **개념 장:** 두 입력 기호의 중앙 정렬·상하16/좌우24px 패딩·하단4개 정의의 중앙축·시그모이드 수학 서체와 분수를 검사합니다. 예시 값과 선택 점이 없으며 샘플·모델 변경에도 본문과 일반 곡선이 같은지 대조합니다.
- **계산 장:** 입력/계수의 두 줄, 일반식→전체 대입→결과의 세 줄·등호 시작선·음수 괄호·좌우 입력 박스의 동일 서식과 전달 z·확률·그래프 교점을 같은 모델과 대조합니다. 연결선은 실제 결과 오른쪽+6px에서 입력 왼쪽−8px까지 이어지는지 DOM/SVG 경계로 검사하고 여섯 샘플과 변경 모델에서도 재검사합니다. 상세 그래프의 축 표시는 z=0.90/p≈0.711, 교점 위치는 원래 정밀도입니다.
- **606개 기본 판정:** 101개 임계값×6개 샘플을 Python의 독립 계산과 비교합니다. 실제 입력/계수/대입식/점수/확률/막대·표시값도 확인합니다.
- **404개 재사용 판정:** 다른 계수·절편·4개 샘플에서도 계산 장/부록의 값·전달선·상세 곡선의 점·축 라벨과 개념 장의 불변성을 확인합니다.
- **경계와 상태:** p=t의 양성 처리, 0/1, 원래 확률을 사용한 판정, ±1000의 수치 안정성, 잘못된 데이터 5개 거부, 선택 샘플·슬라이더 키보드·모드 왕복·새로고침·잘못된 URL.
- **기존 회귀:** 원본 48개 화면과 기존 두 모드 64개 화면을 확인하고 마지막 장 왕복 검사를 추가했습니다.

모드별 대표 이미지는 두 JPG만 저장하며, 외부 검토용으로 세 장의 PNG를 `review/`에 보관합니다. 나머지 화면별 캡처는 `/tmp/logistic-reuse-review`, CI 실행별 증거는 Actions artifact에 보관합니다. 검증 JSON은 설계 MD·실행 스크립트·화면 소스·공통 CSS/폰트·프리뷰의 해시를 기록합니다. 소스나 명세를 바꾼 뒤 이전 통과 보고서를 그대로 사용할 수 없습니다.

## 문서만으로 충분했던 점과 보완한 점

| --- | --- |
| 프레임·색·폰트·행간·8/16/24px·카드·마지막 캡션 | 기존 MD로 선택/재현 가능. 원본 그림을 복제할 필요가 없었음 |

| 새 개념의 전용 수치 | 곡선 범위/좌표, 표 행, 수식 트랙, 6개 샘플의 높이 예산은 새 명세에 작성해야 함 |
| 폼 요소의 자간 | 상위 −1pt만으로 네이티브 버튼의 UA `normal`이 바뀌지 않음. `letter-spacing:inherit`를 명시하도록 공통 규격 보완 |

| 유형 선택과 분량 | 임계값 실습은 확률 계산의 필수 단계가 아님. 본편2장/선택 부록을 구분하고 유형 수를 채우려고 장을 추가하지 않음 |

| 수학 Typography | 모든 영문에 같은 서체를 쓰지 않음. 수학량만 STIX Two Math/MathML로 분리하고 글리프 폰트를 역할별 검사하도록 보완 |
| 연속 문서의 마지막 장 | 읽기 기준선만으로 활성 장을 고르면 직전 장이 남음. 문서 끝 처리와 왕복 검사를 공통 규격에 추가 |

데이터를 영구 변경할 때는 `model.js`의 기본 모델을 수정합니다. `window.LogisticLesson.setModel(model)`은 임시 편집/재사용 검증 API이며 계수 변경을 URL에 저장하지 않습니다. 한 화면의 표시 예산은 최대 6개 샘플입니다. 더 많은 데이터는 Scroll 상세 영역이나 추가 장으로 나눕니다.
