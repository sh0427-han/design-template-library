## 실제 요청 반영

부제는 '학습 데이터에 잘 맞는 것과 새로운 데이터에도 잘 동작하는 것의 차이'라는 제목 보충 문장으로 읽힌다. 용어 정의를 나열한 예전 부제는 사라졌다. 손실(Loss)의 짧은 뜻은 왼쪽 그래프 컨테이너 첫 줄에 있어 범례/축을 보기 전에 읽을 수 있다. 그 옆 학습/검증 범례는 서로 떨어진 선·문자 묶음이며 내부 폭에 들어간다.

일반화 정의는 모든8화면에서 한 줄이다. 짧아진 오른쪽 정의도 왼쪽과 같은 제목/정의 시작선을 유지하고 카드/그림 경계를 바꾸지 않는다. 하단 두 Figure가 다른 모양인 것은 '과적합의 단서'와 '일반화의 역할'이라는 다른 설명 목적에 맞는 재구성이다. 동등 White·대응열·같은 기본 위계라는 #3 Comparison 재사용 관계는 유지된다.

오른쪽은 이제 곡선이 아니라 학습 이미지3개/클래스 라벨→학습된 모델→동일 모델의 학습 미사용 새 입력A/B→예측A사과/B토마토로 읽힌다. A/B 식별자가 입력과 예측을 연결하고, 준비한 모델을 새 모델로 바꾸거나 새 이미지를 재학습한다는 흐름으로 보이지 않는다. 학습과 새 입력은 공간·제목·라벨로 구분되며, 새 이미지가 다른 SVG path라는 자동 검사와 원본도 확인했다. 실제 학습/추론 성과를 주장하는 화면 수치나 정확도는 없다. 개념도라는 출처·범위는 사용자 요청대로 명세/JSON/접근성 설명에 남긴다.

## 일반화 Figure의 연결·라벨 직접 확인

세 Blue 흐름은 학습그룹→학습된 모델, 새 이미지그룹→같은 모델, 같은 모델→예측결과의 실제 경계 사이에 있고 라벨을 가로지르지 않는다. 두 모델의 ref가 동일하고 Teal 전달선이 준비→적용의 관계를 표시한다.

자동검사가 존재만 확인하던 Teal 경로는 원본 계산식과 실제 대표 PNG에서 추가 확인했다. 위 모델 rect(362,51,162,66)의 아래 중앙(443,117)에서4px 떨어진(443,121)에 시작하고, y160에서 왼쪽으로 꺾인 뒤 아래 모델 rect(274,220,130,64)의 위 중앙(339,220)보다4px 위인(339,216)에 화살촉이 끝난다. 선·tip이 같은 좌표를 쓰며 모델·문자 위를 통과하지 않는다. '학습에 쓰지 않은 새 이미지' 제목은 경로 왼쪽 별도 구역에 있고 예측 제목/두 결과 행도 분리돼 있다. 좁은PC Slide에서도 흐름과 입력/출력 대응이 유지된다.

학습/새입력의 이미지 수와 성공 예측 두 개는 개념 설명용 선택이다. '세 장이면 충분히 학습', '모든 새 데이터에서 성공', '이 그림이 실제 성능 측정'이라는 주장으로 확대해서는 안 되며 현재 소스·명세에는 그런 주장이 없다.

## 문서 충분성·남은 범위

이번 새 공통 축 계약은 기존 일반 중앙축 기준에 없던 '위/아래 위치·실제 glyph·8px·본문+수학그룹'을 사용자 표준화 요청에 따라 보완한1건이다. 최초D0의 충분/누락0 기록은 당시 요구 범위의 기록으로 보존하고, 이번 확대 기준에서 보완 전 부족과 보완 후 통과를 분리해야 한다. 최종적으로 '공통 문서는 한 번도 보완이 필요 없었다'고 쓰지 않는다.

새 규칙 보완 전의 이번 축 표준 요구는 일부 보완이 필요했고, Figure표준1파일/opt-in helper와 독립16화면 검증으로 그 요구가 충족됐다. 보완 후 시험한 #3 비교 재구성/#8 그래프 원칙 일부·새 공통 축 계약의 재사용성은 충분하다. 오른쪽의 좌표/이미지 수/모델 위치/A-B 구조는 C 설계로 남고 전역 기본값으로 승격하지 않는다. 새 기준에 대한 문서 보완1건과 이전 구현 오류/주제 고유 설계를 혼동하지 않는 기록에 동의한다.

현재 source/preview를 기준으로 심각도별 미해결 사항은 없다. 본 Reviewer가 수정 요청할 신규 코드/디자인 문제를 발견하지 않았다. 로컬 문서의 API 호출 예시 보강은 실행 로직·그림을 바꾼 수정이 아니므로 이 결과와 별도의 새 디자인 검증 반복을 요구하지 않는다.

미검증 범위는 독립 제작자가 Markdown만 받아 처음부터 만드는 재현 시험, 이번에 사용하지 않은 패턴의 타주제 재사용, 모바일/태블릿·실제 스크린리더 청취·실제 학습/추론/독립테스트 실측 성능, 임의 변환/비율의 모든 SVG에서 새helper를 사용하는 경우다. 자동검증/독립검토 통과와 사용자 승인·main 병합은 계속 별개다.
