## 사용자 요청·문구 위계

부제는 학습 데이터 적합과 새 데이터 성능의 차이라는 제목 보충 문장으로 바뀌었다. 손실(Loss)의 뜻은 왼쪽 그래프 컨테이너 첫 줄에 있고 범례/축을 읽기 전에 보인다. 부제를 용어집으로 쓰지 않으면서 공통 첫 등장 기준을 지킨다. 일반화 정의는 강제br 없이 '학습에 쓰지 않은 새 데이터에서도 잘 동작하는 능력' 한 줄로 간결해졌고, 같은35/56px 제목/정의 트랙으로 왼쪽 카드와 시작선을 공유한다. 실제 한 줄 렌더링은 새 CI에서 확인해야 한다.

오른쪽 검증 손실 곡선은 코드/데이터에서 제거됐다. 새580×320 편집 가능 SVG는 학습 이미지3개와 클래스 라벨→학습된 모델, 학습에 쓰지 않은 별개 이미지A/B→같은 모델→A사과/B토마토 예측을 보여준다. 학습/미사용 입력의 그룹·배치와 식별자가 구분되며 두 모델 표기의 ref가 같고 준비→적용 Teal 연결이 있어 모델을 새로 학습한다는 오해를 줄인다.

새이미지는 학습이미지와 fruit path 자체가 다르고 A/B가 결과의 입력 대응을 보존한다. 색상 하나만으로 분류한다는 규칙을 설명하지 않으며 실제 학습/추론/성능 측정을 수행했다고 주장하지 않는다. 모식도 범위는 명세와 접근성 설명에 남아 있고 이는 앞선 사용자 화면 부가 문구 삭제 요청과 일치한다. 두 성공 예측은 일반화의 역할을 설명하는 사례이며 모든 새 이미지에서 항상 성공하거나 세 장이면 충분한 학습이라는 주장으로 확대하면 안 된다. 현재 본문/명세에 그런 확대 주장은 없다.

#3의 학습 자료/준비한 체계/같은 모델의 새 입력 적용 관계와 동등 White 비교를 재사용한 선택은 타당하다. 두 열에 다른 형태의 Figure를 쓰는 것은 기술적 역할이 다른 두 개념을 설명하기 위한 C 설계이며, 동일 그림 형태나 원본의 모든 비교행을 강제할 이유가 없다.

## 새 공통 축 규칙·구현

Figure표준§6의 새 규칙은 y축 이름의 실제 가로 중심을 축X에, 아래 경계를 상단 끝점8px 위에 맞춘다. x축 이름은 가로축 시작~끝(화살촉tip 포함)의 중앙 아래8px에 둔다. 본문/수학 기호를 실제 경계와8px 간격의 한 그룹으로 정렬하므로 두 서체의 메트릭을 눈대중으로 보정하지 않는다. 기존 공통8px 토큰과−1pt를 유지하며 기존 승인8종을 전역 변경하지 않는 opt-in 범위가 명확하다.

`packInline`은 실제 part bbox로 각 부분을 연결하고 `alignAxes`는 폰트 준비 뒤 group bbox에 transform을 적용한다. 과적합 그래프의 x46/58~266/끝358, GD의 x48/상단tip29/가로tip305/바닥454라는 실제 축 좌표를 전달한다. x/y 제목의 기대중앙과8px 간격은 검증기가 실제 `getBoundingClientRect()`를 SVG 좌표로 환산해 독립 확인하므로 구현 결과를 기대값으로 복사하지 않는다. GD의 기존 곡선/수학/접선/상태는 그대로이며 그룹이 바뀐 glyph 경계도 충돌 검사에 반영됐다.

공통helper의 적용은 이번 두 자료와 같은 고정viewBox·비례축소 환경에서 검증하는 범위로 제한한다. 임의의 좌표계/회전·skew/다른 preserveAspectRatio 조건 전체의 보편 지원을 입증한 것은 아니다.

## 도식·검증 코드 검토

도식 layout은 폰트 로딩 뒤 학습그룹/새입력/예측을84/252/252 중심에 맞추고 모델 텍스트도 실제 사각형 중앙에 둔다. Blue 가로선은 실제 그룹 경계에서4px 떨어진 시작/끝을 계산하며 동일tip의 선/화살촉을 만든다. Teal 준비→적용 경로는 두 모델의 중앙과 경계에 연결한다. 코드상 방향/대상은 맞고 실제 text·노드·전달선 교차/시각 중앙은 캡처에서 확인해야 한다.

검증기는 학습3개·새입력2개·고유ID·다른 SVG path·클래스와A/B결과 대응·동일모델ref, 실제 가로흐름 경계/중앙을 검사한다. 보이지 않는 '추론 완료' 결과를 성공으로 판정하는 검사는 아니며 `inference_executed=False`라고 구분한다. Teal 준비→적용 경로는 현재 존재만 검사하므로 실제 endpoint/경로와 라벨 교차는 시각 검토 때 따로 확인한다.

과적합 왼쪽은41점/82좌표 독립 검산을 유지하고 두 변경데이터·오류데이터·실패·탐색을 다시 검사하도록 되어 있다. 새 손실뜻 위치·부제에서 용어집 제거·일반화 정의 한 줄·왼쪽380×320·기존 오른쪽곡선 제거·실제 glyph축정렬의 검사가 있다. 두 모드/PC4×2와 실제폰트/패딩/문자경계/충돌/콘솔 등은 작성된 검사 코드의 정적 확인이며 아직 실행 결과가 아니다.

GD baseline 검사는 `git ls-tree`의 원래8종 파일 목록으로 보존을 확인하고 신규helper/의도된문서수정을 별도 상태로 기록한다. 새 공통 파일을 원래 baseline에도 있었던 파일처럼 조회하거나, 공통 문서 변경이 없다고 계속 주장하던 모순은 피했다.
